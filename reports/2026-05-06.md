## 第二模块：核心架构解释

### 1. 基础世界模型架构（Tokenize–Predict–Decode）

 backbone 采用双分支视觉 tokenizer：
- **上下文编码器 $E_c$**：将条件帧编码为 $N_c=1280$ 个上下文 token $z^{\mathrm{ctx}}$。
- **动态编码器 $E_d$**：在 $E_c$ 特征金字塔的交叉注意力下，将观测帧编码为 $N_d=80$ 个动态 token $z^{\mathrm{dyn}}_t$，仅承载残差变化。
- 连续动作 $a_t$ 被离散化为动作 token $\hat{a}_t$，与视觉 token 交错为统一序列 $s = [z^{\mathrm{ctx}}, z^{\mathrm{dyn}}_1, \hat{a}_1, z^{\mathrm{dyn}}_2, \hat{a}_2, \dots]$。
- 12 层 LLaMA 因果 Transformer 执行标准 next-token 预测，损失仅作用于动态 token：

$$
\mathcal{L}_{\mathrm{AR}} = -\sum_{t=1}^{T} \log p_\theta\bigl(z^{\mathrm{dyn}}_t \mid z^{\mathrm{ctx}}, z^{\mathrm{dyn}}_{<t}, \hat{a}_{\le t}\bigr).
$$

### 2. Reward-Aligned Post-Training（三阶段管线）

**阶段 A：RobotWorldBench 构建**
从 RT-1、BridgeData V2、CALVIN、LIBERO 四个机器人数据集中筛选 10,000 条视频-指令对。每条样本 $(l, v)$ 由人工或规则化退化管道标注六维原始分数向量 $\mathbf{r}=(r_1,\dots,r_6)$，对应：
1. Instruction Following (0–3)
2. Manipulation Success (0–2)
3. Action–Outcome Consistency (0–1)
4. Temporal Consistency (0–1)
5. Contact Realism (0–1)
6. Physics Adherence (0–2)

**阶段 B：教师评判器（RoboAlign-Judge）**
以 Qwen3-VL-8B-Thinking 为基座，通过 LoRA 微调得到教师 $f_\phi$。输入指令 $l$ 与视频 $v$，输出六维结构化分数 $\hat{\mathbf{r}} = f_\phi(l,v)$。训练目标为监督负对数似然：

$$
\mathcal{L}_{\mathrm{teacher}} = -\mathbb{E}_{(l,v,\mathbf{r})\sim\mathcal{D}_{\mathrm{bench}}} \bigl[\log p_\phi(\mathbf{r}\mid l, v)\bigr].
$$

**阶段 C：学生奖励蒸馏与在线迭代**
教师推理成本过高（~2.8 s/视频），无法直接用于在线 RL。作者将其蒸馏为轻量学生 $g_\psi$（ViT-Base/16 部分解冻 + 4 层文本 Transformer + MLP 头，共 98M 参数）。教师分数按维度最大分值归一化到 $[0,1]$ 后，学生通过加权 Huber 损失回归：

$$
\mathcal{L}_{\mathrm{distill}} = \mathbb{E}_{(l,v)\sim\mathcal{D}_{\mathrm{distill}}} \sum_{k=1}^{6} \lambda_k \,\mathrm{Huber}_{\delta_h}\!\bigl([g_\psi(l,v)]_k,\; \tilde{s}_k(l,v)\bigr).
$$

为对抗分布漂移导致的 reward hacking，每 $K$ 个策略更新后，用当前策略生成新 rollout，由教师重新打分并刷新学生（Online Iterative Distillation）。

**阶段 D：GRPO 后训练**
学生提供复合奖励：

$$
R(\hat{x}_{1:T}) = \sum_{k=1}^{6} w_k \,[g_\psi(l,\hat{x}_{1:T})]_k.
$$

采用 GRPO：对每组 $G$ 个 rollout 计算组内归一化优势：

$$
A^{(j)} = \frac{R(\hat{x}^{(j)}) - \operatorname{mean}_j R}{\operatorname{std}_j R},
$$

并优化裁剪策略梯度目标：

$$
\mathcal{L}_{\mathrm{GRPO}} = -\mathbb{E}\!\Biggl[\frac{1}{G}\sum_{j=1}^{G} \min\!\Bigl(\rho^{(j)} A^{(j)},\; \operatorname{clip}(\rho^{(j)}, 1-\epsilon, 1+\epsilon)\, A^{(j)}\Bigr)\Biggr] + \beta\, D_{\mathrm{KL}}(p_\theta \| p_{\theta_0}).
$$

### 3. Sliding Window Re-encoding (SWR)

SWR 是一种**无需重新训练**的推理策略，用于抑制长程自回归漂移。
- 将 $T$ 帧 rollout 划分为 $K=\lceil T/W\rceil$ 段，每段长度 $W$。
- 段内按标准自回归生成。
- **段边界刷新**：将第 $k$ 段最后一帧解码到像素空间，再通过 tokenizer 重新编码为新的上下文 token $z^{\mathrm{ctx}}_{k+1}$，作为下一段的初始条件：

$$
\hat{x}_{kW} = \bigl[\mathcal{D}_{\mathrm{vis}}(z^{\mathrm{ctx}}_k, \hat{z}^{\mathrm{dyn}}_{(k-1)W+1:kW})\bigr]_{t=kW}, \quad (z^{\mathrm{ctx}}_{k+1}, z^{\mathrm{dyn}}_0) = \mathcal{T}_{\mathrm{vis}}(\hat{x}_{kW}).
$$

论文给出理想化误差分析：在局部收缩假设下，SWR 的误差界为 $W\varepsilon + (W\varepsilon+\delta_q)/(1-\alpha^W)$，不随 $T$ 显式增长；而原生 AR 在最坏情况下为 $\mathcal{O}(T\varepsilon)$。

# ========== 学生奖励模型（蒸馏与推理） ==========
class StudentRewardModel(nn.Module):
    def __init__(self):
        # 视觉分支：ViT-Base/16，后4层可训练
        self.visual_encoder = ViTBase16(unfreeze_last_n=4)
        # 文本分支：轻量4层Transformer
        self.text_encoder = LightweightTransformer(layers=4, hidden=256)
        # 融合+评分头
        self.fusion_mlp = MLP([1024, 512, 256, 6], activation='GELU')
        self.sigmoid = nn.Sigmoid()

    def forward(self, frames, instruction):
        # frames: [B, N=8, 3, 224, 224]
        v = self.visual_encoder(frames).mean(dim=1)   # [B, 768]
        t = self.text_encoder(instruction)            # [B, 256]
        z = torch.cat([v, t], dim=-1)                 # [B, 1024]
        scores = self.sigmoid(self.fusion_mlp(z))     # [B, 6] in [0,1]
        return scores

def distill_student(teacher, student, dataloader):
    for batch in dataloader:
        l, v, teacher_scores = batch
        # teacher_scores 已按维度归一化到 [0,1]
        pred = student(v, l)  # [B, 6]
        loss = weighted_huber_loss(pred, teacher_scores, weights=LAMBDA, delta=0.5)
        loss.backward()
        optimizer.step()

# ========== GRPO 奖励对齐后训练 ==========
def grpo_post_train(policy, student_reward, ref_policy, dataloader):
    for batch in dataloader:
        l, actions = batch
        # 生成 G 个 rollout
        rollouts = [policy.generate(l, actions) for _ in range(G)]
        # 学生打分
        rewards = torch.stack([student_reward(r, l).sum(dim=-1) for r in rollouts])
        advantages = (rewards - rewards.mean()) / (rewards.std() + 1e-8)
        
        # 计算比率与裁剪
        ratios = policy.prob(rollouts) / ref_policy.prob(rollouts)
        surr1 = ratios * advantages
        surr2 = torch.clamp(ratios, 1-EPS, 1+EPS) * advantages
        policy_loss = -torch.min(surr1, surr2).mean()
        kl_loss = beta * kl_divergence(policy, ref_policy)
        loss = policy_loss + kl_loss
        loss.backward()
        optimizer.step()
        
        # 在线迭代蒸馏：每 K 步用教师刷新学生
        if step % K == 0:
            fresh_rollouts = [policy.generate(l, actions) for _ in range(M)]
            teacher_scores = [teacher(r, l) for r in fresh_rollouts]
            update_student_with_fresh_labels(student_reward, fresh_rollouts, teacher_scores)

# ========== Sliding Window Re-encoding 推理 ==========
def swr_generate(policy, tokenizer, decoder, x0, actions, T, W):
    # 初始编码
    z_ctx, z_dyn_0 = tokenizer.encode(x0)
    generated_frames = []
    
    for k in range(0, T, W):
        segment_frames = []
        z_dyn = z_dyn_0
        # 段内自回归生成 W 帧
        for t in range(W):
            if k + t >= T:
                break
            z_dyn = policy.next_token(z_ctx, z_dyn, actions[k+t])
            segment_frames.append(z_dyn)
        # 解码整段并取最后一帧
        decoded_segment = decoder(z_ctx, segment_frames)
        last_frame = decoded_segment[-1]
        generated_frames.extend(decoded_segment)
        # 刷新上下文：重新编码最后一帧作为下一段条件
        z_ctx, z_dyn_0 = tokenizer.encode(last_frame)
    
    return generated_frames

3. **评判器的域内依赖性**。RoboAlign-Judge 虽经人工标注和外部 VLM 验证，但其训练数据仍集中在特定机器人数据集和失败模式上，对未见环境、物体类别或 embodiment（如移动操作、灵巧手）的泛化能力存疑；此外，学生奖励模型始终是对教师的近似，在线迭代蒸馏只能缓解而非根除 reward hacking。
4. **低层指标与高层奖励的潜在冲突**。论文显示多模态奖励在提升高层评分的同时也改善了 SSIM/LPIPS，但这可能只是副产品；若未来在更复杂场景中出现“高层对、像素差”或反之的情况，当前框架未明确处理这种多目标权衡。

**对后续科研的启发：**
- **从“生成质量”走向“控制效用”**：下一步必须将世界模型评估与真实机器人闭环控制性能直接挂钩，测量 reward-aligned world model 对 model-based RL 或 MPC 的样本效率与渐近性能增益。
- **自适应与多教师集成**：可探索根据生成难度动态调整 SWR 窗口，或集成多个专业教师（分别擅长物理/语义/时序）以构成更鲁棒的奖励委员会，减少对单一评判器的依赖。
- **跨 embodiment 泛化**：将 RobotWorldBench 和评判器训练扩展到移动操作、双臂协作、灵巧手等更复杂 embodiment，检验奖励对齐方法是否具备跨域迁移能力。

当前世界模型研究缺乏大规模数据集和统一基准来评估其物理交互能力。现有基准通常局限于单一视角（如行人视角）、缺乏跨模态动作输入的统一定义，且未充分考察模型对外部动作序列的响应能力与记忆能力。针对这一空白，本文提出iWorld-Bench，首个专为交互式世界模型设计的综合性评测基准。

实验对14种代表性交互式世界模型进行了全面评估，包括文本控制、one-hot编码和相机参数控制三类范式。结果显示，HY-World 1.5综合表现最佳（平均分0.7873），one-hot模型交互能力强但灵活性不足，文本控制模型生成质量高而轨迹跟随较弱，相机参数模型中AC3D在轨迹容差上达到0.9091。研究还揭示了视觉保真度与动作可控性之间的根本性权衡。

iWorld-Bench为交互式世界模型提供了标准化评测体系，其跨模态统一评估框架和高质量数据集填补了领域空白。该工作不仅系统诊断了现有模型在交互能力上的关键缺陷，也为面向具身智能和机器人控制的世界模型训练提供了重要指引，具有重要的社区价值。

## 第二模块：核心架构解释

### 1. 数据处理管线（Data Processing Pipeline）

论文构建了一套四层递进的数据清洗与标准化流程，将原始异构数据转化为可训练的世界模型语料：

- **多源采集**：整合12个开源数据集（KITTI-360、nuScenes、RealEstate-10K、TartanAir-V2等）与4个模拟器（aerial_VLN、UAV_ON、Openfly、Embodied_City）的18个场景，原始数据量达 **27.8M** 帧。
- **结构统一**：将不同数据集的坐标系、相机内外参格式（矩阵、四元数、6-DoF）统一对齐到右手坐标系，并以CityWorld四层架构（模态-类别-身份-参数）存储。
- **质量过滤**：采用两阶段过滤。第一阶段进行单帧异常检测，通过95百分位亮度值与帧间MSE的滚动Z-Score识别突变帧；第二阶段进行样本密度过滤，通过1D Boxcar卷积计算异常密度，提取低密度干净区间，合并邻近片段并丢弃短于阈值的序列（详见Algorithm 1）。
- **VLM标注与人工校验**：使用GPT-4o对33万片段进行场景、天气、实体等语义标注，并通过Gemini 3.0 Flash、Qwen-VL-Max、Kimi-K2.5进行交叉验证；仅81.4%的全票通过样本直接采纳，其余18.6%经人工复核，最终精选 **2,100个视频** 构建评测子集。

### 2. 统一动作生成框架（Action Generation Framework）

这是论文的算法核心，由两部分组成：

**（1）交互动作编码（Interactive Action Encoding）**
定义四元组控制信号 **$C_t = [D, T, R, V]$**：
- **$D$（Difficulty）**：动作难度，静止为1，多自由度复合动作难度累加，最高至6。
- **$T_{ID} \in [0,26]$**：27种平移原子动作（含静止、前后左右上下及复合）。
- **$R_{ID} \in [0,26]$**：27种旋转原子动作（含静止、俯仰偏航及复合）。
- **$V \in \{0,1\}$**：有效性标志，基于训练数据频率标记罕见动作为无效。

**（2）统一编码映射（Unified Encoding Mapping）**
由于现有模型实际仅支持部分动作（如不支持上下平移或顺/逆时针旋转），论文优先定义了 **各9个实际可用的平移与旋转原子动作**，组合成 **81个基础动作**。每个动作被赋予唯一ID，并建立映射字典，同时指向三种模态的具体控制信号：
- **相机内外参**：SE(3)外参矩阵或6-DoF位姿变化。
- **One-hot编码**：对应键盘按键组合（如W+A、↑+→）。
- **文本控制信号**：自然语言描述（如"move forward and turn left"）。

### 3. 任务设计

基于上述框架，论文设计了 **6类任务**，共 **4,900个** 测试样本：
- **Action Control Difficulty 1-4**：难度递增的基础动作跟随任务（各1,000个），从单自由度静止/前后左右，到四自由度复杂复合动作。
- **Memory Ability（200个）**：构建循环路径（如出发后返回原点），评估模型在长时推理中的视觉一致性与空间记忆。
- **Camera Following（700个）**：专为相机参数控制模型设计，使用真实相机轨迹文件测试细粒度跟随能力。

### 4. 评估体系

定义 **9个指标**，分三大维度：
- **Generation Quality（4个）**：Image Quality（MUSIQ）、Brightness Consistency、Color Temperature Constraint（HSV空间时序相似性）、Sharpness Retention（Tenengrad + BRISQUE断路器逻辑）。
- **Trajectory Following（3个）**：Motion Smoothness（基于插帧模型的LPIPS/SSIM/MSE）、Trajectory Accuracy（ViPE切线空间方向映射）、Trajectory Tolerance（与真值视频交叉校准）。
- **Memory Ability（2个）**：Memory Symmetry（对称帧像素一致性）、Trajectory Alignment（瞬时位移向量镜像相似性）。

class UnifiedActionFramework:
    def __init__(self):
        # 实际优先支持的9个平移与9个旋转原子动作
        self.base_translations = 9   # 0-8: 静止,前,后,左,右,前左,前右,后左,后右
        self.base_rotations = 9      # 0-8: 静止,上,下,右,左,上右,上左,下右,下左
        self.mapping = self._build_unified_dict()  # 81个基础动作
    
    def _build_unified_dict(self):
        """为每个(T_id, R_id)建立跨模态唯一映射"""
        mapping = {}
        for t in range(9):
            for r in range(9):
                action_code = t * 9 + r
                mapping[action_code] = {
                    'camera_extrinsics': compute_se3(t, r),
                    'onehot': key_combination_to_vector(t, r),  # 如 W+A, ↑+→
                    'text': template_to_language(t, r)          # 如 "forward+left"
                }
        return mapping
    
    def encode(self, modality: str, raw_action) -> int:
        """将任意模态输入统一转换为81维动作ID"""
        if modality == 'camera':
            return self._extrinsics_to_id(raw_action)
        elif modality == 'onehot':
            return self._keyboard_to_id(raw_action)
        elif modality == 'text':
            return self._text_to_id(raw_action)
        else:
            raise ValueError("Unsupported modality")

class DataFilter:
    """两阶段数据过滤管线（对应Algorithm 1）"""
    def process(self, video_dataset, tau=0.06, L_min=81):
        clean_clips = []
        for video in video_dataset:
            # Stage 1: 单帧异常检测
            anomalies = []
            for t in range(1, len(video)):
                M_light = percentile(gray(video[t]), 95)
                M_mse = mse(video[t], video[t-1])
                if is_brightness_outlier(M_light) or zscore(M_mse) > 4:
                    anomalies.append(t)
            
            # Stage 2: 密度过滤与片段提取
            signal = construct_binary_signal(anomalies, T=len(video))
            density = boxcar_convolve(signal, window=W)
            zones = extract_continuous_zones(density < tau)
            zones = bridge_merge(zones, max_gap=5)
            for z in zones:
                if length(z) >= L_min:
                    clean_clips.append(video[z.start:z.end])
        return clean_clips

class iWorldBenchEvaluator:
    def __init__(self, framework: UnifiedActionFramework):
        self.framework = framework
    
    def evaluate(self, model, task) -> dict:
        # 统一动作编码
        action_seq = self.framework.encode(task.modality, task.raw_action)
        
        # 模型推理
        generated = model.generate(initial_frame=task.first_frame, 
                                   action_sequence=action_seq)
        
        # 三维度量计算
        metrics = {}
        # Generation Quality
        metrics['image_quality'] = compute_musiq(generated)
        metrics['brightness'] = temporal_brightness_consistency(generated)
        metrics['color_temp'] = hsv_temporal_similarity(generated)
        metrics['sharpness'] = tenengrad_with_brisque_circuit_breaker(generated)
        
        # Trajectory Following
        metrics['motion_smoothness'] = interpolation_model_lpips(generated)
        metrics['trajectory_accuracy'] = vipe_tangent_alignment(generated, task.gt_path)

## 第三模块：核心学术问答

Q1: 这篇论文试图解决什么核心问题？

A1: 本文旨在解决交互式世界模型领域缺乏 **大规模、多样化、且动作模态统一** 的基准测试问题。具体而言，现有基准存在三大缺陷：场景与视角多样性严重不足；文本、one-hot编码、相机内外参等异构交互模态之间缺乏统一描述语言，导致无法公平比较；以及现有任务缺乏对模型动作序列响应能力与记忆能力的系统性评估。iWorld-Bench通过统一动作空间和六类任务设计，首次实现了对交互式世界模型交互能力的全面量化。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 核心解决方案包含三个层面：
- **数据层面**：建立了一套从27.8M原始帧到33万视频片段的标准化处理管线，涵盖4种视角（无人车、无人机、人形、机器人）、9种户外天气与5种室内光照，并通过VLM多模型交叉验证与人工复核确保标注质量。
- **框架层面**：提出 **Action Generation Framework**，将交互动作解耦为平移与旋转子空间，定义四元组 $[D, T, R, V]$，并建立81个基础动作的统一映射字典，使文本、one-hot、相机参数三种模态的控制信号能够被唯一编码到同一动作ID，实现跨模态公平评估。
- **评估层面**：设计了4,900个涵盖4级难度动作控制、记忆能力与相机跟随的测试任务，并定义了9个跨维度指标（生成质量、轨迹跟随、记忆能力），系统性地量化了14个代表性模型的能力边界。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

A3: 实验设计的关键支撑在于其 **对三类主流控制范式的全覆盖与细粒度解耦评估**：
- **模型覆盖**：评估了14个模型，包括5个文本控制（如HunyuanVideo-1.5）、2个one-hot控制（HY-World 1.5, Matrix-game 2.0）、7个相机参数控制（如AC3D, MotionCtrl），确保了结论的普适性。
- **任务分层**：Action Control任务按自由度（Difficulty 1-4）递增设计，能够精细刻画模型从基础到复杂的动作跟随能力衰减曲线。
- **真值对照**：Camera Following任务使用700个真实相机参数文件作为真值，Trajectory Tolerance指标通过与真值视频交叉校准消除估计器方差，提供了高可信度的物理执行保真度测量。
- **人类验证**：通过人类偏好研究验证了9个自动指标与主观感知的高度一致性。

Q4: 这篇论文最显著的贡献点（Top 3）是什么？

A4:
- **贡献1**：提出了 **iWorld-Bench**，这是首个专门为交互式世界模型设计的综合基准，填补了该领域缺乏统一评估标准的空白。
- **贡献2**：构建了 **统一动作生成框架**，通过81个基础动作的跨模态映射字典，首次实现了文本、one-hot编码、相机内外参三种异构控制范式在同一基准下的公平比较。
- **贡献3**：基于4,900个任务与9维指标对14个模型进行了大规模诊断性评估，明确揭示了当前模型在 **生成质量与动作可控性之间存在显著权衡**（如AC3D和HY-World 1.5在可控性上超越基础模型，但视觉保真度下降），为后续研究指明了优化方向。

Q5: 这项工作在哪些相关研究的基础上做了推进？（列举1-2个最核心的前置工作即可）

A5:
- **前置工作1**：**WorldScore** (Duan et al., 2025)。该工作提出了面向通用世界模型的基准，包含相机控制评估，但缺乏交互式任务设计与多模态动作统一框架。iWorld-Bench在此基础上扩展了显式的动作序列评估与跨模态对齐机制。
- **前置工作2**：**MotionCtrl / CameraCtrl** (Wang et al., 2024; He et al., 2025)。这类工作提出了基于相机内外参的视频生成控制方法，但仅在自身设定的单一模态下验证。iWorld-Bench将这些模型纳入统一框架，首次在相同动作语义下与文本控制、one-hot控制模型进行公平对比，暴露了其轨迹跟随能力的真实差距。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

## 第二模块：核心架构解释

RLDX-1 的架构由两大核心组件构成：**时序感知的 Vision-Language Model (VLM)** 负责将视频与语言指令编码为认知特征，**多模态动作模型**负责基于 Flow Matching 生成动作块。其完整前向与训练流程如下。

### 1. VLM：从视频-语言到认知特征
- **基础模型**：以 **Qwen3-VL 8B** 为基座，经机器人专属 VQA 数据微调（RLDX-1-VLM），强化空间关系、子任务推理与低级动作对齐能力。
- **Cognition Tokens**：在输入序列末尾追加 **64 个可学习查询 token**，经 VLM 处理后提取其对应隐藏状态作为 **cognition features** $\rvh_t$。论文发现取**第 18 层**（而非最终层）特征对动作生成最优（表 4a）。
- **运动感知**：Vision Encoder 第 9 层后插入 **STSS（Space-Time Self-Similarity）模块**，计算局部时空自相似度张量 $\rmS_t$ 并残差更新特征；LLM 第 4 层后将过去帧观测压缩为**单个上下文 token**（平均池化），当前帧继续参与后续层，兼顾时序推理与计算效率。
- **长期记忆**：在 VLM 后插入轻量 Transformer **Memory Module**。维护一个队列 $\rmQ_t$，缓存最近 **$n_{\text{mem}}=3$** 个 cognition 特征（采样间隔为动作块长度 $H+1$）。将 $\rmQ_t$ 与当前 $\rvh_t$ 拼接后做**因果自注意力**，输出记忆特征 $\rvm_t$。

### 2. 动作模型：基于 MSAT 的 Flow Matching
- **输入**：cognition 特征 $\rvh_t$、记忆特征 $\rvm_t$、本体状态 $\rvs_t$、可选物理信号 $\rvp_t$、以及噪声动作块 $\rva_{t:t+H}^\tau$。
- **MSAT（Multi-Stream Action Transformer）**：扩展自 MM-DiT。
  - **早期多流块**：存在物理信号时为**三流**（Cognition $\rmC$ / Action $\rmA$ / Physics $\rmP$），否则为双流（$\rmC$ / $\rmA$）。每流有独立的 RMSNorm 与 QKV 投影。
  - **联合自注意力**：将各流 QKV 在** token 维度拼接**，执行单次自注意力，输出再按长度拆分回流，分别做残差更新。
  - **后期融合块**：三流逐步合并为双流或单流，最终输出动作去噪速度。
  - **关键设计**：Action Stream 加 **RoPE** 以捕捉动作块内时序；Flow Matching 时间步 $\tau$ 编码为** in-context token** 拼入 Action Stream，而非 adaLN 特征调制；Physics Stream 可独立屏蔽（mask），兼容缺失物理信号的数据。
- **物理信号预测**：联合去噪未来动作块与未来 **$L$ 步物理信号** $\rvp_{t+1:t+L}$，作为辅助目标，迫使模型内化接触动力学。

### 3. 三阶段训练流程
- **预训练**：在 1.5M episodes 的多形态数据（OXE、DROID、AgiBot、Fourier ActionNet 等 + 150K 合成数据）上训练。冻结 VLM 除顶部 4 层外全部参数，100K 步，全局 batch size 8192。
- **中训练**：针对 ALLEX（内部数据:合成数据 = 5:5）与 FR3（DROID:内部 = 8:2）。插入运动模块、记忆模块与物理流。新增参数先经 2K 步对齐预热（冻结预训练参数），再联合训练 25K 步。
- **后训练**：任务特定模仿学习，辅以自适应数据收集（针对失败模式迭代补数据）与可选 **RECAP 强化学习**。RECAP 中采用**文本预测 Critic**：直接利用 VLM 原生数字 token 接口自回归预测值函数，避免新增预测头。

### 4. 推理优化
- **静态图转换**：预计算 RoPE 与 attention mask，将完整前向捕获为**单一 CUDA Graph**，消除 kernel launch 开销。
- **手工核融合**：针对短预填充（short-prefill）设计融合核（如 RMSNorm→RoPE→Attention），减少内存往返。
- **效果**：PyTorch Eager 下全模态延迟 **71.2 ms** → 优化后 **43.7 ms**（1.63× 加速，表 2）。

```python
class RLDX1:
    def __init__(self):
        # VLM with temporal and memory extensions
        self.vlm = RLDX1_VLM(base="Qwen3-VL-8B")
        self.memory = MemoryModule(n_mem=3, interval=H+1)
        # Action model: Flow Matching DiT with MSAT
        self.msat = MSAT(n_layers=..., use_physics_stream=True)
        self.action_head = Linear(d_a, action_dim)
        self.physics_head = Linear(d_p, physics_dim)

    def forward(self, video, text, state, physics=None,
                noisy_action=None, tau=None):
        # ---- VLM Encoding ----
        v_feats = self.vlm.vision_encoder(video)   # STSS inside layer 9
        # Temporal compression happens inside LLM after layer 4
        cognition_queries = self.vlm.cognition_queries  # [64, d]
        inputs = concat(v_feats, text, cognition_queries)
        h_t = self.vlm.llm(inputs, extract_layer=18)  # cognition features

        # ---- Memory Module ----
        mem_queue = self.memory.get_queue()  # past cognition features
        m_t = self.memory.transformer(concat(mem_queue, h_t))  # causal

        # ---- Action Model (Flow Matching) ----
        # Build streams
        c_stream = self.msat.proj_c(concat(h_t, m_t))
        tau_token = self.msat.embed_tau(tau)  # in-context timestep
        a_stream = self.msat.proj_a(concat(state, noisy_action, tau_token))
        p_stream = self.msat.proj_p(physics) if physics is not None else None

        # MSAT blocks: joint self-attention across streams
        for block in self.msat.blocks:
            qkv_c = block.qkv_c(block.norm_c(c_stream))
            qkv_a = block.qkv_a(block.norm_a(a_stream))
            qkv_list = [qkv_c, qkv_a]
            if p_stream is not None:
                qkv_p = block.qkv_p(block.norm_p(p_stream))
                qkv_list.append(qkv_p)
            
            # Concatenate along token dimension
            qkv_joint = concat(qkv_list, dim='token')
            out_joint = block.joint_attention(qkv_joint)
            
            # Split back to respective streams
            splits = [c_stream.size(0), a_stream.size(0)]
            if p_stream is not None:
                splits.append(p_stream.size(0))
            out_streams = split(out_joint, splits)
            
            c_stream = c_stream + out_streams[0]
            a_stream = a_stream + out_streams[1]
            if p_stream is not None:
                p_stream = p_stream + out_streams[2]
            
            # Stream-wise FFN (SwiGLU)
            c_stream = c_stream + block.ff_c(block.norm_c(c_stream))
            a_stream = a_stream + block.ff_a(block.norm_a(a_stream))
            if p_stream is not None:
                p_stream = p_stream + block.ff_p(block.norm_p(p_stream))

        # ---- Prediction ----
        v_action = self.action_head(a_stream)      # velocity for denoising
        v_physics = self.physics_head(p_stream) if p_stream is not None else None
        return v_action, v_physics
```

## 第二模块：核心架构解释

本文是一篇系统性综述，其核心"架构"是作者提出的**三维效率分类法**，覆盖从训练范式到部署推理的全栈技术体系。以下按论文结构拆解其技术框架，并附上一个集成这些效率机制的伪代码实现。

### 1. 高效建模范式（Efficient Modeling）
该维度解决"如何减少生成步骤并支持长程交互"的问题，分为两大分支：

- **扩散模型蒸馏：** 将多步教师模型压缩为少步/单步学生模型。
  - **Step-Reduction Distillation：** 直接匹配教师多步去噪结果，如 GPD 将 Wan 的 48 步压缩至 6 步。
  - **Consistency Distillation：** 强制同一轨迹上不同时间点的预测一致（如 VideoLCM、AnimateLCM），实现单步生成。
  - **对抗蒸馏：** 通过分布匹配（DMD/DMD2）或对抗训练（Seaweed-APT）在单步约束下维持感知质量。

- **长程交互式建模：** 突破固定片段生成限制，支持持久世界模拟。
  - **纯自回归（AR）：** 将视频视为离散 Token 序列（VideoGPT、VideoPoet、Loong、Genie、iVideoGPT），天然支持无限滚动，但存在误差累积。
  - **混合 AR-扩散：** 时间维度自回归，单帧/块内用扩散生成（Progressive AR Video Diffusion、FramePack），在可扩展性与保真度之间折中。
  - **流式因果扩散：** 通过因果注意力或块因果设计将扩散模型本身因果化（CausVid、Diffusion Forcing、Self Forcing、Rolling Forcing），支持增量式生成。

### 2. 高效架构（Efficient Architecture）
该维度解决"如何降低时空冗余与注意力复杂度"的问题，分为四大分支：

- **分层与 VAE 设计：** 通过粗到精的级联生成（Pyramidal Flow Matching、Waver、FlashVideo）或深度压缩（DC-VideoGen 实现 64× 空间压缩、REGEN 实现 32× 时间压缩）降低状态维度。
- **长上下文与记忆机制：** 
  - **视觉记忆：** 保留关键帧（FramePack、WorldPack、StoryMem）。
  - **空间记忆：** 使用点云/网格等显式几何表示（EvoWorld、VMem、HunyuanWorld-Voyager）。
  - **压缩上下文：** 将历史压缩为隐向量（MemFlow、VideoSSM、LoViC）。
  - **隐式模型记忆：** 通过测试时训练（TTT、LaCT）在线更新子网络权重记忆长程信息。
- **高效注意力：** 用稀疏注意力（SVG、VMoBA）、窗口注意力（DiTFastAttn、LongLive、STA）、线性注意力（SANA-Video、SLA）或状态空间模型（LinGen、LaMamba-Diff）替代全注意力，将二次复杂度降至线性或近线性。
- **外推与 RoPE：** 通过频率缩放（RIFLEx）、注意力衰减（UltraViCo）或块相对论 RoPE（Infinity-RoPE）突破训练时长的生成长度限制。

### 3. 高效推理（Efficient Inference）
该维度解决"如何在硬件上实时运行"的问题，分为四大分支：

- **并行：** 空间/序列并行（DistriFusion、Video-Infinity）、流水线并行（LiveAvatar、xDiT）。
- **缓存：** 利用相邻去噪步的冗余复用中间特征（PAB、TeaCache、FasterCache、PreciseCache、WorldCache）。
- **剪枝：** Token 级合并（VidToMe、AsymRnR、TDTM）与结构级剪枝（VDMini、Mobile Video DiT、UniCP）。
- **量化：** 注意力中心量化（SageAttention 系列）、训练后量化（ViDiT-Q、DVD-Quant、LRQ-DiT）、量化感知训练（QVGen）与动态时序量化（AdaTSQ、QuantCache）。

### Python 风格伪代码

以下伪代码展示了一个集成上述效率技术的**流式视频世界模型**推理框架：

```python
class EfficientVideoWorldModel:
    def __init__(self):
        # 1. 深度压缩 VAE（对应 Efficient VAE）
        self.vae = Causal3DVAE(spatial_compression=64, temporal_compression=4)
        
        # 2. 生成骨干：DiT + 稀疏/线性注意力 + Infinity-RoPE（对应 Efficient Attention / Extrapolation）
        self.backbone = DiT(
            attention="sparse_windowed",  # 可选: sparse / linear / SSM
            rope="infinity_block_relative",
            use_distilled_steps=True      # 已蒸馏为 6 步
        )
        
        # 3. 分层记忆（对应 Long Context & Memory）
        self.memory = HierarchicalMemory(
            visual=FramePacker(max_frames=32),
            spatial=SurfelPointCloudMap(),
            compressed=SSMStateCompressor(state_dim=512)
        )
        
        # 4. 推理优化引擎（对应 Efficient Inference）
        self.engine = InferenceOptimizer(
            parallel=PipelineParallel(num_stages=4),
            cache=PreciseCache(threshold=0.02),
            quantizer=QVGenQuantizer(w_bits=4, a_bits=4),
            pruner=TokenMerger(merge_ratio=0.3)
        )
    
    def encode_condition(self, text, action, trajectory):
        # 多模态条件编码：文本、动作、轨迹、布局
        return self.condition_encoder(text, action, trajectory)
    
    def generate_chunk(self, prompt, action, history_frames):
        # Step 1: 记忆检索与上下文压缩
        mem_tokens = self.memory.encode(history_frames)
        
        # Step 2: 条件融合
        cond = self.encode_condition(prompt, action, trajectory=None)
        
        # Step 3: 低步数因果扩散（已蒸馏，如 6 步）
        latent = sample_noise()
        for t in self.distilled_timesteps:  # [T_1, ..., T_6]
            # 3a: 缓存决策——若特征变化低于阈值则复用
            if self.engine.cache.should_reuse(latent, t):
                feat = self.engine.cache.get(t)
            else:
                # 3b: 稀疏/窗口注意力 + 记忆注入
                feat = self.backbone(
                    latent, t, cond, 
                    context=mem_tokens,
                    causal_mask=True
                )
                # 3c: Token 剪枝（仅在深层执行）
                feat = self.engine.pruner(feat)
                self.engine.cache.put(t, feat)
            
            # 3d: 单步去噪
            latent = self.denoise(feat, latent, t)
        
        # Step 4: 低比特量化解码
        frames = self.engine.quantizer.decode(self.vae.decode(latent))
        
        # Step 5: 更新记忆库
        self.memory.update(frames)
        return frames
    
    def rollout(self, prompt, action_sequence):
        """
        流式因果生成：对应 Streaming Causal Diffusion / Rolling Forcing
        支持分钟级甚至无限长交互式 rollout
        """
        video = []
        for action in action_sequence:
            chunk = self.generate_chunk(prompt, action, video)
            video.extend(chunk)
            # 可选：在线测试时训练更新隐式记忆
            # self.memory.implicit_update(chunk)
        return video
```

## 第二模块：核心架构解释

### 1. 基础世界模型架构（Tokenize–Predict–Decode）

 backbone 采用双分支视觉 tokenizer：
- **上下文编码器 $E_c$**：将条件帧编码为 $N_c=1280$ 个上下文 token $z^{\mathrm{ctx}}$。
- **动态编码器 $E_d$**：在 $E_c$ 特征金字塔的交叉注意力下，将观测帧编码为 $N_d=80$ 个动态 token $z^{\mathrm{dyn}}_t$，仅承载残差变化。
- 连续动作 $a_t$ 被离散化为动作 token $\hat{a}_t$，与视觉 token 交错为统一序列 $s = [z^{\mathrm{ctx}}, z^{\mathrm{dyn}}_1, \hat{a}_1, z^{\mathrm{dyn}}_2, \hat{a}_2, \dots]$。
- 12 层 LLaMA 因果 Transformer 执行标准 next-token 预测，损失仅作用于动态 token：

$$
\mathcal{L}_{\mathrm{AR}} = -\sum_{t=1}^{T} \log p_\theta\bigl(z^{\mathrm{dyn}}_t \mid z^{\mathrm{ctx}}, z^{\mathrm{dyn}}_{<t}, \hat{a}_{\le t}\bigr).
$$

### 2. Reward-Aligned Post-Training（三阶段管线）

**阶段 A：RobotWorldBench 构建**
从 RT-1、BridgeData V2、CALVIN、LIBERO 四个机器人数据集中筛选 10,000 条视频-指令对。每条样本 $(l, v)$ 由人工或规则化退化管道标注六维原始分数向量 $\mathbf{r}=(r_1,\dots,r_6)$，对应：
1. Instruction Following (0–3)
2. Manipulation Success (0–2)
3. Action–Outcome Consistency (0–1)
4. Temporal Consistency (0–1)
5. Contact Realism (0–1)
6. Physics Adherence (0–2)

**阶段 B：教师评判器（RoboAlign-Judge）**
以 Qwen3-VL-8B-Thinking 为基座，通过 LoRA 微调得到教师 $f_\phi$。输入指令 $l$ 与视频 $v$，输出六维结构化分数 $\hat{\mathbf{r}} = f_\phi(l,v)$。训练目标为监督负对数似然：

$$
\mathcal{L}_{\mathrm{teacher}} = -\mathbb{E}_{(l,v,\mathbf{r})\sim\mathcal{D}_{\mathrm{bench}}} \bigl[\log p_\phi(\mathbf{r}\mid l, v)\bigr].
$$

**阶段 C：学生奖励蒸馏与在线迭代**
教师推理成本过高（~2.8 s/视频），无法直接用于在线 RL。作者将其蒸馏为轻量学生 $g_\psi$（ViT-Base/16 部分解冻 + 4 层文本 Transformer + MLP 头，共 98M 参数）。教师分数按维度最大分值归一化到 $[0,1]$ 后，学生通过加权 Huber 损失回归：

$$
\mathcal{L}_{\mathrm{distill}} = \mathbb{E}_{(l,v)\sim\mathcal{D}_{\mathrm{distill}}} \sum_{k=1}^{6} \lambda_k \,\mathrm{Huber}_{\delta_h}\!\bigl([g_\psi(l,v)]_k,\; \tilde{s}_k(l,v)\bigr).
$$

为对抗分布漂移导致的 reward hacking，每 $K$ 个策略更新后，用当前策略生成新 rollout，由教师重新打分并刷新学生（Online Iterative Distillation）。

**阶段 D：GRPO 后训练**
学生提供复合奖励：

$$
R(\hat{x}_{1:T}) = \sum_{k=1}^{6} w_k \,[g_\psi(l,\hat{x}_{1:T})]_k.
$$

采用 GRPO：对每组 $G$ 个 rollout 计算组内归一化优势：

$$
A^{(j)} = \frac{R(\hat{x}^{(j)}) - \operatorname{mean}_j R}{\operatorname{std}_j R},
$$

并优化裁剪策略梯度目标：

$$
\mathcal{L}_{\mathrm{GRPO}} = -\mathbb{E}\!\Biggl[\frac{1}{G}\sum_{j=1}^{G} \min\!\Bigl(\rho^{(j)} A^{(j)},\; \operatorname{clip}(\rho^{(j)}, 1-\epsilon, 1+\epsilon)\, A^{(j)}\Bigr)\Biggr] + \beta\, D_{\mathrm{KL}}(p_\theta \| p_{\theta_0}).
$$

### 3. Sliding Window Re-encoding (SWR)

SWR 是一种**无需重新训练**的推理策略，用于抑制长程自回归漂移。
- 将 $T$ 帧 rollout 划分为 $K=\lceil T/W\rceil$ 段，每段长度 $W$。
- 段内按标准自回归生成。
- **段边界刷新**：将第 $k$ 段最后一帧解码到像素空间，再通过 tokenizer 重新编码为新的上下文 token $z^{\mathrm{ctx}}_{k+1}$，作为下一段的初始条件：

$$
\hat{x}_{kW} = \bigl[\mathcal{D}_{\mathrm{vis}}(z^{\mathrm{ctx}}_k, \hat{z}^{\mathrm{dyn}}_{(k-1)W+1:kW})\bigr]_{t=kW}, \quad (z^{\mathrm{ctx}}_{k+1}, z^{\mathrm{dyn}}_0) = \mathcal{T}_{\mathrm{vis}}(\hat{x}_{kW}).
$$

论文给出理想化误差分析：在局部收缩假设下，SWR 的误差界为 $W\varepsilon + (W\varepsilon+\delta_q)/(1-\alpha^W)$，不随 $T$ 显式增长；而原生 AR 在最坏情况下为 $\mathcal{O}(T\varepsilon)$。

```python
# ========== 学生奖励模型（蒸馏与推理） ==========
class StudentRewardModel(nn.Module):
    def __init__(self):
        # 视觉分支：ViT-Base/16，后4层可训练
        self.visual_encoder = ViTBase16(unfreeze_last_n=4)
        # 文本分支：轻量4层Transformer
        self.text_encoder = LightweightTransformer(layers=4, hidden=256)
        # 融合+评分头
        self.fusion_mlp = MLP([1024, 512, 256, 6], activation='GELU')
        self.sigmoid = nn.Sigmoid()

    def forward(self, frames, instruction):
        # frames: [B, N=8, 3, 224, 224]
        v = self.visual_encoder(frames).mean(dim=1)   # [B, 768]
        t = self.text_encoder(instruction)            # [B, 256]
        z = torch.cat([v, t], dim=-1)                 # [B, 1024]
        scores = self.sigmoid(self.fusion_mlp(z))     # [B, 6] in [0,1]
        return scores

def distill_student(teacher, student, dataloader):
    for batch in dataloader:
        l, v, teacher_scores = batch
        # teacher_scores 已按维度归一化到 [0,1]
        pred = student(v, l)  # [B, 6]
        loss = weighted_huber_loss(pred, teacher_scores, weights=LAMBDA, delta=0.5)
        loss.backward()
        optimizer.step()

# ========== GRPO 奖励对齐后训练 ==========
def grpo_post_train(policy, student_reward, ref_policy, dataloader):
    for batch in dataloader:
        l, actions = batch
        # 生成 G 个 rollout
        rollouts = [policy.generate(l, actions) for _ in range(G)]
        # 学生打分
        rewards = torch.stack([student_reward(r, l).sum(dim=-1) for r in rollouts])
        advantages = (rewards - rewards.mean()) / (rewards.std() + 1e-8)
        
        # 计算比率与裁剪
        ratios = policy.prob(rollouts) / ref_policy.prob(rollouts)
        surr1 = ratios * advantages
        surr2 = torch.clamp(ratios, 1-EPS, 1+EPS) * advantages
        policy_loss = -torch.min(surr1, surr2).mean()
        kl_loss = beta * kl_divergence(policy, ref_policy)
        loss = policy_loss + kl_loss
        loss.backward()
        optimizer.step()
        
        # 在线迭代蒸馏：每 K 步用教师刷新学生
        if step % K == 0:
            fresh_rollouts = [policy.generate(l, actions) for _ in range(M)]
            teacher_scores = [teacher(r, l) for r in fresh_rollouts]
            update_student_with_fresh_labels(student_reward, fresh_rollouts, teacher_scores)

# ========== Sliding Window Re-encoding 推理 ==========
def swr_generate(policy, tokenizer, decoder, x0, actions, T, W):
    # 初始编码
    z_ctx, z_dyn_0 = tokenizer.encode(x0)
    generated_frames = []
    
    for k in range(0, T, W):
        segment_frames = []
        z_dyn = z_dyn_0
        # 段内自回归生成 W 帧
        for t in range(W):
            if k + t >= T:
                break
            z_dyn = policy.next_token(z_ctx, z_dyn, actions[k+t])
            segment_frames.append(z_dyn)
        # 解码整段并取最后一帧
        decoded_segment = decoder(z_ctx, segment_frames)
        last_frame = decoded_segment[-1]
        generated_frames.extend(decoded_segment)
        # 刷新上下文：重新编码最后一帧作为下一段条件
        z_ctx, z_dyn_0 = tokenizer.encode(last_frame)
    
    return generated_frames
```

## 第二模块：核心架构解释

### 1. 数据处理管线（Data Processing Pipeline）

论文构建了一套四层递进的数据清洗与标准化流程，将原始异构数据转化为可训练的世界模型语料：

- **多源采集**：整合12个开源数据集（KITTI-360、nuScenes、RealEstate-10K、TartanAir-V2等）与4个模拟器（aerial_VLN、UAV_ON、Openfly、Embodied_City）的18个场景，原始数据量达 **27.8M** 帧。
- **结构统一**：将不同数据集的坐标系、相机内外参格式（矩阵、四元数、6-DoF）统一对齐到右手坐标系，并以CityWorld四层架构（模态-类别-身份-参数）存储。
- **质量过滤**：采用两阶段过滤。第一阶段进行单帧异常检测，通过95百分位亮度值与帧间MSE的滚动Z-Score识别突变帧；第二阶段进行样本密度过滤，通过1D Boxcar卷积计算异常密度，提取低密度干净区间，合并邻近片段并丢弃短于阈值的序列（详见Algorithm 1）。
- **VLM标注与人工校验**：使用GPT-4o对33万片段进行场景、天气、实体等语义标注，并通过Gemini 3.0 Flash、Qwen-VL-Max、Kimi-K2.5进行交叉验证；仅81.4%的全票通过样本直接采纳，其余18.6%经人工复核，最终精选 **2,100个视频** 构建评测子集。

### 2. 统一动作生成框架（Action Generation Framework）

这是论文的算法核心，由两部分组成：

**（1）交互动作编码（Interactive Action Encoding）**
定义四元组控制信号 **$C_t = [D, T, R, V]$**：
- **$D$（Difficulty）**：动作难度，静止为1，多自由度复合动作难度累加，最高至6。
- **$T_{ID} \in [0,26]$**：27种平移原子动作（含静止、前后左右上下及复合）。
- **$R_{ID} \in [0,26]$**：27种旋转原子动作（含静止、俯仰偏航及复合）。
- **$V \in \{0,1\}$**：有效性标志，基于训练数据频率标记罕见动作为无效。

**（2）统一编码映射（Unified Encoding Mapping）**
由于现有模型实际仅支持部分动作（如不支持上下平移或顺/逆时针旋转），论文优先定义了 **各9个实际可用的平移与旋转原子动作**，组合成 **81个基础动作**。每个动作被赋予唯一ID，并建立映射字典，同时指向三种模态的具体控制信号：
- **相机内外参**：SE(3)外参矩阵或6-DoF位姿变化。
- **One-hot编码**：对应键盘按键组合（如W+A、↑+→）。
- **文本控制信号**：自然语言描述（如"move forward and turn left"）。

### 3. 任务设计

基于上述框架，论文设计了 **6类任务**，共 **4,900个** 测试样本：
- **Action Control Difficulty 1-4**：难度递增的基础动作跟随任务（各1,000个），从单自由度静止/前后左右，到四自由度复杂复合动作。
- **Memory Ability（200个）**：构建循环路径（如出发后返回原点），评估模型在长时推理中的视觉一致性与空间记忆。
- **Camera Following（700个）**：专为相机参数控制模型设计，使用真实相机轨迹文件测试细粒度跟随能力。

### 4. 评估体系

定义 **9个指标**，分三大维度：
- **Generation Quality（4个）**：Image Quality（MUSIQ）、Brightness Consistency、Color Temperature Constraint（HSV空间时序相似性）、Sharpness Retention（Tenengrad + BRISQUE断路器逻辑）。
- **Trajectory Following（3个）**：Motion Smoothness（基于插帧模型的LPIPS/SSIM/MSE）、Trajectory Accuracy（ViPE切线空间方向映射）、Trajectory Tolerance（与真值视频交叉校准）。
- **Memory Ability（2个）**：Memory Symmetry（对称帧像素一致性）、Trajectory Alignment（瞬时位移向量镜像相似性）。

class UnifiedActionFramework:
    def __init__(self):
        # 实际优先支持的9个平移与9个旋转原子动作
        self.base_translations = 9   # 0-8: 静止,前,后,左,右,前左,前右,后左,后右
        self.base_rotations = 9      # 0-8: 静止,上,下,右,左,上右,上左,下右,下左
        self.mapping = self._build_unified_dict()  # 81个基础动作
    
    def _build_unified_dict(self):
        """为每个(T_id, R_id)建立跨模态唯一映射"""
        mapping = {}
        for t in range(9):
            for r in range(9):
                action_code = t * 9 + r
                mapping[action_code] = {
                    'camera_extrinsics': compute_se3(t, r),
                    'onehot': key_combination_to_vector(t, r),  # 如 W+A, ↑+→
                    'text': template_to_language(t, r)          # 如 "forward+left"
                }
        return mapping
    
    def encode(self, modality: str, raw_action) -> int:
        """将任意模态输入统一转换为81维动作ID"""
        if modality == 'camera':
            return self._extrinsics_to_id(raw_action)
        elif modality == 'onehot':
            return self._keyboard_to_id(raw_action)
        elif modality == 'text':
            return self._text_to_id(raw_action)
        else:
            raise ValueError("Unsupported modality")

class DataFilter:
    """两阶段数据过滤管线（对应Algorithm 1）"""
    def process(self, video_dataset, tau=0.06, L_min=81):
        clean_clips = []
        for video in video_dataset:
            # Stage 1: 单帧异常检测
            anomalies = []
            for t in range(1, len(video)):
                M_light = percentile(gray(video[t]), 95)
                M_mse = mse(video[t], video[t-1])
                if is_brightness_outlier(M_light) or zscore(M_mse) > 4:
                    anomalies.append(t)
            
            # Stage 2: 密度过滤与片段提取
            signal = construct_binary_signal(anomalies, T=len(video))
            density = boxcar_convolve(signal, window=W)

            for z in zones:
                if length(z) >= L_min:
                    clean_clips.append(video[z.start:z.end])
        return clean_clips

## 第二模块：核心架构解释

RLDX-1 的架构由两大核心组件构成：**时序感知的 Vision-Language Model (VLM)** 负责将视频与语言指令编码为认知特征，**多模态动作模型**负责基于 Flow Matching 生成动作块。其完整前向与训练流程如下。

### 1. VLM：从视频-语言到认知特征
- **基础模型**：以 **Qwen3-VL 8B** 为基座，经机器人专属 VQA 数据微调（RLDX-1-VLM），强化空间关系、子任务推理与低级动作对齐能力。
- **Cognition Tokens**：在输入序列末尾追加 **64 个可学习查询 token**，经 VLM 处理后提取其对应隐藏状态作为 **cognition features** $\rvh_t$。论文发现取**第 18 层**（而非最终层）特征对动作生成最优（表 4a）。
- **运动感知**：Vision Encoder 第 9 层后插入 **STSS（Space-Time Self-Similarity）模块**，计算局部时空自相似度张量 $\rmS_t$ 并残差更新特征；LLM 第 4 层后将过去帧观测压缩为**单个上下文 token**（平均池化），当前帧继续参与后续层，兼顾时序推理与计算效率。
- **长期记忆**：在 VLM 后插入轻量 Transformer **Memory Module**。维护一个队列 $\rmQ_t$，缓存最近 **$n_{\text{mem}}=3$** 个 cognition 特征（采样间隔为动作块长度 $H+1$）。将 $\rmQ_t$ 与当前 $\rvh_t$ 拼接后做**因果自注意力**，输出记忆特征 $\rvm_t$。

### 2. 动作模型：基于 MSAT 的 Flow Matching
- **输入**：cognition 特征 $\rvh_t$、记忆特征 $\rvm_t$、本体状态 $\rvs_t$、可选物理信号 $\rvp_t$、以及噪声动作块 $\rva_{t:t+H}^\tau$。
- **MSAT（Multi-Stream Action Transformer）**：扩展自 MM-DiT。
  - **早期多流块**：存在物理信号时为**三流**（Cognition $\rmC$ / Action $\rmA$ / Physics $\rmP$），否则为双流（$\rmC$ / $\rmA$）。每流有独立的 RMSNorm 与 QKV 投影。
  - **联合自注意力**：将各流 QKV 在** token 维度拼接**，执行单次自注意力，输出再按长度拆分回流，分别做残差更新。
  - **后期融合块**：三流逐步合并为双流或单流，最终输出动作去噪速度。
  - **关键设计**：Action Stream 加 **RoPE** 以捕捉动作块内时序；Flow Matching 时间步 $\tau$ 编码为** in-context token** 拼入 Action Stream，而非 adaLN 特征调制；Physics Stream 可独立屏蔽（mask），兼容缺失物理信号的数据。
- **物理信号预测**：联合去噪未来动作块与未来 **$L$ 步物理信号** $\rvp_{t+1:t+L}$，作为辅助目标，迫使模型内化接触动力学。

### 3. 三阶段训练流程
- **预训练**：在 1.5M episodes 的多形态数据（OXE、DROID、AgiBot、Fourier ActionNet 等 + 150K 合成数据）上训练。冻结 VLM 除顶部 4 层外全部参数，100K 步，全局 batch size 8192。
- **中训练**：针对 ALLEX（内部数据:合成数据 = 5:5）与 FR3（DROID:内部 = 8:2）。插入运动模块、记忆模块与物理流。新增参数先经 2K 步对齐预热（冻结预训练参数），再联合训练 25K 步。
- **后训练**：任务特定模仿学习，辅以自适应数据收集（针对失败模式迭代补数据）与可选 **RECAP 强化学习**。RECAP 中采用**文本预测 Critic**：直接利用 VLM 原生数字 token 接口自回归预测值函数，避免新增预测头。

### 4. 推理优化
- **静态图转换**：预计算 RoPE 与 attention mask，将完整前向捕获为**单一 CUDA Graph**，消除 kernel launch 开销。
- **手工核融合**：针对短预填充（short-prefill）设计融合核（如 RMSNorm→RoPE→Attention），减少内存往返。
- **效果**：PyTorch Eager 下全模态延迟 **71.2 ms** → 优化后 **43.7 ms**（1.63× 加速，表 2）。

```python
class RLDX1:
    def __init__(self):
        # VLM with temporal and memory extensions
        self.vlm = RLDX1_VLM(base="Qwen3-VL-8B")
        self.memory = MemoryModule(n_mem=3, interval=H+1)
        # Action model: Flow Matching DiT with MSAT
        self.msat = MSAT(n_layers=..., use_physics_stream=True)
        self.action_head = Linear(d_a, action_dim)
        self.physics_head = Linear(d_p, physics_dim)

    def forward(self, video, text, state, physics=None,
                noisy_action=None, tau=None):
        # ---- VLM Encoding ----
        v_feats = self.vlm.vision_encoder(video)   # STSS inside layer 9
        # Temporal compression happens inside LLM after layer 4
        cognition_queries = self.vlm.cognition_queries  # [64, d]
        inputs = concat(v_feats, text, cognition_queries)
        h_t = self.vlm.llm(inputs, extract_layer=18)  # cognition features

        # ---- Memory Module ----
        mem_queue = self.memory.get_queue()  # past cognition features
        m_t = self.memory.transformer(concat(mem_queue, h_t))  # causal

        # ---- Action Model (Flow Matching) ----
        # Build streams
        c_stream = self.msat.proj_c(concat(h_t, m_t))
        tau_token = self.msat.embed_tau(tau)  # in-context timestep
        a_stream = self.msat.proj_a(concat(state, noisy_action, tau_token))
        p_stream = self.msat.proj_p(physics) if physics is not None else None

        # MSAT blocks: joint self-attention across streams
        for block in self.msat.blocks:
            qkv_c = block.qkv_c(block.norm_c(c_stream))
            qkv_a = block.qkv_a(block.norm_a(a_stream))
            qkv_list = [qkv_c, qkv_a]
            if p_stream is not None:
                qkv_p = block.qkv_p(block.norm_p(p_stream))
                qkv_list.append(qkv_p)
            
            # Concatenate along token dimension
            qkv_joint = concat(qkv_list, dim='token')
            out_joint = block.joint_attention(qkv_joint)
            
            # Split back to respective streams
            splits = [c_stream.size(0), a_stream.size(0)]
            if p_stream is not None:
                splits.append(p_stream.size(0))
            out_streams = split(out_joint, splits)
            
            c_stream = c_stream + out_streams[0]
            a_stream = a_stream + out_streams[1]
            if p_stream is not None:
                p_stream = p_stream + out_streams[2]
            
            # Stream-wise FFN (SwiGLU)
            c_stream = c_stream + block.ff_c(block.norm_c(c_stream))
            a_stream = a_stream + block.ff_a(block.norm_a(a_stream))
            if p_stream is not None:
                p_stream = p_stream + block.ff_p(block.norm_p(p_stream))

        # ---- Prediction ----
        v_action = self.action_head(a_stream)      # velocity for denoising
        v_physics = self.physics_head(p_stream) if p_stream is not None else None
        return v_action, v_physics
```

## 第二模块：核心架构解释

本文是一篇系统性综述，其核心"架构"是作者提出的**三维效率分类法**，覆盖从训练范式到部署推理的全栈技术体系。以下按论文结构拆解其技术框架，并附上一个集成这些效率机制的伪代码实现。

### 1. 高效建模范式（Efficient Modeling）
该维度解决"如何减少生成步骤并支持长程交互"的问题，分为两大分支：

- **扩散模型蒸馏：** 将多步教师模型压缩为少步/单步学生模型。
  - **Step-Reduction Distillation：** 直接匹配教师多步去噪结果，如 GPD 将 Wan 的 48 步压缩至 6 步。
  - **Consistency Distillation：** 强制同一轨迹上不同时间点的预测一致（如 VideoLCM、AnimateLCM），实现单步生成。
  - **对抗蒸馏：** 通过分布匹配（DMD/DMD2）或对抗训练（Seaweed-APT）在单步约束下维持感知质量。

- **长程交互式建模：** 突破固定片段生成限制，支持持久世界模拟。
  - **纯自回归（AR）：** 将视频视为离散 Token 序列（VideoGPT、VideoPoet、Loong、Genie、iVideoGPT），天然支持无限滚动，但存在误差累积。
  - **混合 AR-扩散：** 时间维度自回归，单帧/块内用扩散生成（Progressive AR Video Diffusion、FramePack），在可扩展性与保真度之间折中。
  - **流式因果扩散：** 通过因果注意力或块因果设计将扩散模型本身因果化（CausVid、Diffusion Forcing、Self Forcing、Rolling Forcing），支持增量式生成。

### 2. 高效架构（Efficient Architecture）
该维度解决"如何降低时空冗余与注意力复杂度"的问题，分为四大分支：

- **分层与 VAE 设计：** 通过粗到精的级联生成（Pyramidal Flow Matching、Waver、FlashVideo）或深度压缩（DC-VideoGen 实现 64× 空间压缩、REGEN 实现 32× 时间压缩）降低状态维度。
- **长上下文与记忆机制：** 
  - **视觉记忆：** 保留关键帧（FramePack、WorldPack、StoryMem）。
  - **空间记忆：** 使用点云/网格等显式几何表示（EvoWorld、VMem、HunyuanWorld-Voyager）。
  - **压缩上下文：** 将历史压缩为隐向量（MemFlow、VideoSSM、LoViC）。
  - **隐式模型记忆：** 通过测试时训练（TTT、LaCT）在线更新子网络权重记忆长程信息。
- **高效注意力：** 用稀疏注意力（SVG、VMoBA）、窗口注意力（DiTFastAttn、LongLive、STA）、线性注意力（SANA-Video、SLA）或状态空间模型（LinGen、LaMamba-Diff）替代全注意力，将二次复杂度降至线性或近线性。
- **外推与 RoPE：** 通过频率缩放（RIFLEx）、注意力衰减（UltraViCo）或块相对论 RoPE（Infinity-RoPE）突破训练时长的生成长度限制。

### 3. 高效推理（Efficient Inference）
该维度解决"如何在硬件上实时运行"的问题，分为四大分支：

- **并行：** 空间/序列并行（DistriFusion、Video-Infinity）、流水线并行（LiveAvatar、xDiT）。
- **缓存：** 利用相邻去噪步的冗余复用中间特征（PAB、TeaCache、FasterCache、PreciseCache、WorldCache）。
- **剪枝：** Token 级合并（VidToMe、AsymRnR、TDTM）与结构级剪枝（VDMini、Mobile Video DiT、UniCP）。
- **量化：** 注意力中心量化（SageAttention 系列）、训练后量化（ViDiT-Q、DVD-Quant、LRQ-DiT）、量化感知训练（QVGen）与动态时序量化（AdaTSQ、QuantCache）。

### Python 风格伪代码

以下伪代码展示了一个集成上述效率技术的**流式视频世界模型**推理框架：

```python
class EfficientVideoWorldModel:
    def __init__(self):
        # 1. 深度压缩 VAE（对应 Efficient VAE）
        self.vae = Causal3DVAE(spatial_compression=64, temporal_compression=4)
        
        # 2. 生成骨干：DiT + 稀疏/线性注意力 + Infinity-RoPE（对应 Efficient Attention / Extrapolation）
        self.backbone = DiT(
            attention="sparse_windowed",  # 可选: sparse / linear / SSM
            rope="infinity_block_relative",
            use_distilled_steps=True      # 已蒸馏为 6 步
        )
        
        # 3. 分层记忆（对应 Long Context & Memory）
        self.memory = HierarchicalMemory(
            visual=FramePacker(max_frames=32),
            spatial=SurfelPointCloudMap(),
            compressed=SSMStateCompressor(state_dim=512)
        )
        
        # 4. 推理优化引擎（对应 Efficient Inference）
        self.engine = InferenceOptimizer(
            parallel=PipelineParallel(num_stages=4),
            cache=PreciseCache(threshold=0.02),
            quantizer=QVGenQuantizer(w_bits=4, a_bits=4),
            pruner=TokenMerger(merge_ratio=0.3)
        )
    
    def encode_condition(self, text, action, trajectory):
        # 多模态条件编码：文本、动作、轨迹、布局
        return self.condition_encoder(text, action, trajectory)
    
    def generate_chunk(self, prompt, action, history_frames):
        # Step 1: 记忆检索与上下文压缩
        mem_tokens = self.memory.encode(history_frames)
        
        # Step 2: 条件融合
        cond = self.encode_condition(prompt, action, trajectory=None)
        
        # Step 3: 低步数因果扩散（已蒸馏，如 6 步）
        latent = sample_noise()
        for t in self.distilled_timesteps:  # [T_1, ..., T_6]
            # 3a: 缓存决策——若特征变化低于阈值则复用
            if self.engine.cache.should_reuse(latent, t):
                feat = self.engine.cache.get(t)
            else:
                # 3b: 稀疏/窗口注意力 + 记忆注入
                feat = self.backbone(
                    latent, t, cond, 
                    context=mem_tokens,
                    causal_mask=True
                )
                # 3c: Token 剪枝（仅在深层执行）
                feat = self.engine.pruner(feat)
                self.engine.cache.put(t, feat)
            
            # 3d: 单步去噪
            latent = self.denoise(feat, latent, t)
        
        # Step 4: 低比特量化解码
        frames = self.engine.quantizer.decode(self.vae.decode(latent))
        
        # Step 5: 更新记忆库
        self.memory.update(frames)
        return frames
    
    def rollout(self, prompt, action_sequence):
        """
        流式因果生成：对应 Streaming Causal Diffusion / Rolling Forcing
        支持分钟级甚至无限长交互式 rollout
        """
        video = []
        for action in action_sequence:
            chunk = self.generate_chunk(prompt, action, video)
            video.extend(chunk)
            # 可选：在线测试时训练更新隐式记忆
            # self.memory.implicit_update(chunk)
        return video
```

A6: 局限性主要体现在三个层面：第一，**硬件协同讨论不足**，论文以算法和架构为主，对专用加速器、内存带宽墙与计算-通信协同设计的涉猎有限；第二，**缺乏统一基准**，综述依赖现有工作的独立评估，不同效率技术（如蒸馏、量化、缓存）的**联合优化**效果与相互干扰（如剪枝放大量化误差、缓存加剧长程漂移）尚未被系统量化；第三，**长程瓶颈的本质归因模糊**，图6揭示的 10 分钟退化表明，当前效率优化多聚焦单步加速，但长程因果一致性的根本瓶颈可能在于**建模范式本身**（如帧级自回归的误差累积、缺乏物理约束的隐空间），而非单纯的计算加速。

"未讲明的故事"是：当生成时长扩展到分钟级甚至无限流式时，现有的基于帧或块的外推与记忆方法是否足以维持物理一致性，抑或需要**全新的因果-物理耦合表示**（如结合神经符号推理或显式物理引擎的混合世界模型）。对后续科研的启发在于：未来需建立面向长程交互式世界模型的**统一评估协议**（超越 VBench 等短片段指标），并探索"效率-物理一致性"的联合优化框架，而非孤立地追求加速比或 FID 分数。
