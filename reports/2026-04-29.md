### 1. KinDER: A Physical Reasoning Benchmark for Robot Learning and Planning

Code Dataset Academic Accepted 🟢 Code 📊 Dataset 🔥 Hot | Score: 4.45/5.0

> 机器人物理推理基准KinDER

**Authors**: Yixuan Huang, Bowen Li, Vaibhav Saxena, Yichao Liang, Utkarsh Aashu Mishra et al.
**Affiliation**: Princeton University, Carnegie Mellon University, Georgia Tech, University of Cambridge, NVIDIA, MIT (Tier 2)
**Links**: [arXiv](http://arxiv.org/abs/2604.25788v1) | [PDF](https://arxiv.org/pdf/2604.25788v1) | [中文翻译](https://hjfy.top/arxiv/2604.25788) | [Code](https://prpl-group.com/kinder-site/)

现有机器人学习与规划基准通常将物理推理与感知、语言理解或特定领域复杂度耦合在一起，难以对物理推理本身进行孤立评估。尽管物理推理是具身智能的核心，学界缺乏一个统一、标准化的测试平台来系统比较经典任务与运动规划（TAMP）、强化学习、模仿学习以及基础模型等不同范式在物理推理上的能力。KinDER针对这一空白，专门设计了隔离物理推理挑战的基准环境。

本文提出KinDER（Kinematic and Dynamic Embodied Reasoning），包含25个程序生成的模拟环境，分为Kinematic2D、Dynamic2D、Kinematic3D和Dynamic3D四类，系统覆盖五大核心物理推理挑战：基本空间关系、非抓取式多物体操作、工具使用、组合几何约束与动态约束。所有环境均采用以物体为中心的状态表示，并与感知和语言解耦。此外，作者发布了KinDERGym——一个兼容Gymnasium的Python库，提供参数化技能与概念、多种遥操作接口及预采集演示数据；以及KinDERBench——包含13个基线的标准化评测套件，涵盖双层规划（TAMP）、LLM/VLM规划、模型预测控制（MPC）、基于模型的强化学习（MBRL）、扩散策略（Diffusion Policy）与微调VLA（π_0.5）等方法。

实验结果表明，当前方法在多数环境中表现不佳：双层规划（BP）平均成功率最高（0.57），但工程成本高；LLM/VLM规划器在提供上下文示例后性能提升，但在复杂环境中仍显著落后；扩散策略与VLA在部分动态和长程任务（如DynPushPullHook2D、SweepIntoDrawer3D）上展现出令人意外的鲁棒性；而标准RL方法（PPO、SAC）因稀疏奖励难以奏效。此外，作者在移动机械臂上完成了real-to-sim-to-real实验，验证了仿真环境与现实物理交互的一致性。

对关注世界模型与具身智能的研究者而言，KinDER提供了一个高保真、可复现的物理推理评测平台。它不仅为评估世界模型对物理规律的理解能力提供了标准化环境，也直接支持VLA、扩散策略及基于模型的规划方法在物理推理、技能学习与sim-to-real迁移方面的研究，有望推动该领域从各自为战走向系统对比与协同进步。

**论文领域：** 机器人学习与规划（横跨 VLA、World Model 及经典 TAMP 的物理推理评测基准）

**TL;DR:** Yixuan Huang 等人提出了一种基于**程序生成环境 + 标准化跨范式评测套件**的 **KinDER** 框架，以解决**现有基准无法将物理推理与感知/语言/领域复杂度解耦、且缺乏跨 TAMP/RL/IL/基础模型统一对比平台**的问题，在覆盖五大物理推理挑战的 25 个仿真环境上揭示了当前各范式（尤其是端到端 VLA/RL 与显式规划）的显著能力差距。

**研究动机:**
现存方案最大的痛点在于：主流机器人基准（如 BEHAVIOR-1k、LIBERO、CALVIN）以应用驱动或广义操作为主，物理推理与感知、语言、长时程决策等挑战高度纠缠；同时，TAMP、RL、IL、FM 各自在孤立平台上评测，缺乏公平对比。本文的切入点极其巧妙：它并非提出单一算法，而是**将物理推理“提纯”**——设计 25 个从 2D 到 3D、从运动学到动力学的程序生成环境，系统隔离五大核心挑战（基本空间关系、非抓取多物体操作、工具使用、组合几何约束、动态约束），并配套统一 API 与 13 个基线，首次让不同范式在“同一起跑线”上比拼物理推理。

**核心机制:**
剥离复杂公式后，其本质创新是构建了一套**“对象中心状态（Object-Centric State）+ 参数化技能（PDDL-Options-Samplers）+ 稀疏奖励”**的分层评测体系：底层用结构化对象状态支持组合泛化与变体生成，中层提供符号-几何混合的技能接口供 TAMP 与 LLM/VLM 调用，上层通过 Gymnasium 兼容 API 和严格稀疏奖励实现 RL/IL/TAMP/FM 的公平对标。

**关键数据:**
- **最能证明有效性的数据：** 在 8 个代表性环境上，**Bilevel Planning (BP)** 以平均成功率 **0.57** 居首；尤其在 **Shelf3D**（Dynamic3D，涉及组合几何约束）中 BP 达到 **1.00**，而 Finetuned VLA 仅 **0.02**、PPO/MBRL/SAC/MPC 全部为 **0**，这直接证明在需要显式满足几何与动态约束的 3D 任务中，经典 TAMP 仍大幅领先端到端学习与纯模型预测控制。
- **存疑的试验结果：** Finetuned VLA 在 **DynPushPullHook2D**（5 障碍物，需工具使用与非抓取操作）上取得 **0.43** 的 SR，是唯一非零基线。论文自身也指出该结果“令人惊讶（surprising）”，因为 2D 渲染与物理和 VLA 预训练数据域差异极大，其成功可能源于对该环境特定视觉模式的过拟合，而非可迁移的物理推理能力；此外，**VLMPlan 与 LLMPlan 平均 SR 完全一致（均为 0.34）**，**VLMCon 与 LLMCon 也完全一致（均为 0.43）**，表明额外提供的 RGB 图像几乎未被 VLM 有效利用，其视觉感知优势在物理推理中未转化为实际增益。

## 第二模块：核心架构解释

KinDER 的整体架构由三大开源组件构成：**KinDERGarden**（环境集合）、**KinDERGym**（软件库）与 **KinDERBench**（评测套件）。

### 1. KinDERGarden：环境设计
25 个环境按 **Kinematic2D / Dynamic2D / Kinematic3D / Dynamic3D** 四类组织。所有环境共享以下核心设计：

- **Object-Centric State：** 状态被定义为从对象名（如 `robot`、`hook`）到特征向量的映射。例如，`MobileManipulator` 类型包含 SE(2) 基座位姿/速度、7DOF 臂关节配置、夹爪开度；`Movable` 类型包含 SE(3) 位姿、速度、包围盒尺寸。该设计天然支持变物体数量，便于测试泛化与规模扩展。
- **程序生成（Procedural Generation）：** 每个 `reset()` 随机化物体位姿、数量与几何布局，形成无限任务分布。
- **三模态观测输出：**
  1. 原始 Object-Centric State（供 TAMP / FM 使用）；
  2. RGB 图像（供视觉策略使用）；
  3. 固定维度展平向量（Constant-Object Variants，供标准 RL/IL 使用）。
- **稀疏奖励：** 每步 **-1**，仅当目标达成时终止，避免密集奖励对 RL 的隐性偏置。

**物理后端差异：**
- **Kinematic2D：** 纯 Python 实现，无物理引擎；状态转移由位姿变化与碰撞检测（回退机制）决定。
- **Dynamic2D：** 使用 **Pymunk** 模拟速度、加速度与接触动力学。
- **Kinematic3D：** 使用 **PyBullet** 进行前向运动学与碰撞检测，但无显式动力学；夹爪闭合时物体刚性附着。
- **Dynamic3D：** 使用 **MuJoCo** 进行全动力学仿真；夹爪通过摩擦接触抓取，物体永不刚性附着，更贴近真实物理。

### 2. KinDERGym：软件接口与数据
- **Gymnasium 兼容 API：** 标准 `reset()` / `step()` 接口，支持 `gymnasium` 生态的所有训练框架。
- **参数化技能与概念（Skills & Concepts）：**
  - **Skills** 以 **Options**（Sutton, 1999）实现，附带 PDDL 操作符与连续参数采样器（Samplers）。例如 `Pick(object, θ)` 中 `θ ∈ SE(3)` 由采样器提议。
  - **Concepts** 为关系谓词（如 `On(object, surface)`），配有基于对象状态的分类器，用于定义前置条件与效果，构成两层场景图。
- **遥操作接口：** 2D 环境支持鼠标键盘 / PS5 手柄；3D 环境支持 iPhone Web App（陀螺仪+加速度计）/ Meta Quest 3S VR 手柄，支持基座/臂/夹爪分离控制与任务空间逆运动学。
- **演示数据：** 通过遥操作与规划器结合，为 10 个环境提供每环境 **≥100** 条预收集演示。

### 3. KinDERBench：基线与评测
在 8 个代表性环境（每类 2 个）上评测 **13** 个基线：

| 范式 | 基线 |
|------|------|
| TAMP | Bilevel Planning (BP) |
| FM 规划 | LLMPlan, VLMPlan, LLMCon, VLMCon (均使用 GPT-5.2) |
| 轨迹优化 | MPC（预测采样，真值模型） |
| 基于模型的 RL | MBRL（神经网络转移模型 + MPC） |
| 生成式规划 | Generative Skill Chaining (GSC) |
| 无模型 RL | PPO, SAC |
| 模仿学习 | Diffusion Policy (DP), DP + Environment States (DPES) |
| VLA | Finetuned π₀.₅ (OpenPI) |

**评测指标：**
- **Success Rate (SR)：** 有效性。
- **Cumulative Rewards (Rwd)：** 效率（仅统计成功回合，值越接近 0 越好）。
- **Inference Time (Inf-Time)：** 每回合墙钟时间（秒）。

**实验流程：**
1. 对每个基线，在 8 个环境的特定变体上训练/配置；
2. 每个环境运行 **5 个随机种子**，每种子评估 **50 个回合**；
3. 报告平均 SR、Rwd、Inf-Time；
4. 额外进行 OOD 泛化实验（DynObstruction2D 训练 1 障碍物，测试 0/2/3 障碍物）、BP 规模扩展实验（StickButton2D 增加按钮数量）及噪声鲁棒性实验。

class KinDEREnv(gym.Env):
    def __init__(self, category="Dynamic3D", variant="Shelf3D"):
        # 根据类别选择物理后端
        self.physics = MuJoCo() if "Dynamic3D" in category else \
                       PyBullet() if "Kinematic3D" in category else \
                       Pymunk() if "Dynamic2D" in category else None
        self.robot = TidyBotPlus() if "3D" in category else CircularBase2D()
        self.objects = {}  # object-centric state 映射

    def reset(self, seed=None):
        # 程序生成：随机化物体数量、位姿、几何参数
        self.objects = self._procedural_generate(seed)
        return self._get_obs()

    def _get_obs(self, mode="object_centric"):
        if mode == "object_centric":
            # 返回结构化字典，支持变长物体
            return {name: obj.features for name, obj in self.objects.items()}
        elif mode == "rgb":
            return self.renderer.capture()
        elif mode == "flattened":
            # 仅用于 constant-object variants，固定维度
            return np.concatenate([obj.features for obj in self.objects.values()])

    def step(self, action):
        # Kinematic: 碰撞检测 + 状态回退；Dynamic: 物理仿真步进
        next_state = self._transition(action)
        reward = -1.0 if not self._check_goal() else 0.0
        terminated = self._check_goal()
        truncated = self._check_timeout()
        return self._get_obs(), reward, terminated, truncated, {}

# KinDERBench: Bilevel Planning 基线
# ==========================================
class BilevelPlanner:
    def __init__(self, skills, concepts):
        """
        skills: List[Option]，每个包含 PDDL operator + 策略 + Sampler
        concepts: Dict[str, Predicate]，含分类器函数
        """
        self.skills = skills
        self.concepts = concepts

    def plan(self, init_state, goal):
        # 高层：基于 hFF 启发式的贪婪最佳优先搜索，生成抽象计划
        abstract_plans = greedy_best_first_search(
            init_state, goal, self.skills,
            max_plans=10, timeout_sec=60
        )
        # 低层：对每个抽象计划进行回溯搜索，采样连续参数
        for abstract_plan in abstract_plans:
            trajectory = self._refine(
                abstract_plan, init_state,
                max_samples_per_step=3
            )
            if trajectory is not None:
                return trajectory  # 返回可执行轨迹
        return None  # 规划失败

    def _refine(self, abstract_plan, state, max_samples_per_step):
        trajectory = []
        for op in abstract_plan:
            sampler = self.skills[op.name].sampler
            for _ in range(max_samples_per_step):
                continuous_params = sampler.sample(state, op.objects)
                if self._check_preconditions(op, state, continuous_params):
                    next_state = self._execute_option(op, state, continuous_params)
                    trajectory.append((op, continuous_params))
                    state = next_state
                    break
            else:
                return None  # 当前步所有采样失败，回溯
        return trajectory

- **视觉在物理推理中的真正作用**尚未被挖掘：当前 VLM/VLA 未能有效利用图像输入，提示未来需设计能显式建模物理约束（如碰撞体积、力闭合）的视觉-语言-动作架构，而非将图像仅作为附加上下文。
- **可扩展性学习：** BP 在物体数量增加时成功率急剧崩溃（StickButton2D 从 1 个按钮的 0.99 降至 10 个按钮的 0.00），提示亟需通过学习增强采样、启发式学习或神经规划器来提升经典 TAMP 的规模泛化能力。

## 第一模块：一分钟核心速写

**论文领域：** 机器人学习与规划（横跨 VLA、World Model 及经典 TAMP 的物理推理评测基准）

**TL;DR:** Yixuan Huang 等人提出了一种基于**程序生成环境 + 标准化跨范式评测套件**的 **KinDER** 框架，以解决**现有基准无法将物理推理与感知/语言/领域复杂度解耦、且缺乏跨 TAMP/RL/IL/基础模型统一对比平台**的问题，在覆盖五大物理推理挑战的 25 个仿真环境上揭示了当前各范式（尤其是端到端 VLA/RL 与显式规划）的显著能力差距。

**研究动机:**
现存方案最大的痛点在于：主流机器人基准（如 BEHAVIOR-1k、LIBERO、CALVIN）以应用驱动或广义操作为主，物理推理与感知、语言、长时程决策等挑战高度纠缠；同时，TAMP、RL、IL、FM 各自在孤立平台上评测，缺乏公平对比。本文的切入点极其巧妙：它并非提出单一算法，而是**将物理推理“提纯”**——设计 25 个从 2D 到 3D、从运动学到动力学的程序生成环境，系统隔离五大核心挑战（基本空间关系、非抓取多物体操作、工具使用、组合几何约束、动态约束），并配套统一 API 与 13 个基线，首次让不同范式在“同一起跑线”上比拼物理推理。

**核心机制:**
剥离复杂公式后，其本质创新是构建了一套**“对象中心状态（Object-Centric State）+ 参数化技能（PDDL-Options-Samplers）+ 稀疏奖励”**的分层评测体系：底层用结构化对象状态支持组合泛化与变体生成，中层提供符号-几何混合的技能接口供 TAMP 与 LLM/VLM 调用，上层通过 Gymnasium 兼容 API 和严格稀疏奖励实现 RL/IL/TAMP/FM 的公平对标。

**关键数据:**
- **最能证明有效性的数据：** 在 8 个代表性环境上，**Bilevel Planning (BP)** 以平均成功率 **0.57** 居首；尤其在 **Shelf3D**（Dynamic3D，涉及组合几何约束）中 BP 达到 **1.00**，而 Finetuned VLA 仅 **0.02**、PPO/MBRL/SAC/MPC 全部为 **0**，这直接证明在需要显式满足几何与动态约束的 3D 任务中，经典 TAMP 仍大幅领先端到端学习与纯模型预测控制。
- **存疑的试验结果：** Finetuned VLA 在 **DynPushPullHook2D**（5 障碍物，需工具使用与非抓取操作）上取得 **0.43** 的 SR，是唯一非零基线。论文自身也指出该结果“令人惊讶（surprising）”，因为 2D 渲染与物理和 VLA 预训练数据域差异极大，其成功可能源于对该环境特定视觉模式的过拟合，而非可迁移的物理推理能力；此外，**VLMPlan 与 LLMPlan 平均 SR 完全一致（均为 0.34）**，**VLMCon 与 LLMCon 也完全一致（均为 0.43）**，表明额外提供的 RGB 图像几乎未被 VLM 有效利用，其视觉感知优势在物理推理中未转化为实际增益。

## 第二模块：核心架构解释

KinDER 的整体架构由三大开源组件构成：**KinDERGarden**（环境集合）、**KinDERGym**（软件库）与 **KinDERBench**（评测套件）。

### 1. KinDERGarden：环境设计
25 个环境按 **Kinematic2D / Dynamic2D / Kinematic3D / Dynamic3D** 四类组织。所有环境共享以下核心设计：

- **Object-Centric State：** 状态被定义为从对象名（如 `robot`、`hook`）到特征向量的映射。例如，`MobileManipulator` 类型包含 SE(2) 基座位姿/速度、7DOF 臂关节配置、夹爪开度；`Movable` 类型包含 SE(3) 位姿、速度、包围盒尺寸。该设计天然支持变物体数量，便于测试泛化与规模扩展。
- **程序生成（Procedural Generation）：** 每个 `reset()` 随机化物体位姿、数量与几何布局，形成无限任务分布。
- **三模态观测输出：**
  1. 原始 Object-Centric State（供 TAMP / FM 使用）；
  2. RGB 图像（供视觉策略使用）；
  3. 固定维度展平向量（Constant-Object Variants，供标准 RL/IL 使用）。
- **稀疏奖励：** 每步 **-1**，仅当目标达成时终止，避免密集奖励对 RL 的隐性偏置。

**物理后端差异：**
- **Kinematic2D：** 纯 Python 实现，无物理引擎；状态转移由位姿变化与碰撞检测（回退机制）决定。
- **Dynamic2D：** 使用 **Pymunk** 模拟速度、加速度与接触动力学。
- **Kinematic3D：** 使用 **PyBullet** 进行前向运动学与碰撞检测，但无显式动力学；夹爪闭合时物体刚性附着。
- **Dynamic3D：** 使用 **MuJoCo** 进行全动力学仿真；夹爪通过摩擦接触抓取，物体永不刚性附着，更贴近真实物理。

### 2. KinDERGym：软件接口与数据
- **Gymnasium 兼容 API：** 标准 `reset()` / `step()` 接口，支持 `gymnasium` 生态的所有训练框架。
- **参数化技能与概念（Skills & Concepts）：**
  - **Skills** 以 **Options**（Sutton, 1999）实现，附带 PDDL 操作符与连续参数采样器（Samplers）。例如 `Pick(object, θ)` 中 `θ ∈ SE(3)` 由采样器提议。
  - **Concepts** 为关系谓词（如 `On(object, surface)`），配有基于对象状态的分类器，用于定义前置条件与效果，构成两层场景图。
- **遥操作接口：** 2D 环境支持鼠标键盘 / PS5 手柄；3D 环境支持 iPhone Web App（陀螺仪+加速度计）/ Meta Quest 3S VR 手柄，支持基座/臂/夹爪分离控制与任务空间逆运动学。
- **演示数据：** 通过遥操作与规划器结合，为 10 个环境提供每环境 **≥100** 条预收集演示。

### 3. KinDERBench：基线与评测
在 8 个代表性环境（每类 2 个）上评测 **13** 个基线：

| 范式 | 基线 |
|------|------|
| TAMP | Bilevel Planning (BP) |
| FM 规划 | LLMPlan, VLMPlan, LLMCon, VLMCon (均使用 GPT-5.2) |
| 轨迹优化 | MPC（预测采样，真值模型） |
| 基于模型的 RL | MBRL（神经网络转移模型 + MPC） |
| 生成式规划 | Generative Skill Chaining (GSC) |
| 无模型 RL | PPO, SAC |
| 模仿学习 | Diffusion Policy (DP), DP + Environment States (DPES) |
| VLA | Finetuned π₀.₅ (OpenPI) |

**评测指标：**
- **Success Rate (SR)：** 有效性。
- **Cumulative Rewards (Rwd)：** 效率（仅统计成功回合，值越接近 0 越好）。
- **Inference Time (Inf-Time)：** 每回合墙钟时间（秒）。

**实验流程：**
1. 对每个基线，在 8 个环境的特定变体上训练/配置；
2. 每个环境运行 **5 个随机种子**，每种子评估 **50 个回合**；
3. 报告平均 SR、Rwd、Inf-Time；
4. 额外进行 OOD 泛化实验（DynObstruction2D 训练 1 障碍物，测试 0/2/3 障碍物）、BP 规模扩展实验（StickButton2D 增加按钮数量）及噪声鲁棒性实验。

class KinDEREnv(gym.Env):
    def __init__(self, category="Dynamic3D", variant="Shelf3D"):
        # 根据类别选择物理后端

        self.robot = TidyBotPlus() if "3D" in category else CircularBase2D()
        self.objects = {}  # object-centric state 映射

        # 程序生成：随机化物体数量、位姿、几何参数
        self.objects = self._procedural_generate(seed)
        return self._get_obs()

    def _get_obs(self, mode="object_centric"):
        if mode == "object_centric":
            # 返回结构化字典，支持变长物体
            return {name: obj.features for name, obj in self.objects.items()}
        elif mode == "rgb":
            return self.renderer.capture()
        elif mode == "flattened":
            # 仅用于 constant-object variants，固定维度
            return np.concatenate([obj.features for obj in self.objects.values()])

    def step(self, action):
        # Kinematic: 碰撞检测 + 状态回退；Dynamic: 物理仿真步进
        next_state = self._transition(action)
        reward = -1.0 if not self._check_goal() else 0.0
        terminated = self._check_goal()
        truncated = self._check_timeout()
        return self._get_obs(), reward, terminated, truncated, {}

class BilevelPlanner:
    def __init__(self, skills, concepts):
        """
        skills: List[Option]，每个包含 PDDL operator + 策略 + Sampler
        concepts: Dict[str, Predicate]，含分类器函数
        """
        self.skills = skills
        self.concepts = concepts

    def plan(self, init_state, goal):
        # 高层：基于 hFF 启发式的贪婪最佳优先搜索，生成抽象计划
        abstract_plans = greedy_best_first_search(
            init_state, goal, self.skills,
            max_plans=10, timeout_sec=60
        )
        # 低层：对每个抽象计划进行回溯搜索，采样连续参数
        for abstract_plan in abstract_plans:
            trajectory = self._refine(
                abstract_plan, init_state,
                max_samples_per_step=3
            )
            if trajectory is not None:
                return trajectory  # 返回可执行轨迹
        return None  # 规划失败

    def _refine(self, abstract_plan, state, max_samples_per_step):
        trajectory = []
        for op in abstract_plan:
            sampler = self.skills[op.name].sampler
            for _ in range(max_samples_per_step):
                continuous_params = sampler.sample(state, op.objects)
                if self._check_preconditions(op, state, continuous_params):
                    next_state = self._execute_option(op, state, continuous_params)
                    trajectory.append((op, continuous_params))
                    state = next_state
                    break
            else:
                return None  # 当前步所有采样失败，回溯
        return trajectory

### 第二模块：核心架构解释

**1. Hybrid Action Space 与概率分解**

Libra-VLA 将动作生成显式分解为离散粗意图与连续细动作。最终动作由函数 Φ 组合：

- **a_t^c ∈ V_act**：离散语义子空间，捕捉宏观方向意图。
- **a_t^f ∈ R^d**：连续几何子空间，负责精确位姿调整。

联合策略按概率链式法则分解（公式 2）：

**P(a_t | o_t, L) ≈ P(a_t^f | a_t^c, o_t) · P(a_t^c | o_t, L)**

前者由 System 1（Action Refiner）建模，后者由 System 2（Semantic Planner）建模。

**2. System 2: Semantic Planner**

- **粗粒度离散化**：将归一化动作 a_t ∈ [-1,1]^D 均匀量化为 N 个 bin（默认 N=10）。ground truth 索引通过公式 3 计算：

  **y_{t,i}^{gt} = clip( floor((a_{t,i}+1)/2 × N), 0, N-1 )**

  与 OpenVLA 等使用 N=256 的细粒度离散化不同，本文刻意采用小词汇量，将任务转化为低基数分类，以匹配 VLM 的语义推理能力。

- **Parallel Coarse-Action Head**：在 InternVL2.5-2B 后接入双向 Transformer。输入为可学习 query tokens **Q_act** 与 VLM 特征 **H_t** 的拼接，输出对应 query 位置的特征 **Z_act**，经线性层投影为 N 个 bin 的概率分布（公式 4）。训练目标为标准交叉熵损失 **L_plan**（公式 5）。

**3. System 1: Action Refiner**

- **自适应意图注入**：维护可学习 codebook **E ∈ R^{N×D}**。训练早期，若 System 2 预测准确率低于阈值 τ，则使用 ground-truth coarse token 查表获得 **e_intent**（teacher forcing）；后期切换为从预测分布采样，强制 refiner 学习对规划噪声的容错纠正。

- **精确动作生成**：采用 Diffusion Transformer。配备**独立的 SigLIP 视觉编码器**提取几何特征 **F_t^geo**，实现与 System 2 的结构解耦。模型以噪声动作 **x_k**、几何特征 **F_t^geo** 和宏观意图 **e_intent** 为条件，预测噪声 **ε_θ**（公式 6）。训练损失为标准 MSE **L_diff**。

**4. 联合训练与异步执行**

- **联合损失**：**L_total = λ_diff · L_diff + λ_plan · L_plan**（公式 7），通过系数平衡防止梯度主导。
- **异步策略**：由 FIFO Intent Buffer **Q** 管理。System 2 一次预测 **L_macro = M × H_chunk** 个粗动作（默认 M=2, H_chunk=5，即 L_macro=10），将粗动作切片压入 Q；System 1 以机器人控制频率运行，每步从 Q 中弹出对应切片作为条件，无需重复调用 VLM（公式 8）。

**5. 实验流程**

- **仿真**：在 LIBERO（4 个 task suite，每任务 50 次独立试验，共 500 rollouts/suite）与 LIBERO-Plus（7 种扰动维度，Zero-Shot 与 SFT 两种设置）上评估。
- **真实世界**：在 AgiBot G1 上执行 Wipe Stain、Pour Water、Make Sandwich 任务，与 π0 和 Go-1 对比。
- **训练**：LIBERO 训练 30k 步，LIBERO-Plus 50k 步，全局 batch size 128；**无大规模机器人数据预训练**。

<summary>详细分析</summary>

现有端到端自动驾驶规划器多基于当前观测生成轨迹，属于反应式规划，难以预见未来场景演化，易导致短视决策与安全风险。虽有研究将世界模型用于轨迹重排序或数据生成，但规划器与世界模型之间通常为松耦合，未来推理未能直接塑造规划器的内部决策过程。ProDrive针对这一 gaps，提出了基于世界模型的主动规划框架，核心在于实现自车与环境的协同演化。

## 第二模块：核心架构解释

### 整体架构与数据流

ProDrive 由两个紧耦合的组件构成：

- **Ego Module（查询中心规划器）**: 基于 BEVFormer，使用 ResNet-34 编码多视角图像。初始化可学习的 ego queries $\mathbf{Q}^{(0)} \in \mathbb{R}^{(K \cdot T) \times d}$，并通过 $L$ 层共享参数的 **Ego Refiner** 迭代细化。每层先做轨迹解码（MLP 输出 $K$ 条候选轨迹的 waypoints），再以这些轨迹点为 3D 参考点执行**可变形交叉注意力**（Deformable Cross-Attention）从图像特征中聚合空间上下文。最终输出 $K=64$ 条候选轨迹 $\boldsymbol{\tau}^{(L)}$ 和精炼的规划感知 token $\mathbf{Q}^{(L)}$。

- **Environment Module（BEV 世界模型）**: 使用独立的 Camera-LiDAR 编码器（TransFuser 风格，ResNet-34×2）生成当前 BEV 状态 $\mathbf{B}_0$。对每个候选轨迹 $k$，编码其几何与运动学信息为 action token $\mathbf{a}^k$。随后进行 $N$ 步循环未来预测：在每一步 $i$，将 $\mathbf{a}^k_i$、当前 BEV $\mathbf{B}^k_i$ 以及来自 Ego Module 的 ego token $\mathbf{s}^k_i$ 拼接为序列 $\mathbf{F}_i$，经 Transformer 编码器输出下一时刻的 action token、 enriched state token 与预测 BEV $\mathbf{B}^k_{i+1}$。

- **Ego-Environment 耦合**:
  - **Ego Token 注入**: 将 $\mathbf{Q}^{(L)}$ reshape 为 $\mathbf{Q}_{\text{plan}} \in \mathbb{R}^{K \times T \times d}$，在世界模型第 $i$ 步时取对应 timestep $t_i$ 的特征经 MLP 投影为 $\mathbf{s}^k_i$，使未来预测不仅知道“去哪里”，还知道“为什么这样规划”。
  - **端到端梯度回流**: 世界模型对所有候选并行评估后预测奖励，奖励损失（包括与规划器分数的对齐损失 $\mathcal{L}_{\text{align}}$）的梯度直接回传至 Ego Module，实现“未来评估”对“当前决策”的直接优化。

- **轨迹选择**: 对世界模型输出的多步 BEV 与 action token 进行聚合，预测 imitation reward（基于与专家轨迹的 soft proximity）和 simulation rewards（NC、DAC、TTC、Comfort、EP），按公式 $R^k = w_0 \log R_{\text{im}}^k + w_1 \log S_{\text{NC}}^k + w_2 \log S_{\text{DAC}}^k + w_3 \log(5S_{\text{TTC}}^k + 2S_{\text{C}}^k + 5S_{\text{EP}}^k)$ 计算最终分数，**argmax** 选取最优轨迹。

### 训练流程

模型在 NAVSIM v1 的 navtrain 上从头训练 15 个 epoch，使用 8 卡 DDP 与混合精度。优化器为 Adam，Ego Module 学习率 $10^{-4}$，Environment Module 学习率 $10^{-5}$。总损失为：

$$
\mathcal{L} = \mathcal{L}_{\text{traj}} + \mathcal{L}_{\text{score}} + \mathcal{L}_{\text{reward}} + \mathcal{L}_{\text{wm}} + \mathcal{L}_{\text{aux}}
$$

其中：
- $\mathcal{L}_{\text{traj}}$: 多阶段 winner-take-all $L_1$ 损失 + 多样性正则；
- $\mathcal{L}_{\text{score}}$: 规划器侧 scorer 的 BCE 损失（PDM 目标、validity、agent state、occupancy）；
- $\mathcal{L}_{\text{reward}}$: 包含 imitation reward 的 soft cross-entropy、simulation reward 的 BCE，以及 planner score 与 world-model score 的对齐损失 $\mathcal{L}_{\text{align}}$；
- $\mathcal{L}_{\text{wm}}$: 当前与未来 BEV 语义图的 Focal Loss（未来目标通过在语义画布上渲染自车框构造）；
- $\mathcal{L}_{\text{aux}}$: Ego queries 的辅助 BEV 感知损失（分割 + 检测）。

```python
class ProDrive(nn.Module):
    def __init__(self):
        # -------- Ego Module --------
        self.img_encoder = ResNet34()
        self.ego_queries = nn.Parameter(torch.randn(K * T, d))
        self.ego_refiners = nn.ModuleList([EgoRefiner(d) for _ in range(L)])
        self.traj_head = MLP(d, 3)          # 输出 (x, y, theta)
        self.scorer = ScorerHead(d)         # 规划器侧打分

        # -------- Environment Module --------
        self.bev_encoder = TransFuserEncoder(
            img_backbone=ResNet34(), 
            lidar_backbone=ResNet34()
        )
        self.world_model = TransformerEncoder(d_model=d)
        self.state_proj = MLP(d, d)         # 投影 ego token
        self.reward_head = RewardHead(d)    # 输出 imitation + simulation rewards

    def forward(self, imgs, lidar, ego_state):
        # ---- Ego Module: 生成候选轨迹与规划感知 token ----
        img_feats = self.img_encoder(imgs)
        Q = self.ego_queries + proj_ego_state(ego_state)
        
        for layer in self.ego_refiners:
            traj = self.traj_head(Q).view(K, T, 3)      # Step 1: 解码轨迹
            Q = layer(Q, traj, img_feats)               # Step 2: 可变形交叉注意力细化
        
        cand_traj = self.traj_head(Q).view(K, T, 3)
        Q_plan = Q.view(K, T, d)                        # 注入世界模型的自车 token

        # ---- Environment Module: 未来推演与评估 ----
        B0 = self.bev_encoder(imgs, lidar)              # 当前 BEV 状态
        scores = []
        
        for k in range(K):
            a = encode_trajectory(cand_traj[k])         # 轨迹 -> action token
            B = B0
            for i in range(N):                          # N 步循环未来预测
                s = self.state_proj(Q_plan[k, t_i])     # Ego Token Injection
                F = torch.stack([a, s, B.flatten()]) + scene_pos_embed[i]
                a, _, B = self.world_model(F).chunk(3, dim=0)
                B = B.view(H, W, d)
            
            R = self.reward_head(aggregate_features(a, B))
            scores.append(R)
        
        best_k = argmax(scores)
        return cand_traj[best_k], scores

def train_step(batch):
    imgs, lidar, ego_state, expert_traj, bev_gt = batch
    cand_traj, wm_scores = model(imgs, lidar, ego_state)
    
    # Ego Module 损失
    loss_traj = wta_l1_over_stages(cand_traj, expert_traj) + diversity_loss(cand_traj)
    loss_score = bce(model.scorer, pdm_target) + aux_perception_loss
    
    # Environment Module 损失
    q = softmax(-l2_distance(cand_traj, expert_traj))
    loss_im = -(q * log(wm_scores.im)).sum()
    loss_sim = bce(wm_scores.sim, anchor_sim_labels)
    loss_align = mse(softmax(model.scorer), normalize(wm_scores.total))
    loss_reward = loss_im + loss_sim + loss_align
    
    # BEV 语义预测损失（当前 + 未来）
    pred_cur, pred_fut = model.predict_bev()
    loss_wm = focal(pred_cur, bev_gt.cur) + focal(pred_fut, render_ego_on_bev(cand_traj, bev_gt.fut))
    
    loss = loss_traj + loss_score + loss_reward + loss_wm
    loss.backward()     # 端到端梯度：Environment 的 reward 信号回传至 Ego Module
```

  - 可将语言-视觉推理（VLA）引入世界模型，使未来推演具备可解释的场景理解与因果推理能力。


</details>
