## 第二模块：核心架构解释

本文不引入新的模型架构，而是以 **π₀.₅** 为基座策略，通过标准的监督微调（SFT）结合经验回放（ER）完成持续学习。整体流程可拆解为三个层面：

**1. 基础训练协议**
以负对数似然（NLL）为目标，对每个到达的任务数据 Dₖ 优化策略 π_θ：
$$L_{\rm SFT}=\mathbb{E}_{(\bm{o},\bm{a})\sim\mathcal{D}} \left[ -\log \pi_{\bm{\theta}}(\bm{a} | \bm{o}) \right]$$
优化器为 AdamW，峰值学习率 5×10⁻⁵，warmup 200 步后 cosine decay 至 5×10⁻⁶，batch size 128，EMA decay 0.998，每任务固定训练 4000 有效步。

**2. 经验回放（ER）机制**
- **Buffer 管理**：总容量 **M = B · |Dₖ|**。完成第 k 个任务训练后，将其数据存入 buffer。在训练第 k 个任务时，buffer 内仅包含前 k−1 个任务的数据，且容量均分：每个旧任务保留 **⌊M/(k−1)⌋** 条轨迹（至少 1 条）。
- **采样频率**：每步以概率 **f_r** 从 buffer 中采样旧任务数据，以概率 **1−f_r** 从当前任务采样。为保证当前任务仍有 4000 有效优化步，总训练步数扩展为 **4000 / (1−f_r)**。

**3. 动作归一化策略（关键实现细节）**
- **Strategy-I（默认）**：固定使用第一个任务（Stack Bowl）的动作统计量 **(μ₁, σ₁)** 贯穿整个任务流，确保动作空间坐标系一致。
- **Strategy-II**：每任务使用自身统计量 **(μₖ, σₖ)**，导致同一 batch 内回放数据与当前任务数据的归一化参考不一致，引发动作空间崩溃。

**Python 风格伪代码（核心逻辑）**

```python
class ContinualVLA:
    def __init__(self, B=0.2, f_r=0.2):
        self.B = B               # buffer 容量相对于单任务数据量的比例
        self.f_r = f_r           # 每步从 buffer 采样的概率
        self.buffer = {}         # task_id -> 轨迹列表
        self.norm_stats = None   # Strategy-I: 固定首任务归一化统计量 (mu, sigma)
        self.policy = load_pi05()

    def train_on_task_stream(self, task_datasets):
        # task_datasets: [D1, D2, D3, D4]
        for k, D_k in enumerate(task_datasets, start=1):
            # Strategy-I: 仅在第一个任务时计算并锁定归一化统计量
            if k == 1:
                self.norm_stats = compute_action_stats(D_k)

            # 补偿回放步数，保证当前任务有效训练步为 4000
            total_steps = int(4000 / (1 - self.f_r))

            for step in range(total_steps):
                # 以概率 f_r 从 buffer 采样旧任务，否则从当前任务采样
                if random() < self.f_r and len(self.buffer) > 0:
                    tid = random_choice(list(self.buffer.keys()))
                    batch = sample_batch(self.buffer[tid], batch_size=128)
                else:
                    batch = sample_batch(D_k, batch_size=128)

                # 统一使用首任务统计量进行动作归一化
                batch.actions = (batch.actions - self.norm_stats.mu) / self.norm_stats.sigma

                # 标准 VLA 监督微调损失
                loss = -self.policy.log_prob(batch.observations, batch.instructions, batch.actions).mean()
                loss.backward()
                optimizer.step()

            # 当前任务训练结束后，将其存入 buffer 并在所有已见任务间重新平衡容量
            self._update_buffer(D_k, k)

    def _update_buffer(self, D_k, k):
        M = int(self.B * len(D_k))      # buffer 总容量
        self.buffer[k] = list(D_k)      # 先完整存入当前任务数据
        # 在全部 k 个已见任务间均分容量，每个任务保留上限 floor(M/k)，至少 1 条
        budget_per_task = max(1, M // k)
        for tid in self.buffer:
            self.buffer[tid] = self.buffer[tid][:budget_per_task]
```

### 2. FineVLA: Fine-Grained Instruction Alignment for Steerable Vision-Language-Action Policies

Code Dataset 🟢 Code 📊 Dataset 🔥 Hot | Score: 4.15/5.0

> 细粒度指令对齐增强VLA策略可操控性

**Authors**: Xintong Hu, Xuhong Huang, Jinyu Zhang, Yutong Yao, Yuchong Sun et al.
**Affiliation**: Unknown (Tier 0)
**Links**: [arXiv](http://arxiv.org/abs/2605.27284v1) | [PDF](https://arxiv.org/pdf/2605.27284v1) | [中文翻译](https://hjfy.top/arxiv/2605.27284) | [图文精读](../rich_readings/2026-05-27/2605.27284/README.md)

现有机器人数据集通常仅包含粗粒度的目标级语言标注（如“拿起杯子”），忽略了执行关键细节（如主动臂选择、接近方向、接触区域、运动路径等），导致Vision-Language-Action（VLA）策略难以遵循人类关于“如何执行”的指令，限制了可操控策略学习与机器人视频理解。

FineVLA提出了一个完整的开源框架，系统性地解决了上述问题。该框架包含四个核心组件：（1）FineVLA-Tool数据构建工具，统一了来自10个开源数据集的972,247条轨迹，通过动作-状态规范化与基于DTW的层次聚类筛选出47,159条代表性轨迹，并基于十维细粒度模式（涵盖动作序列、主动执行器、目标对象、接触与接近、轨迹与朝向、失败与恢复等）进行人工验证标注，构建出FineVLA-Data；（2）RoboFine-Bench评测基准，包含500段视频、10,816个原子事实与1,030个VQA问题，用于评估机器人视频理解能力；（3）RoboFine-VLM，基于Qwen3.5-397B-A17B在FineVLA-Data上微调得到的机器人专用VLM标注器，用于可扩展的细粒度标注；（4）FineVLA-Policy，通过在固定轨迹、动作与视觉观测的条件下，仅改变配对语言指令的FG（细粒度）与Raw（目标级）混合比例，系统研究了动作对齐监督对策略学习的影响。

实验在RoboTwin仿真与真实世界双臂平台上展开，得出三项关键发现。第一，细粒度监督不会损害目标级任务成功率：FG-only在三种策略设置下均优于Raw-only，提升幅度为+1.4至+8.1个百分点。第二，细粒度与目标级指令具有互补性：随着FG比例增加，成功率呈现一致的倒U型趋势，在FG:Raw=1:2至1:1时达到峰值；最佳混合设置在RoboTwin仿真中达到86.8%/82.5%（Easy/Hard），在真实世界双平台操作中达到62.7/100，显著优于Raw-only的49.9。第三，细粒度监督直接提升了因子级可操控控制：在真实世界任务中，姿态（+23）、颜色（+18）和接近方向（+18）等目标级指令完全未指定的属性获得了最大提升。RoboFine-VLM在评测基准上也达到71.0%的VQA准确率与83.6%的Hard模式字幕总分，显著优于通用VLM。

该研究的意义在于，它首次通过大规模对照实验证明了细粒度过程级语言应作为目标级指令的补充而非替代，为可操控VLA策略提供了开放的数据基础设施、评测基准、可扩展标注器与训练方案。其释放的代码、数据与模型检查点将直接推动具身智能领域在细粒度动作对齐、语言条件控制及开源机器人基础模型方面的研究。

## 第二模块：核心架构解释

### 1. 数据构建：FineVLA-Tool 与 FineVLA-Data

整个数据管线分为四阶段，目的是将 10 个开源数据集的 972,247 条异构轨迹转化为 47,159 条带人工验证细粒度标注的代表性轨迹。

- **Stage 1：格式统一与过滤**。将所有轨迹转为 LeRobot 2.1 格式，剔除无效视频。
- **Stage 2：动作-状态规范化**。将不同数据集的动作/状态表示（绝对/相对/增量；关节空间/末端执行器空间；多种旋转编码）统一规范为**绝对坐标 + 归一化四元数（xyzw）**。随后计算动作-状态 DTW 距离，剔除不一致的损坏轨迹。
- **Stage 3：DTW 聚类与代表采样**。对每个任务内的轨迹，基于规范化后的动作序列计算两两 DTW 距离（帧级代价区分关节空间与 EEF 空间，EEF 代价包含位置、四元数测地距离、夹爪状态，其中夹爪权重设为 100.0 以突出关键交互），再进行层次聚类，从每个类簇中选取 2-3 条靠近 medoid 的高质量轨迹。这一步将数据量从 97 万压缩至约 4.7 万，同时保留操作策略的多样性。
- **Stage 4：十维细粒度标注与人工验证**。对每条代表性轨迹，先用 Qwen3.5-Plus 生成步骤化描述，再由人工审核修正。标注覆盖十个控制相关维度：**Action sequence、Active actor、Target object、Initial configuration、Final configuration、Contact & approach、Trajectory & orientation、Object interaction、Failure & recovery、Body motion**。最终数据集平均指令长度从 9.3 词增至 **96.8 词**，信息密度提升约 10.4 倍。

### 2. 基准与可扩展标注器：RoboFine-Bench 与 RoboFine-VLM

- **RoboFine-Bench**：包含严格隔离的 500 条视频（来自 10 个数据集，覆盖 32 种本体），10,816 条原子事实，1,030 道 VQA 题。分两个赛道：
  - **VQA 赛道**：探测模型对执行级细节的理解，按 Entity & Scene Grounding、Action & Motion Understanding、Interaction & State Reasoning 三个轴报告。
  - **Caption 赛道**：要求模型生成与动作对齐的步骤级描述，通过 LLM judge（GPT-5.4-Pro）与原子事实对齐，计算 Consistency、Coverage、Anti-Hallucination 和 Overall 分数。
- **RoboFine-VLM**：在 Qwen3.5-397B-A17B 基座上，用 47,159 条人工验证数据做全参数 SFT（256 H200，9 epoch，约 40 小时），作为未来可扩展的自动标注器。在 Bench 上达到 **71.0%** VQA 准确率和 **83.6%** Hard Caption Overall，显著优于最强通用基线 Gemini-3.1-Pro（62.1% VQA；78.1% Caption）。

### 3. 策略训练：FineVLA-Policy 与指令混合

作者不提出新架构，而是隔离**语言监督信号**本身的影响。基于 StarVLA 代码库（共享 Qwen3.5-4B 视觉-语言主干），测试两种动作解码框架：

- **StarVLA-OFT**：在预定义 action token 的隐状态上接轻量 MLP，并行回归连续动作块，L1 损失。
- **StarVLA-GR00T**：双系统设计，VL 主干作为 System 2 慢思考，DiT 流匹配模块作为 System 1 生成连续动作。

**关键控制：指令混合（Instruction Mixing）**。从同一批源轨迹中构建两个并行数据集：
- **FG 数据集**：仅包含被 FineVLA-Tool 选中的代表性轨迹，配对**细粒度过程级指令**（RDT 上 1,287 条；AlohaMix 上 5,872 条）。
- **Raw 数据集**：包含**全部**源轨迹，配对原始**目标级指令**（RDT 上 6,061 条；AlohaMix 上 84,067 条）。

两者轨迹、动作标签、视觉观测完全一致，**仅语言指令不同**。FG:Raw 比例控制训练时的采样权重（如 1:1 表示约 50% 步骤使用 FG 指令）。共比较 7 种比例：Raw-only、1:4、1:2、1:1、2:1、4:1、FG-only。

**训练流程**：
1. **预训练**：100k 步，64×A100，全局 batch size 512。RDT-OFT、RDT-GR00T 使用 RDT 数据；AlohaMix-OFT 使用 AlohaMix 数据（约 13 倍 RDT 规模）。
2. **RoboTwin 微调**：在 Clean + Random 训练集（27,500 条轨迹）上微调 100k 步，8×A100，全局 batch size 128，此阶段应用 FG:Raw 混合。
3. **真实世界微调**：在 Cobot Magic 双臂平台上采集的 12 个桌面任务共 600 条演示上进一步微调。

```python
# ========== FineVLA-Tool: Data Construction ==========
def build_finevla_data(raw_datasets):
    # Stage 1: Unify format (LeRobot 2.1)
    trajectories = load_and_unify(raw_datasets)  # 972,247 trajectories
    
    # Stage 2: Canonicalize action/state + consistency filtering
    trajectories = canonicalize_to_abs_quat(trajectories)
    trajectories = filter_by_dtw_action_state_consistency(trajectories)
    
    # Stage 3: DTW-based clustering and representative sampling
    representatives = []
    for task in group_by_task(trajectories):
        D = compute_dtw_distance_matrix(
            task, 
            frame_cost=joint_or_eef_cost  # EEF: pos + quat_geodesic + gripper*100
        )
        clusters = hierarchical_clustering(D, linkage='average')
        reps = select_medoid_samples(clusters, samples_per_cluster=2)
        representatives.extend(reps)
    # Result: 47,159 representative trajectories
    
    # Stage 4: Fine-grained annotation (10-dim schema) + human verification
    dataset = []
    for traj in representatives:
        draft = vlm_generate_steps(traj.video, prompt=FG_SCHEMA_PROMPT)
        fg_instruction = human_verify_and_correct(draft, traj.video)
        dataset.append((traj.obs, traj.action, fg_instruction))
    return FineVLAData(dataset)


# ========== FineVLA-Policy: Training with Controlled Mixture ==========
def train_steerable_vla(fg_dataset, raw_dataset, fg_raw_ratio, policy_arch):
    """
    fg_raw_ratio: tuple (fg_weight, raw_weight), e.g., (1, 1)
    policy_arch: 'OFT' or 'GR00T'
    """
    policy = StarVLA(backbone="Qwen3.5-4B", decoder=policy_arch)
    
    for step in range(PRETRAIN_STEPS + FINETUNE_STEPS):
        # Sample according to FG:Raw mixture probability
        p_fg = fg_raw_ratio[0] / sum(fg_raw_ratio)
        if random() < p_fg:
            batch = sample(fg_dataset)      # fine-grained process-level language
        else:
            batch = sample(raw_dataset)     # raw goal-level language
        
        # Identical trajectory, actions, and observations; ONLY language differs
        obs = batch.observations            # multi-view RGB
        lang = batch.instruction            # FG or Raw
        actions = batch.actions             # continuous action chunk
        
        # Forward pass
        pred_actions = policy(obs, lang)
        
        if policy_arch == 'OFT':
            loss = L1_loss(pred_actions, actions)
        else:  # GR00T
            loss = flow_matching_loss(pred_actions, actions)
        
        update(policy.parameters(), loss)
    
    return policy
```

A1: 现有开源机器人数据集中的语言标注仅为粗粒度的目标级描述（如“拿起杯子”），缺少执行级细节（如使用哪只手臂、从哪个方向接近、接触物体的哪个部位）。这导致训练出的 VLA 策略无法通过自然语言对执行过程进行细粒度操控。本文旨在构建一套开放的**动作对齐细粒度监督基础设施**，并系统验证这种监督能否提升策略的可操控性，同时不损害目标级任务成功率。

- **FineVLA-Tool**：统一 10 个数据集的 97 万条轨迹，通过 DTW 聚类降采样至 4.7 万条代表性轨迹，并建立覆盖十个控制维度的细粒度标注模式，经人工验证后构成 FineVLA-Data。

- **数据层面**：未来工作应探索完全自动化的细粒度标注管线（降低人工验证成本），并将十维标注模式扩展到更复杂的移动操作和长程任务。

- **训练层面**：倒 U 型趋势提示社区，在构建大规模 VLA 训练数据时，不应盲目追求全量细粒度标注，而应设计最优的 FG:Raw 混合策略，以兼顾目标级泛化与执行级可控性。

**推断的方法流程**：

1. **隐世界模型（Latent World Model）**：环境动态被编码至潜在空间，支持状态转移的隐式推演与轨迹 rollout。
2. **轨迹搜索**：在当前隐状态上，通过采样或轻量级搜索（如 MPPI-style shooting）生成一批候选轨迹。
3. **隐式能量函数提取**：从已收集的离线或在线数据中学习一个能量函数，该函数对高价值轨迹赋予低能量，对低价值轨迹赋予高能量，从而锚定策略优化的方向。
4. **扩散策略优化**：不直接参数化策略网络输出动作，而是将策略视为对**搜索轨迹分布**的 score function。通过扩散模型的去噪过程，在潜在空间中逐步优化轨迹表示，使其能量降低、价值提升。
5. **统一对齐**：由于策略改进直接作用于搜索产生的轨迹分布，而非依赖独立的价值函数近似，搜索与策略学习在训练过程中保持一致。

**Python 风格伪代码（基于摘要推断，非论文原文）**：

```python
class MBDPO:
    def __init__(self, world_model, diffusion_score_net, energy_net):
        self.world_model = world_model          # 隐世界模型 p(s_{t+1}|s_t,a_t)
        self.score_net = diffusion_score_net    # 扩散策略的 score function
        self.energy_net = energy_net            # 隐式能量函数 E(trajectory)
    
    def search_trajectories(self, latent_state, horizon, n_candidates):
        # 在隐世界模型中生成候选轨迹（如随机 shooting 或 MPPI）
        trajs = []
        for _ in range(n_candidates):
            traj = self.world_model.rollout(latent_state, horizon)
            trajs.append(traj)
        return torch.stack(trajs)
    
    def compute_energy_anchor(self, trajectories):
        # 利用能量函数为轨迹赋予权重，高价值轨迹能量低
        energy = self.energy_net(trajectories)
        return energy
    
    def diffusion_policy_optimization(self, searched_trajs, num_steps):
        # 将策略优化视为对搜索轨迹的扩散过程
        x = searched_trajs + torch.randn_like(searched_trajs)  # 加噪初始化
        for t in range(num_steps):
            score = self.score_net(x, t, context=latent_state)
            energy_grad = torch.autograd.grad(
                self.energy_net(x).sum(), x, create_graph=True
            )[0]
            # 用能量函数的梯度修正 score field
            x = x + step_size * (score - energy_grad)
        return x  # 优化后的动作序列或轨迹表示
    
    def update(self, batch):
        # 联合更新世界模型、能量函数与扩散 score network
        self.world_model.update(batch)
        self.energy_net.update(batch)
        
        latent = self.world_model.encode(batch['state'])
        trajs = self.search_trajectories(latent, horizon=H, n_candidates=K)
        optimized_trajs = self.diffusion_policy_optimization(trajs, num_steps=T)
        
        # 监督更新 score network，使其匹配优化后的轨迹分布
        self.score_net.update(optimized_trajs, latent)
```

## 第二模块：核心架构解释

本文不引入新的模型架构，而是以 **π₀.₅** 为基座策略，通过标准的监督微调（SFT）结合经验回放（ER）完成持续学习。整体流程可拆解为三个层面：

**1. 基础训练协议**
以负对数似然（NLL）为目标，对每个到达的任务数据 Dₖ 优化策略 π_θ：
$$L_{\rm SFT}=\mathbb{E}_{(\bm{o},\bm{a})\sim\mathcal{D}} \left[ -\log \pi_{\bm{\theta}}(\bm{a} | \bm{o}) \right]$$
优化器为 AdamW，峰值学习率 5×10⁻⁵，warmup 200 步后 cosine decay 至 5×10⁻⁶，batch size 128，EMA decay 0.998，每任务固定训练 4000 有效步。

**2. 经验回放（ER）机制**
- **Buffer 管理**：总容量 **M = B · |Dₖ|**。完成第 k 个任务训练后，将其数据存入 buffer。在训练第 k 个任务时，buffer 内仅包含前 k−1 个任务的数据，且容量均分：每个旧任务保留 **⌊M/(k−1)⌋** 条轨迹（至少 1 条）。
- **采样频率**：每步以概率 **f_r** 从 buffer 中采样旧任务数据，以概率 **1−f_r** 从当前任务采样。为保证当前任务仍有 4000 有效优化步，总训练步数扩展为 **4000 / (1−f_r)**。

**3. 动作归一化策略（关键实现细节）**
- **Strategy-I（默认）**：固定使用第一个任务（Stack Bowl）的动作统计量 **(μ₁, σ₁)** 贯穿整个任务流，确保动作空间坐标系一致。
- **Strategy-II**：每任务使用自身统计量 **(μₖ, σₖ)**，导致同一 batch 内回放数据与当前任务数据的归一化参考不一致，引发动作空间崩溃。

**Python 风格伪代码（核心逻辑）**

```python
class ContinualVLA:
    def __init__(self, B=0.2, f_r=0.2):
        self.B = B               # buffer 容量相对于单任务数据量的比例
        self.f_r = f_r           # 每步从 buffer 采样的概率
        self.buffer = {}         # task_id -> 轨迹列表
        self.norm_stats = None   # Strategy-I: 固定首任务归一化统计量 (mu, sigma)
        self.policy = load_pi05()

    def train_on_task_stream(self, task_datasets):
        # task_datasets: [D1, D2, D3, D4]
        for k, D_k in enumerate(task_datasets, start=1):
            # Strategy-I: 仅在第一个任务时计算并锁定归一化统计量
            if k == 1:
                self.norm_stats = compute_action_stats(D_k)

            # 补偿回放步数，保证当前任务有效训练步为 4000
            total_steps = int(4000 / (1 - self.f_r))

            for step in range(total_steps):
                # 以概率 f_r 从 buffer 采样旧任务，否则从当前任务采样
                if random() < self.f_r and len(self.buffer) > 0:
                    tid = random_choice(list(self.buffer.keys()))
                    batch = sample_batch(self.buffer[tid], batch_size=128)
                else:
                    batch = sample_batch(D_k, batch_size=128)

                # 统一使用首任务统计量进行动作归一化
                batch.actions = (batch.actions - self.norm_stats.mu) / self.norm_stats.sigma

                # 标准 VLA 监督微调损失
                loss = -self.policy.log_prob(batch.observations, batch.instructions, batch.actions).mean()
                loss.backward()
                optimizer.step()

            # 当前任务训练结束后，将其存入 buffer 并在所有已见任务间重新平衡容量
            self._update_buffer(D_k, k)

    def _update_buffer(self, D_k, k):
        M = int(self.B * len(D_k))      # buffer 总容量
        self.buffer[k] = list(D_k)      # 先完整存入当前任务数据
        # 在全部 k 个已见任务间均分容量，每个任务保留上限 floor(M/k)，至少 1 条
        budget_per_task = max(1, M // k)
        for tid in self.buffer:
            self.buffer[tid] = self.buffer[tid][:budget_per_task]
```

## 第二模块：核心架构解释

### 1. 数据构建：FineVLA-Tool 与 FineVLA-Data

整个数据管线分为四阶段，目的是将 10 个开源数据集的 972,247 条异构轨迹转化为 47,159 条带人工验证细粒度标注的代表性轨迹。

- **Stage 1：格式统一与过滤**。将所有轨迹转为 LeRobot 2.1 格式，剔除无效视频。
- **Stage 2：动作-状态规范化**。将不同数据集的动作/状态表示（绝对/相对/增量；关节空间/末端执行器空间；多种旋转编码）统一规范为**绝对坐标 + 归一化四元数（xyzw）**。随后计算动作-状态 DTW 距离，剔除不一致的损坏轨迹。
- **Stage 3：DTW 聚类与代表采样**。对每个任务内的轨迹，基于规范化后的动作序列计算两两 DTW 距离（帧级代价区分关节空间与 EEF 空间，EEF 代价包含位置、四元数测地距离、夹爪状态，其中夹爪权重设为 100.0 以突出关键交互），再进行层次聚类，从每个类簇中选取 2-3 条靠近 medoid 的高质量轨迹。这一步将数据量从 97 万压缩至约 4.7 万，同时保留操作策略的多样性。
- **Stage 4：十维细粒度标注与人工验证**。对每条代表性轨迹，先用 Qwen3.5-Plus 生成步骤化描述，再由人工审核修正。标注覆盖十个控制相关维度：**Action sequence、Active actor、Target object、Initial configuration、Final configuration、Contact & approach、Trajectory & orientation、Object interaction、Failure & recovery、Body motion**。最终数据集平均指令长度从 9.3 词增至 **96.8 词**，信息密度提升约 10.4 倍。

### 2. 基准与可扩展标注器：RoboFine-Bench 与 RoboFine-VLM

- **RoboFine-Bench**：包含严格隔离的 500 条视频（来自 10 个数据集，覆盖 32 种本体），10,816 条原子事实，1,030 道 VQA 题。分两个赛道：

### 3. 策略训练：FineVLA-Policy 与指令混合

作者不提出新架构，而是隔离**语言监督信号**本身的影响。基于 StarVLA 代码库（共享 Qwen3.5-4B 视觉-语言主干），测试两种动作解码框架：

- **StarVLA-OFT**：在预定义 action token 的隐状态上接轻量 MLP，并行回归连续动作块，L1 损失。
- **StarVLA-GR00T**：双系统设计，VL 主干作为 System 2 慢思考，DiT 流匹配模块作为 System 1 生成连续动作。

```python
def train_steerable_vla(fg_dataset, raw_dataset, fg_raw_ratio, policy_arch):
    """
    fg_raw_ratio: tuple (fg_weight, raw_weight), e.g., (1, 1)
    policy_arch: 'OFT' or 'GR00T'
    """
    policy = StarVLA(backbone="Qwen3.5-4B", decoder=policy_arch)
    
    for step in range(PRETRAIN_STEPS + FINETUNE_STEPS):
        # Sample according to FG:Raw mixture probability
        p_fg = fg_raw_ratio[0] / sum(fg_raw_ratio)
        if random() < p_fg:
            batch = sample(fg_dataset)      # fine-grained process-level language
        else:
            batch = sample(raw_dataset)     # raw goal-level language
        
        # Identical trajectory, actions, and observations; ONLY language differs
        obs = batch.observations            # multi-view RGB
        lang = batch.instruction            # FG or Raw
        actions = batch.actions             # continuous action chunk
        
        # Forward pass
        pred_actions = policy(obs, lang)
        
        if policy_arch == 'OFT':
            loss = L1_loss(pred_actions, actions)
        else:  # GR00T
            loss = flow_matching_loss(pred_actions, actions)
        
        update(policy.parameters(), loss)
    
    return policy
```

**推断的方法流程**：

1. **隐世界模型（Latent World Model）**：环境动态被编码至潜在空间，支持状态转移的隐式推演与轨迹 rollout。
2. **轨迹搜索**：在当前隐状态上，通过采样或轻量级搜索（如 MPPI-style shooting）生成一批候选轨迹。
3. **隐式能量函数提取**：从已收集的离线或在线数据中学习一个能量函数，该函数对高价值轨迹赋予低能量，对低价值轨迹赋予高能量，从而锚定策略优化的方向。
4. **扩散策略优化**：不直接参数化策略网络输出动作，而是将策略视为对**搜索轨迹分布**的 score function。通过扩散模型的去噪过程，在潜在空间中逐步优化轨迹表示，使其能量降低、价值提升。
5. **统一对齐**：由于策略改进直接作用于搜索产生的轨迹分布，而非依赖独立的价值函数近似，搜索与策略学习在训练过程中保持一致。

```python
class MBDPO:

        self.world_model = world_model          # 隐世界模型 p(s_{t+1}|s_t,a_t)

            traj = self.world_model.rollout(latent_state, horizon)
            trajs.append(traj)
        return torch.stack(trajs)
    
    def compute_energy_anchor(self, trajectories):
        # 利用能量函数为轨迹赋予权重，高价值轨迹能量低
        energy = self.energy_net(trajectories)
        return energy
    
    def diffusion_policy_optimization(self, searched_trajs, num_steps):
        # 将策略优化视为对搜索轨迹的扩散过程
        x = searched_trajs + torch.randn_like(searched_trajs)  # 加噪初始化
        for t in range(num_steps):
            score = self.score_net(x, t, context=latent_state)
            energy_grad = torch.autograd.grad(
                self.energy_net(x).sum(), x, create_graph=True
            )[0]
            # 用能量函数的梯度修正 score field
            x = x + step_size * (score - energy_grad)
        return x  # 优化后的动作序列或轨迹表示
    
    def update(self, batch):
        # 联合更新世界模型、能量函数与扩散 score network
        self.world_model.update(batch)
        self.energy_net.update(batch)
        
        latent = self.world_model.encode(batch['state'])
        trajs = self.search_trajectories(latent, horizon=H, n_candidates=K)
        optimized_trajs = self.diffusion_policy_optimization(trajs, num_steps=T)
        
        # 监督更新 score network，使其匹配优化后的轨迹分布
        self.score_net.update(optimized_trajs, latent)
```

## 第二模块：核心架构解释

TPS-Drive 将自动驾驶形式化为一个以**净化空间词汇**为中介的解耦三阶段推理过程。

**1. 输入与表示**
在时刻 $t$，系统接收多视图图像 $\mathcal{I}_t$、当前 BEV 特征图 $\mathcal{B}_t \in \mathbb{R}^{D \times H \times W}$、导航指令 $\mathbf{c}$、任务提示 $\mathbf{p}$ 和自车运动学 $\mathbf{k}_t = [\mathbf{v}_t, \mathbf{a}_t]$。目标为输出未来轨迹 $\boldsymbol{\tau}_{t+1:t+T_{\text{plan}}}$。

**2. Agent-Centric Tokenization（核心创新）**
这是实现"表示净化"的关键模块。
- **主码本 $\mathcal{V}_1$：** 编码器 $E_\phi$ 将 $\mathcal{B}$ 压缩为潜在网格 $\mathbf{e} \in \mathbb{R}^{D' \times H' \times W'}$，每个空间位置通过最近邻搜索量化到 $\mathcal{V}_1$（公式 1）：
  $$z_{i,j} = \arg\min_{m} \| \mathbf{e}_{i,j} - \mathbf{v}_m \|_2$$
- **任务引导损失（公式 2）：** 为防止码本被动编码背景，引入**冻结的 CenterPoint3D 检测头**进行监督。总损失为：
  $$\mathcal{L}_{\text{primary}} = \lambda_r \mathcal{L}_{\text{rec}} + \lambda_h \mathcal{L}_{\text{hm}} + \lambda_b \mathcal{L}_{\text{box}} + \mathcal{L}_{\text{vq}} + \beta \mathcal{L}_{\text{commit}}$$
  其中 $\mathcal{L}_{\text{hm}}$ 与 $\mathcal{L}_{\text{box}}$ 为检测头的 heatmap 与 3D bbox 损失，强制码本关注动态智能体；$\lambda_r \mathcal{L}_{\text{rec}}$ 则防止净化特征结构崩溃。
- **残差细化层：** 设置 $L=4$ 层残差码本 $\{\mathcal{V}_\ell\}_{\ell=2}^{L}$，逐层量化前一层残差。最终仅**主 token** $\mathbf{z}^{(1)}$ 输入 VLM 进行自回归预测，残差 token 由轻量分类头并行预测，兼顾序列紧凑性与几何精度。

**3. 解耦推理流程**
- **场景理解（Scene Understanding）：** VLM 从当前观测提取结构化表示 $\mathbf{s}_t$（环境属性 + 物理规则）。训练时使用 Qwen3.5-27B 自动生成标注并经人工校验，以交叉熵损失 $\mathcal{L}_{\text{scene}}$ 监督。
- **未来预测（Future Forecasting）：** 以完整上下文 $\mathbf{x}_t = \{\mathcal{I}_t, \mathcal{B}_t, \mathbf{c}, \mathbf{p}, \mathbf{k}_t, \mathbf{s}_t\}$ 为条件，VLM **自回归预测**未来主 token $\mathbf{z}_{t+\Delta t}^{(1)}$（公式 3 第一项）；同时 $L-1$ 个分类头基于 VLM 隐状态 $\mathbf{h}_{t+\Delta t}$ **并行预测**残差 token（公式 3 第二项）：
  $$\mathcal{L}_{\text{world}} = -\sum_{n=1}^{N} \log p\bigl(z_{t+\Delta t, n}^{(1)} \mid \mathbf{x}_t, \mathbf{z}_{t+\Delta t, <n}^{(1)}\bigr) + \lambda_{\text{res}} \sum_{\ell=2}^{L} \mathcal{L}_{\text{CE}}\bigl(g_\ell(\mathbf{h}_{t+\Delta t}), \mathbf{z}_{t+\Delta t}^{(\ell)}\bigr)$$
- **动作生成（Action Generation）：** 采用条件扩散模型。将预测的未来 token 隐状态 $\mathbf{h}_{t+\Delta t}$、结构化表示 $\mathbf{s}_t$ 与动作起始提示 $\mathbf{p}_{\text{start}}$ 拼接为 $\mathbf{f}_t$，输入去噪 Transformer $\epsilon_\theta$ 估计噪声（公式 4）：
  $$\mathcal{L}_{\text{plan}} = \mathbb{E}_{k, \boldsymbol{\tau}^{0}, \boldsymbol{\epsilon}} \bigl[ \| \boldsymbol{\epsilon} - \epsilon_\theta(\boldsymbol{\tau}^{k}, k, \mathbf{f}_t) \|_2^2 \bigr]$$

**4. 渐进三阶段训练**
- **Stage 1（Tokenizer 预训练）：** 先训练主码本（含检测监督），冻结后训练残差码本。
- **Stage 2（SFT）：** 联合优化 $\mathcal{L}_{\text{scene}} + \mathcal{L}_{\text{world}} + \mathcal{L}_{\text{plan}}$，VLM 与扩散头全量更新。
- **Stage 3（Reward-Driven Refinement）：** 采用**分组相对优化策略**。对每个样本生成多条 rollout，以几何误差与运动平滑度计算离线奖励，组内归一化得到相对优势，无需价值网络。世界模型分支通过优势加权策略目标更新，扩散规划器通过奖励加权去噪损失优化。

**5. 实验流程**
- **nuScenes：** 评估开环轨迹规划（ST-P3 与 UniAD 双协议的 L2/CR）以及智能体空间预测（NDS/mAP 等检测指标）。
- **NAVSIMv1：** 评估闭环 PDMS（NC/DAC/TTC/C/EP）。
- **NAVSIMv2：** 评估严格交互闭环 EPDMS（增加 DDC/TLC/LK/HC/EC 等法规指标）。
- **消融：** 从标准 VQ-VAE 基线逐步叠加 Task-Guided Tokenizer、Residual Layers、Reward-Driven Refinement，量化各组件贡献。

```python
import torch
import torch.nn as nn

class AgentCentricTokenizer(nn.Module):
    def __init__(self):
        self.encoder = Encoder()                     # E_phi
        self.primary_codebook = nn.Embedding(8192, D_prime)   # V_1
        self.residual_codebooks = nn.ModuleList([
            nn.Embedding(K, D_prime) for _ in range(3)       # V_2..V_4, L=4
        ])
        self.decoder = Decoder()                     # D_psi
        self.frozen_detector = CenterPoint3D()       # 冻结 3D 检测头
        self.frozen_detector.eval()
        for p in self.frozen_detector.parameters():
            p.requires_grad = False

    def forward(self, B_t):
        # B_t: [D, H, W]
        e = self.encoder(B_t)  # [D', H', W']
        
        # Primary VQ (Eq.1)
        z1, q1 = vector_quantize(e, self.primary_codebook)
        
        # Residual VQ
        residual = e - q1
        qs, zs = [q1], [z1]
        for codebook in self.residual_codebooks:
            z_l, q_l = vector_quantize(residual, codebook)
            qs.append(q_l)
            zs.append(z_l)
            residual = residual - q_l
        
        B_hat = self.decoder(sum(qs))
        
        # Task-guided loss (Eq.2)
        loss_rec = F.l1_loss(B_hat, B_t)
        det_out = self.frozen_detector(B_hat)        # 检测监督
        loss_hm = heatmap_loss(det_out, gt_boxes)
        loss_box = bbox_loss(det_out, gt_boxes)
        loss_vq = F.mse_loss(e, q1.detach())
        loss_commit = F.mse_loss(e, q1.detach()) * beta  # commitment
        
        loss_primary = (lambda_r * loss_rec + 
                       lambda_h * loss_hm + 
                       lambda_b * loss_box + 
                       loss_vq + beta * loss_commit)
        return zs, qs, loss_primary

        # 2. Scene Understanding

            target_tokens=z_future_prim, 
            context=x_t
        )
        
        loss_res = 0
        for l, head in enumerate(self.residual_heads, start=2):
            pred_z_l = head(h)
            loss_res += F.cross_entropy(pred_z_l, z_future[l])
        loss_world = loss_ar + lambda_res * loss_res
        
        # 4. Action Generation (Eq.4)
        f_t = concat(h, s_t, p_start)
        loss_plan = self.diffusion_planner.denoise_loss(
            f_t=f_t, gt_traj=traj_gt
        )
        
        return loss_scene + loss_world + loss_plan


# ==================== 训练流程 ====================
def train():
```

### 第二模块：核心架构解释

**整体流程**

论文的理论框架由“世界”与“学习者”两部分构成：

1. **世界（World）**：假设存在真实的独立潜在变量 \(z \in \mathbb{R}^n\)，服从标准高斯分布 \(z \sim \mathcal{N}(0, I_n)\)。正样本对通过 Ornstein–Uhlenbeck（OU）平稳转移生成：\(z' = \rho z + \sqrt{1-\rho^2}\,\eta\)，其中 \(\eta \sim \mathcal{N}(0, I_n)\)。随后，一个**未知**的非线性混合函数 \(g\) 将潜在变量渲染为观测数据：\(x = g(z)\)。
2. **学习者（LeJEPA）**：训练一个编码器 \(f\)（或等效地，组合映射 \(h = f \circ g\)），通过两个约束目标进行优化：
   - **对齐（Alignment）**：最小化正样本对在表示空间中的距离 \(\mathbb{E}[\|h(z') - h(z)\|^2]\)。
   - **高斯正则化（SIGReg）**：强制表示分布精确匹配标准高斯 \(h(z) \sim \mathcal{N}(0, I_n)\)。
3. **理论保证**：在满足上述目标的全局最优处，\(h\) 必须是一个正交线性映射 \(h(z) = Qz\)（\(Q \in O(n)\)），即完美恢复潜在结构至多一个全局旋转；且该结论的**逆否**成立——若潜在变量非高斯，则无法保证线性可识别性。
4. **实验验证**：
   - **2D 可控实验**：使用螺旋、正弦剪切、抛物线剪切、RealNVP 四种非线性混合，验证 LeJEPA 将纠缠的观测恢复为旋转后的高斯散点。
   - **高维扩展**：维度从 2 扫描至 1024，比较 SIGReg、VICReg、InfoNCE 的线性恢复能力。
   - **分布消融**：在广义正态分布族（形状参数 \(\alpha\)）中扫描，验证仅在 \(\alpha=2\)（高斯）处出现 \(R^2\) 尖峰。
   - **真实控制**：在 DMC Reacher 的像素输入上，对比人工高斯 OU 数据与真实 RL 轨迹数据的可识别性差异。
   - **近似界限验证**：测量对齐间隙 \(\delta\) 与白化误差 \(\varepsilon\)，验证理论界 \(\mathbb{E}[\|h(z)-Qz\|^2] \leq D + (\varepsilon + D)^2\)。
   - **潜在空间规划**：在学到的潜在空间中进行直线插值规划，验证高斯编码器能达到与 Oracle 几乎一致的控制成本。

```python
import torch
import torch.nn as nn

# ------------------------------------------------------------
# 1. 世界模型：生成高斯潜在变量与 OU 正样本对
# ------------------------------------------------------------
def sample_ou_pair(batch_size, n, rho):
    """
    世界侧：z ~ N(0, I)，通过 OU 转移生成 z'
    z' = rho * z + sqrt(1 - rho^2) * eta
    """
    z = torch.randn(batch_size, n)
    eta = torch.randn(batch_size, n)
    z_prime = rho * z + (1.0 - rho**2)**0.5 * eta
    return z, z_prime

def nonlinear_mix(z):
    """
    未知生成过程 g：将潜在变量非线性混合为观测 x。
    例如：螺旋、剪切、RealNVP 耦合层等。
    """
    # 以螺旋为例：g(z) = R(pi * ||z||) @ z
    angle = 3.14159 * torch.norm(z, dim=1, keepdim=True)
    cos_a, sin_a = torch.cos(angle), torch.sin(angle)
    x = torch.stack([
        cos_a.squeeze() * z[:, 0] - sin_a.squeeze() * z[:, 1],
        sin_a.squeeze() * z[:, 0] + cos_a.squeeze() * z[:, 1]
    ], dim=1)
    return x

# ------------------------------------------------------------
# 2. LeJEPA 学习者：编码器 + 对齐损失 + SIGReg
# ------------------------------------------------------------
class Encoder(nn.Module):
    def __init__(self, obs_dim, latent_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(obs_dim, 256), nn.GELU(),
            nn.Linear(256, 256), nn.GELU(),
            nn.Linear(256, 256), nn.GELU(),
            nn.Linear(256, latent_dim)
        )
    
    def forward(self, x):
        return self.net(x)

def sigreg_loss(y):
    """
    SIGReg：强制批次统计量匹配 N(0, I)。
    实践中可替换为 Sketched Isotropic Gaussian Regularization。
    """
    mean = y.mean(dim=0)
    cov = torch.cov(y.T)
    I = torch.eye(y.shape[1], device=y.device)
    loss_mean = torch.norm(mean, p=2)**2
    loss_cov = torch.norm(cov - I, p='fro')**2
    return loss_mean + loss_cov

def alignment_loss(y, y_prime):
    """对齐损失：拉近正样本对"""
    return ((y_prime - y)**2).sum(dim=1).mean()

def train_lejepa(encoder, g, n, rho, lam=0.1, steps=10000, bs=1024):
    opt = torch.optim.Adam(encoder.parameters(), lr=1e-3)
    for step in range(steps):
        z, z_prime = sample_ou_pair(bs, n, rho)
        x, x_prime = g(z), g(z_prime)
        
        y = encoder(x)
        y_prime = encoder(x_prime)
        
        loss = (1.0 - lam) * alignment_loss(y, y_prime) + lam * sigreg_loss(y)
        opt.zero_grad()
        loss.backward()
        opt.step()
    return encoder

# ------------------------------------------------------------
# 3. 评估：线性可识别性与潜在空间规划
# ------------------------------------------------------------
def linear_identifiability_r2(h_z, z_true):
    """
    计算 R^2(h -> z)：在表示 h_z 上作线性回归预测真实潜在 z_true。
    若 h_z = Q z_true，则 R^2 应接近 1.0。
    """
    # 伪代码：最小二乘求解线性矩阵 W
    W, _, _, _ = torch.linalg.lstsq(h_z, z_true)
    z_pred = h_z @ W
    ss_res = ((z_true - z_pred)**2).sum()
    ss_tot = ((z_true - z_true.mean(dim=0))**2).sum()
    r2 = 1.0 - ss_res / ss_tot
    return r2.item()

def latent_space_planning(encoder, g, start_z, goal_z, steps=50):
    """
    在潜在空间做直线插值规划，验证 Thm. 5（最优规划）。
    """
    with torch.no_grad():
        start_h = encoder(g(start_z))
        goal_h = encoder(g(goal_z))
        # 潜在空间直线插值
        alphas = torch.linspace(0, 1, steps).view(-1, 1)
        plan_h = alphas * goal_h + (1 - alphas) * start_h
    return plan_h
```

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 作者的核心解决方案是一个**双向的数学刻画**：
- **前向定理（Thm. 1）**：在潜在变量服从高斯分布、且演化遵循平稳加性噪声（OU 过程）的世界中，LeJEPA 的对齐损失加 SIGReg 高斯正则化的全局最优解，必然是一个正交线性映射 \(h(z) = Qz\)。证明的关键在于利用 Hermite 多项式谱分解，展示对齐损失对非线性分量（Hermite 阶数 \(d \geq 2\)）按 \(\rho^d\) 严格惩罚，从而线性分量是唯一最大化相关性的解。
- **反向定理（Thm. 2）**：在上述世界模型类中，如果要求所有最优解都是线性的，则潜在变量分布**必须是**高斯。证明通过 Sturm–Liouville 理论，指出线性可识别性要求转移算子的第一非恒定特征函数为仿射，这唯一强制了高斯分布。
- **近似稳定性（Thm. 3）**：当对齐与白化仅近似满足时，恢复误差被显式界定为 \(\mathbb{E}[\|h(z)-Qz\|^2] \leq D + (\varepsilon + D)^2\)，其中 \(D\) 由对齐间隙 \(\delta\) 决定。
- **规划等价性（Thm. 4）**：证明线性正交可识别性足以保证在潜在空间中进行的最优控制（在正交不变成本下）与在真实潜在空间中的规划完全等价。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

## 第二模块：核心架构解释

### 1. 整体框架：两阶段记忆流水线

POLAR 将长期个性化具身任务形式化为 POMDP，核心是一个**记忆构建（Memorization）**与**记忆使用（Utilization）**的两阶段流水线：

- **Memorization：** 将先前交互 episodes $E_{<k}$ 转化为多模态知识图谱 $\mathcal{M} = (\mathcal{V}, \mathcal{E})$。
- **Utilization：** 给定当前指令 $\mathcal{I}_k$，从 $\mathcal{M}$ 中检索相关记忆子集 $\mathcal{R}_k$，供 MLLM 策略 $\pi$ 进行目标推理与动作规划：$a_t = \pi(\tau_t, \mathcal{I}_k, \mathcal{R}_k)$。

### 2. 记忆表示：多模态知识图谱

图谱节点 $\mathcal{V}$ 包含三类：

- **对象节点：** 以唯一对象 ID 标识，通过参考图像视觉相似度或 ID 匹配进行链接。
- **语义记忆节点：** 将交互重构为关于该对象的**简洁文本陈述**，每条陈述仅保留**单一**用户特定属性（如“这双鞋是用户跑步时穿的”）。对象 $o_i$ 对应陈述集 $\{s_{i,1}, \dots, s_{i,K_i}\}$。这种细粒度解耦避免了多属性纠缠导致的检索噪声。
- **情景记忆节点：** 将完整轨迹压缩为紧凑文本 $p_i$，仅保留**规划相关信息**（成功/失败、哪些房间无希望、哪些观察/转移具有信息量）。

**图谱构建与更新逻辑：**
- 边带**时间戳**，支持时序更新与近期性检索。
- 若新生成语义记忆与现有节点足够相似，则直接链接到现有节点而非创建重复节点。
- 若对象视觉相似或 ID 匹配，则挂载到现有对象节点；否则新建对象节点。

### 3. 记忆检索与任务执行

给定指令 $\mathcal{I}$，执行以下检索：

1. 使用 **BGE-M3** 编码器计算 $\mathrm{sim}(\mathcal{I}, s) = \phi(\mathcal{I}) \cdot \phi(s)$。
2. 检索 top-$k$（$k=5$）语义记忆节点。
3. 沿图边找到对应的对象节点 $z_j$，收集其关联的指令与情景记忆 $p_j$。
4. MLLM 对候选对象进行推理，完成**目标定位**，并基于 $p_j$ 指导后续**导航规划**。

### 4. MLLM 具身智能体架构

采用**分层规划**：

- **高层规划：** 预遍历环境构建场景图 $\mathcal{G}$（房间为节点，邻接关系为边），每个节点包含一个可导航 waypoint。基于全局空间结构推理，生成向最可能包含目标房间的移动指令。
- **低层规划：** 接收 egocentric 视觉输入（前、左、右三视图）、自然语言指令及可选参考图像，选择下一移动方向（\texttt{MOVE FORWARD}、\texttt{TURN LEFT}、\texttt{TURN RIGHT}），检测到目标则执行 \texttt{STOP}。
- **控制器：** 在 Habitat 模拟器中执行原语动作（前进 1 米，转向 30 度）。

### 5. 实验流程

- **数据集：** 基于 PinNED（Habitat-Matterport3D），4 个场景，1,817 个 episode。使用 GPT-5 生成个性化上下文，经人工筛选与 MTurk 质量验证。
- **两阶段协议：**
  - **Acquisition Stage：** 执行**显式**个性化指令（包含直接目标引用），积累用户-智能体交互历史。
  - **Evaluation Stage：** 执行**隐式**评估指令（无直接引用，需从历史推断目标）。两阶段改变对象位置与智能体初始位置，防止直接复用轨迹。
- **评估场景：**
  - **Compositional Single：** 目标可从单一先前 episode 推断。
  - **Compositional Joint：** 需组合 2–3 个先前 episode 的信息进行多跳推理。
  - **Distractor：** 环境中存在多个同类候选对象，测试实例级区分能力。
  - **Temporal：** 测试时序变化（对象属性演变或同一上下文指向不同对象），要求智能体依赖最新有效交互。
- **Backbone：** Qwen3-VL-8B-Instruct、Qwen2.5-VL-8B-Instruct、GPT-5、GPT-4o-mini、Gemini-2.5-Flash。
- **基线：**
  - **no-prior：** 仅使用当前指令与观察。
  - **raw-interaction：** 随机采样 15 个先前交互（包含 gold interaction）直接输入上下文。
- **指标：** SR（成功率，距目标 < 2 米）、SPL（路径效率加权成功率）、CM（Category Match，同类错误定位数）。

```python
class MemoryGraph:
    def __init__(self):
        self.object_nodes = {}      # obj_id -> ObjectNode
        self.semantic_nodes = []    # list of SemanticNode
        self.episodic_nodes = []    # list of EpisodicNode
        self.edges = []             # (src, dst, timestamp)

    def get_or_create_object(self, obj_id, ref_image):
        if obj_id not in self.object_nodes:
            # Link by visual similarity if ID not found
            for oid, node in self.object_nodes.items():
                if visual_similarity(node.ref_image, ref_image) > 0.9:
                    return node
            self.object_nodes[obj_id] = ObjectNode(obj_id, ref_image)
        return self.object_nodes[obj_id]

    def add_semantic(self, text, timestamp):
        node = SemanticNode(text, timestamp)
        self.semantic_nodes.append(node)
        return node

    def add_episodic(self, text, timestamp):
        node = EpisodicNode(text, timestamp)
        self.episodic_nodes.append(node)
        return node

    def add_edge(self, src, dst, timestamp):
        self.edges.append((src, dst, timestamp))

    def find_similar_semantic(self, obj_node, new_text, threshold=0.95):
        # Deduplication: link to existing if embedding similarity high
        new_emb = encoder.encode(new_text)
        for sem in obj_node.semantic_neighbors:
            if cosine_similarity(new_emb, sem.embedding) > threshold:
                return sem
        return None


class POLAR:
    def __init__(self, vlm_policy, encoder):
        self.memory = MemoryGraph()
        self.policy = vlm_policy   # Hierarchical MLLM agent
        self.encoder = encoder     # BGE-M3

    # ---------- Memorization Stage ----------
    def build_memory(self, prior_episodes):
        for ep in prior_episodes:
            # 1. Object node linking
            obj_node = self.memory.get_or_create_object(
                ep.object_id, ep.ref_image
            )

            # 2. Semantic memory: fine-grained statements
            semantic_statements = self.policy.summarize(
                context=ep.instruction,
                prompt="Extract concise object-specific personalized statements, one attribute per sentence."
            )
            for stmt in semantic_statements:
                existing = self.memory.find_similar_semantic(obj_node, stmt)
                if existing:
                    self.memory.add_edge(obj_node, existing, ep.timestamp)
                else:
                    sem_node = self.memory.add_semantic(stmt, ep.timestamp)
                    self.memory.add_edge(obj_node, sem_node, ep.timestamp)

            # 3. Episodic memory: planning-relevant trajectory summary
            episodic_text = self.policy.summarize(
                context=ep.trajectory,
                prompt="Summarize planning experience: success/failure, unfruitful rooms, informative observations."
            )
            ep_node = self.memory.add_episodic(episodic_text, ep.timestamp)
            self.memory.add_edge(obj_node, ep_node, ep.timestamp)

    # ---------- Utilization Stage ----------
    def retrieve_memory(self, instruction, k=5):
        q_emb = self.encoder.encode(instruction)
        scores = []
        for sem_node in self.memory.semantic_nodes:
            score = cosine_similarity(q_emb, sem_node.embedding)
            scores.append((score, sem_node))
        scores.sort(reverse=True)
        top_k = scores[:k]

        retrieved_context = []
        for _, sem_node in top_k:
            # Traverse to object node
            obj_node = sem_node.linked_object
            # Gather associated episodic memory
            episodic = obj_node.get_latest_episodic()
            retrieved_context.append({
                "object_id": obj_node.obj_id,
                "semantic": sem_node.text,
                "episodic": episodic.text if episodic else None
            })
        return retrieved_context

    # ---------- Execution ----------
    def act(self, obs, instruction):
        mem_context = self.retrieve_memory(instruction, k=5)
        # Hierarchical planning with memory conditioning
        action = self.policy.plan(
            observation=obs,
            instruction=instruction,
            memory=mem_context
        )
        return action
```

A1: 论文试图解决长期用户交互中，具身智能体如何利用累积的、隐式的个性化上下文来定位用户意图的特定对象实例，并避免直接堆砌原始交互记录带来的噪声与上下文限制问题。具体而言，当用户指令未显式指定目标（如只说“拿鞋”而非“拿我的红色跑鞋”）且环境中存在多个同类实例时，智能体必须从历史交互中推断个性化意图，而现有 MLLM 要么无法处理长上下文，要么被非结构化历史淹没。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 作者提出 POLAR 框架，其核心创新是将非结构化的历史交互转化为结构化的多模态知识图谱记忆。该记忆显式分离为两类：语义记忆（将交互重构为对象级别的细粒度文本陈述，用于个性化属性检索）和情景记忆（将轨迹压缩为规划相关的经验文本，用于后续导航规划）。在执行时，通过 BGE-M3 编码器基于指令相似度检索候选对象记忆，由 MLLM 完成目标推理与分层规划。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

A3: 实验基于 PinNED 数据集构建了三种针对性评估场景：Compositional（测试单/多 episode 信息组合推理）、Distractor（测试同类实例干扰下的精确区分）、Temporal（测试时序变化与上下文更新追踪）。此外，实验采用 acquisition/evaluation 两阶段分离设计：先执行显式指令积累交互，再执行隐式指令评估，且两阶段改变对象位置与智能体初始位置，防止智能体直接复用轨迹而非真正推理个性化上下文。

Q4: 这篇论文最显著的贡献点（Top 3）是什么？

A4:

- 提出 POLAR 多模态记忆增强框架，首次系统地将长期交互历史组织为对象中心的知识图谱，将“原始交互记录”转化为“可检索复用的个性化知识”。

- 显式解构并验证了语义记忆与情景记忆在具身个性化中的互补作用：前者支撑细粒度目标检索，后者支撑规划经验复用。

- 在多个 MLLM backbone（开源与闭源）和多样化场景下实证了结构化记忆对长期个性化的必要性，并揭示了直接输入原始交互的不稳定性与局限性。

Q5: 这项工作在哪些相关研究的基础上做了推进？（列举1-2个最核心的前置工作即可）

A5:

- **PinNED** (Barsellotti et al., 2024)：提供了个性化实例定位的基准数据集与显式/隐式指令设定，本文直接基于此构建长期交互评估协议。

- **MLLM-based embodied agents** (如 NavBench / Qiao et al., 2026; EmbodiedBench / Yang et al., 2025)：提供了分层规划（高层场景图 + 低层 egocentric 控制）的 MLLM 具身智能体基线架构，本文在此基础上外挂记忆模块并验证其增益。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

A6: 局限性包括：实验仅验证于导航任务，未触及操作（manipulation）或更复杂的物理交互，记忆泛化到多模态动作空间的潜力未明；记忆构建完全依赖 MLLM 的总结能力，若生成错误语义陈述将直接污染知识图谱，但论文未量化此类错误传播风险；GPT-4o-mini 在 Temporal 场景下 POLAR 表现略逊于 raw-interaction，且部分 SPL 指标（如 Qwen2.5-VL-8B 的 Compositional Joint）出现下降，说明记忆结构化对强模型或路径效率的影响机制论文未充分解释。对后续科研的启发在于：未来可探索端到端可训练的记忆更新与遗忘机制（而非外挂式 RAG）、将记忆模块与 VLA 模型联合训练以实现更紧耦合的个性化推理，以及研究开放域持续学习中记忆冲突消解与动态图谱演化问题。
