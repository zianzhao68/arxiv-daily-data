### 1. LARA: Latent Action Representation Alignment for Vision-Language-Action Models

Code Academic 🟢 Code 🔥 Hot | Score: 4.45/5.0

> 联合优化LAM与VLA表示对齐的即插即用框架

**Authors**: Mengya Liu, Baoxiong Jia, Jiangyong Huang, Jingze Zhang, Siyuan Huang
**Affiliation**: BIGAI, Peking University (Tier 2)
**Links**: [arXiv](http://arxiv.org/abs/2606.07100v1) | [PDF](https://arxiv.org/pdf/2606.07100v1) | [中文翻译](https://hjfy.top/arxiv/2606.07100) | [图文精读](../rich_readings/2026-06-08/2606.07100/README.md) | [Code](https://github.com/lmy1001/LARA)

视觉-语言-动作（VLA）模型虽能直接从观测与语言指令预测机器人动作，但其性能高度依赖大规模高质量标注数据，而真实机器人动作数据稀缺且成本高昂。现有研究利用潜在动作模型（LAM）从无标注视频中学习视觉动态的潜在表示，为VLA提供额外监督。然而，LAM与VLA通常分阶段独立训练：LAM在VLA训练期间保持冻结，导致其缺乏真实动作轨迹的grounding，容易学习到背景、光照等与控制无关的虚假视觉变化；同时VLA也被限制在固定的LAM表示中，无法利用前向动态先验来约束动作生成。

为此，本文提出Latent Action Representation Alignment（LARA），一种轻量且即插即用的联合优化框架。LARA将LAM的连续潜在动作与基于扩散的VLA策略（DiT）中间层隐藏状态通过可学习的投影头进行余弦相似度对齐，联合优化目标为动作流匹配损失、LARA对齐损失与LAM重构损失。该机制产生双向正则化效应：一方面，LAM在动作轨迹监督下抑制非因果视觉干扰，学习更专注于末端执行器与交互目标的逆动态表示；另一方面，VLA通过LAM蕴含的前向动态先验，减少物理上不可行或功能无效的动作轨迹幻觉。LARA兼容预训练从头训练、预训练VLA后训练增强、以及LAM精炼三种应用范式。

实验在LIBERO（4个子集）、SIMPLER-ENV（3类任务）、GR1-Sim-24及Unitree G1真机（双臂抓取-倾倒等复合任务）上展开。在OXE数据受限设置下，完整LARA在LIBERO平均达到88.6%（较DiT-only提升5.0%），在SIMPLER-ENV平均达到65.2%（提升16.8%），并超越Moto-GPT、LAPA等同类方法。作为后训练模块应用于GR00T-N1.6时，在LIBERO平均提升0.6%，在G1真机任务平均提升5.56%；应用于π0.5同样在LIBERO平均提升0.9%。此外，将LARA精炼后的LAM（LARA-LAM）作为伪标签用于Moto-GPT训练，在SIMPLER-ENV上较vanilla LAM平均提升15.7%，注意力可视化也显示其更聚焦于任务相关区域。

LARA的意义在于以极低的架构改动代价，首次实现了世界模型（LAM）与策略（VLA）在表示层面的端到端联合演化。这不仅缓解了机器人数据瓶颈，还通过注入物理动态先验显著提升了策略的泛化性与物理一致性。其即插即用特性使得现有大规模预训练VLA模型（如GR00T-N1.6、π0.5）无需重新预训练即可获得稳定增益，为利用互联网规模无标注视频进行通用机器人学习提供了高效且可扩展的技术路线。

### 第二模块：核心架构解释

**1. LAM（Latent Action Model）架构**

LAM 采用类 Moto-GPT 的 VQ-VAE 结构，负责从视觉动态中提取潜在动作：

- **视觉编码**：使用**冻结的预训练 ViT** 分别编码当前帧 \(I_t\) 与未来帧 \(I_{t+C}\)，将得到的 patch embedding 拼接为统一视觉特征序列。
- **运动提取（M-Former）**：4 层 Transformer Encoder 配备 8 个可学习 query，通过自注意力将视觉变化蒸馏为连续潜在动作表示 \(z_t\)。
- **量化**：采用 VQ 码本（词汇量 128）将 \(z_t\) 离散化为 \(z_t^q\)。
- **重建**：12 层 ViT 解码器（隐藏维度 768）以 \(I_t\) 和 \(z_t^q\) 为条件重建未来帧 \(\hat{I}_{t+C}\)。
- **训练目标**：标准 VQ-VAE 损失 \(\mathcal{L}_{\text{LAM}}\)，包含重建损失、stop-gradient 码本损失与 commitment 损失。

**2. 扩散 VLA 架构**

VLA 采用基于流匹配（Flow Matching）的扩散策略：

- **视觉-语言编码**：冻结的 Eagle-2 VLM 提取任务相关的视觉-语言 token，经可学习的自注意力 Adapter 精炼。
- **状态与动作编码**：针对异构机器人 embodiment，使用独立的 MLP 编码器将本体状态 \(s_t\) 和加噪动作 \(A_t^\tau\) 投影到共享嵌入空间。
- **DiT 去噪网络**：16 层 Diffusion Transformer，交替执行自注意力与交叉注意力（条件为 VLM 输出），预测速度场 \(v_\theta\)。
- **动作生成**：通过流匹配从噪声积分得到动作块 \(A_{t:t+C}\)。

**3. LARA 对齐机制**

LARA 的核心是将 LAM 与 VLA 通过表示对齐进行联合优化：

- **特征提取**：将 DiT 视为编码器-解码器结构 \(E_\theta \circ D_\theta\)。在 DiT 的第 **L-2 层**（倒数第二层）提取中间隐藏状态 \(h_t^\theta\)。论文特别指出，选取对应动作块**最终时间步**（\(t+C\)）的 hidden token 进行对齐，以强制策略对完整动作轨迹的表示与 LAM 预测的视觉效应匹配。
- **对齐损失**：计算 LAM 的**连续潜在动作** \(z_t\)（量化前）与投影后的 DiT 特征之间的余弦相似度：
  \[
  \mathcal{L}_{\text{LARA}} = -\mathbb{E}\left[\texttt{CosSim}\left(z_t,\; f_\psi(h_t^\theta)\right)\right]
  \]
  其中 \(f_\psi\) 为可学习的投影头。
- **联合目标**：
  \[
  \mathcal{L} = \mathcal{L}_{\text{ACT}} + w_1 \mathcal{L}_{\text{LARA}} + w_2 \mathcal{L}_{\text{LAM}}
  \]
  默认 \(w_1=0.01,\; w_2=0.01\)。

**4. 三阶段训练流程**

- **阶段 1（LAM 预训练）**：在 OXE 子集的无标签视频上训练 LAM，时域跨度 \(C=5\)，步数 350k。
- **阶段 2（LARA 联合预训练）**：加载阶段 1 的 LAM，在带动作标签的机器人数据上联合训练 DiT 与 LAM，时域跨度 \(C=16\) 以匹配动作块长度，步数 200k。
- **阶段 3（LARA 联合后训练）**：在目标任务数据上微调全部参数。

import torch
import torch.nn as nn
import torch.nn.functional as F

# -----------------------
# 模块定义
# -----------------------
class LAM(nn.Module):
    def __init__(self):
        super().__init__()
        self.vit_encoder = load_pretrained_vit(frozen=True)
        self.mformer = MFormer(num_layers=4, num_queries=8)
        self.vq = VectorQuantize(codebook_size=128)
        self.vit_decoder = ViTDecoder(num_layers=12, hidden_size=768)
    
    def forward(self, I_t, I_tC):
        # I_t, I_tC: [B, 3, H, W]
        feat_t = self.vit_encoder(I_t)
        feat_tC = self.vit_encoder(I_tC)
        visual_feat = torch.cat([feat_t, feat_tC], dim=1)  # 拼接 patch tokens
        
        z_t = self.mformer(visual_feat)          # [B, D] 连续潜在动作
        z_t_q, indices = self.vq(z_t)            # 量化
        I_hat_tC = self.vit_decoder(I_t, z_t_q)  # 重建未来帧
        return z_t, z_t_q, I_hat_tC

class DiT_VLA(nn.Module):
    def __init__(self, num_layers=16, align_layer=14):  # L=16, L-2=14
        super().__init__()
        self.vlm = load_eagle2_vlm(frozen=True)
        self.adapter = SelfAttentionAdapter()
        self.state_encoder = MLPEncoder()
        self.action_encoder = MLPEncoder()
        self.dit_blocks = nn.ModuleList([DiTBlock() for _ in range(num_layers)])
        self.action_head = nn.Linear(hidden_dim, action_dim)
        self.align_layer = align_layer
    
    def forward(self, A_tau, condition):
        # A_tau: [B, C, action_dim] 加噪动作块
        # condition 包含 VLM 特征与本体状态
        h = self.embed(A_tau, condition)
        h_align = None
        for i, block in enumerate(self.dit_blocks):
            h = block(h, condition)
            if i == self.align_layer:
                h_align = h  # 提取 L-2 层特征
        v_pred = self.action_head(h)
        return v_pred, h_align

# -----------------------
# LARA 联合训练步骤
# -----------------------
def lara_train_step(batch, lam, vla, proj_head, optim, w1=0.01, w2=0.01):
    I_t, I_tC, A_chunk, instruction, proprio = batch
    B, C, _ = A_chunk.shape
    
    # --- LAM 前向 ---
    z_t, z_t_q, I_hat_tC = lam(I_t, I_tC)  # z_t: [B, D_z]
    
    # --- VLA 条件构造 ---
    vl_feat = vla.vlm(I_t, instruction)
    vl_feat = vla.adapter(vl_feat)
    condition = {
        'vl': vl_feat,
        'state': vla.state_encoder(proprio)
    }
    
    # --- 流匹配前向 ---
    tau = torch.rand(B, 1, 1)
    epsilon = torch.randn_like(A_chunk)
    A_tau = tau * A_chunk + (1 - tau) * epsilon
    
    v_pred, h_align = vla(A_tau, condition)
    # h_align: [B, C, D_h] ; 取最终时间步 token 对应动作块末端
    h_target = h_align[:, -1, :]             # [B, D_h]
    z_proj = proj_head(h_target)             # [B, D_z]
    
    # --- 损失计算 ---
    loss_act = F.mse_loss(v_pred, A_chunk - epsilon)
    loss_lam = F.mse_loss(I_hat_tC, I_tC) + vq_commitment_loss(z_t, z_t_q)
    loss_lara = -F.cosine_similarity(z_t, z_proj, dim=-1).mean()
    
    loss = loss_act + w1 * loss_lara + w2 * loss_lam
    
    # --- 反向传播与更新 ---
    optim.zero_grad()
    loss.backward()
    optim.step()
    
    return {
        'loss': loss.item(),
        'loss_act': loss_act.item(),
        'loss_lara': loss_lara.item(),
        'loss_lam': loss_lam.item()
    }
```

### 第三模块：核心学术问答

Q1: 这篇论文试图解决什么核心问题？

A1: 论文试图解决 LAM（Latent Action Model）与 VLA（Vision-Language-Action）模型训练脱节的核心问题。现有范式通常将 LAM 作为静态的伪标签提供者或预训练权重，导致两个直接后果：第一，LAM 仅通过视觉重建学习，缺乏真实动作轨迹的 grounding，容易编码光照、阴影、背景等与控制无关的虚假视觉变化；第二，VLA 策略受限于冻结的 LAM 表示，且行为克隆本身缺乏对动作物理后果的显式建模，容易产生运动学合理但功能无效的动作轨迹幻觉。

当前视觉-语言-动作（VLA）模型在骨干网络、训练数据与策略上快速迭代，但其动作解码器——负责将隐藏状态映射为连续控制信号——却长期停滞，普遍采用单点预测范式（如L1回归、自回归分桶或流匹配去噪）。这类解码器将动作空间视为无结构向量，忽略了相邻动作在几何与物理上的邻近性，导致训练信号稀疏、数据效率低下，且难以捕捉多模态示教中的分布信息，从而限制了末端执行器的定位精度与策略收敛速度。

本文提出ActionMap，一种即插即用的体素热力图动作头，可直接替换现有VLA的原生解码器而无需改动骨干网络。该方法将7维动作分解为平移、旋转与夹爪三个分支，在离散化的三维体素网格上显式预测动作概率分布；训练时以ground-truth为中心生成高斯blob软标签，通过交叉熵进行监督；推理时采用top-k soft-argmax从热力图中恢复连续动作值。这种“空间结构化分类”替代了传统的单点回归，使得模型在训练阶段即可利用动作空间的局部几何结构，并兼容不同架构的VLA骨干。

实验在LIBERO仿真四套件与真实Franka机器人三项操作任务上开展。在相同训练步数下，ActionMap将OpenVLA-OFT的四套件平均成功率提升8.2%（其中Long套件提升26.6%），将π0.5提升1.6%；在仅使用10%训练数据的低数据场景下，相比OpenVLA-OFT提升26.0%，且收敛速度显著加快。在真实世界实验中，ActionMap在完整数据下以20/30对7/30全胜OpenVLA-OFT，抓取定位误差缩小2–3倍，展现出更强的空间精度与数据效率。

该研究表明，动作表示本身是VLA性能的一个独立优化杠杆，而非仅依赖骨干网络或数据规模的持续扩张。其跨骨干的一致性增益验证了结构化动作监督的普适价值。此外，论文明确展望了将该热力图动作头与世界动作模型（World Action Models）结合的方向——在保留视频预测分支的同时，用空间分布式的动作输出替代单点预测，这为世界模型辅助的机器人控制与sim-to-real迁移提供了可直接落地的架构升级路径。

## 第二模块：核心架构解释

### 模型架构与流程

ActionMap 是一个**即插即用（drop-in）的 action head**，直接替换现有 VLA 的原始动作解码器，而保留 backbone、视觉-语言编码器、注意力机制及训练配方不变。

**1. 输入与主干**
- VLA backbone（如 OpenVLA-OFT 或 π0.5）处理视觉观测与语言指令，输出对应于动作 token 位置的最后一层隐状态 **h**。
- 现代 VLA 通常一次前向传播输出 **T** 个动作（chunked prediction），head 需并行读取这 **T** 个 action-token 隐状态。

**2. ActionMap Head 结构**
- 共享的 MLP trunk（含残差连接）接收隐状态 **h**。
- 三分支并行输出：
  - **Translation head**：输出 logits，reshape 为 **N_x × N_y × N_z** 的 3D grid。
  - **Rotation head**：输出 logits，reshape 为 **N_φ × N_θ × N_ψ** 的 3D grid。
  - **Gripper head**：输出 2 个 logits（binary open/close）。
- 每个体素直接存储对应动作取值的概率质量，即 **Pr(x,y,z)** 与 **Pr(φ,θ,ψ)**。

**3. 训练：软标签监督**
- 对每一维动作分量，将 ground-truth 动作坐标映射到对应体素网格位置。
- 构建以该坐标为中心的 **Gaussian blob** 目标分布（softmax 归一化），标准差为 σ：
  - 邻近体素获得非零软标签，显式编码动作空间几何邻近性。
- 损失函数为预测 softmax 分布与 Gaussian blob 目标之间的**交叉熵**，三分支求和，并对 **T** 个 chunk slot 求和。

**4. 推理：Top-k Soft-Argmax 解码**
- Translation 与 Rotation：对 grid logits 取 top-k（默认 k=10），经 temperature softmax 后做概率加权平均，恢复连续动作值。
- Gripper：直接对 2 个 bin 取 argmax。
- 该解码方式可微且比硬 argmax 更稳定。

### 实验流程

- **LIBERO 模拟**：在四个套件（Spatial, Object, Goal, Long）上评估。OpenVLA-OFT 使用 LoRA（rank 32）微调 10K 步；π0.5 遵循原 recipe 训练 30K 步。数据效率实验在 LIBERO-Spatial 上取 10%、25%、50% 分层子集。
- **真实世界 Franka**：三项任务（Pick, Sweep, Insert），对比 full data 与 50-episode 低数据场景。除 action head 外，所有超参、优化器、相机输入、训练步数均与基线严格一致。额外测量 Pick 任务 grasp 时刻的末端执行器定位误差（mm）。

import torch
import torch.nn as nn
import torch.nn.functional as F

class ActionMapHead(nn.Module):
    def __init__(self, hidden_dim, trans_grid=(48,48,24), rot_grid=(24,24,24), grip_bins=2):
        super().__init__()
        self.trans_grid = trans_grid
        self.rot_grid = rot_grid
        
        # Shared trunk
        self.trunk = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
        )
        
        # Three parallel branches
        self.trans_head = nn.Linear(hidden_dim, trans_grid[0]*trans_grid[1]*trans_grid[2])
        self.rot_head   = nn.Linear(hidden_dim, rot_grid[0]*rot_grid[1]*rot_grid[2])
        self.grip_head  = nn.Linear(hidden_dim, grip_bins)
        
    def forward(self, h):
        # h: (B, T, hidden_dim)
        x = self.trunk(h)
        trans_logits = self.trans_head(x).view(-1, *self.trans_grid)   # (B*T, Nx, Ny, Nz)
        rot_logits   = self.rot_head(x).view(-1, *self.rot_grid)       # (B*T, Nphi, Ntheta, Npsi)
        grip_logits  = self.grip_head(x)                               # (B*T, 2)
        return trans_logits, rot_logits, grip_logits

def gaussian_blob_target(gt_action, bin_centers, sigma):
    """
    gt_action: (..., D)  ground-truth continuous action
    bin_centers: (G, D)  grid bin centers
    sigma: scalar
    Returns: (G,) softmax-normalized target distribution
    """
    dist_sq = torch.sum((bin_centers - gt_action.unsqueeze(-2)) ** 2, dim=-1)
    logits = -dist_sq / (2 * sigma ** 2)
    target = F.softmax(logits, dim=-1)
    return target

def actionmap_loss(trans_logits, rot_logits, grip_logits, 
                   gt_trans, gt_rot, gt_grip, 
                   trans_bins, rot_bins, sigma):
    # Flatten grids for cross-entropy
    B = trans_logits.size(0)
    trans_pred = F.log_softmax(trans_logits.view(B, -1), dim=-1)  # (B, Nx*Ny*Nz)
    rot_pred   = F.log_softmax(rot_logits.view(B, -1), dim=-1)      # (B, Nphi*Ntheta*Npsi)
    grip_pred  = F.log_softmax(grip_logits, dim=-1)               # (B, 2)
    
    # Build soft targets
    trans_target = gaussian_blob_target(gt_trans, trans_bins, sigma)  # (B, Nx*Ny*Nz)
    rot_target   = gaussian_blob_target(gt_rot, rot_bins, sigma)      # (B, Nphi*Ntheta*Npsi)
    grip_target  = F.one_hot(gt_grip.long(), num_classes=2).float()   # (B, 2)
    
    # Cross-entropy (soft labels)
    loss_trans = -(trans_target * trans_pred).sum(dim=-1).mean()
    loss_rot   = -(rot_target * rot_pred).sum(dim=-1).mean()
    loss_grip  = -(grip_target * grip_pred).sum(dim=-1).mean()
    
    return loss_trans + loss_rot + loss_grip

def topk_soft_argmax(logits, bin_centers, k=10, temperature=1.0):
    """
    logits: (B, G)  or  (B, Nx, Ny, Nz)
    bin_centers: (G, D)
    """
    B = logits.size(0)
    logits_flat = logits.view(B, -1)
    probs = F.softmax(logits_flat / temperature, dim=-1)
    
    # Select top-k
    topk_probs, topk_idx = torch.topk(probs, k, dim=-1)  # (B, k)
    topk_probs = topk_probs / topk_probs.sum(dim=-1, keepdim=True)
    topk_bins = bin_centers[topk_idx]                      # (B, k, D)
    
    action = (topk_probs.unsqueeze(-1) * topk_bins).sum(dim=1)  # (B, D)
    return action
```

单体式视觉-动作（VLA）模型正成为自动驾驶的新范式，但在编码扩展时间上下文以处理复杂交互时，视觉token序列长度迅速膨胀，超出实时计算预算。现有压缩方法多采用基于规则的时间衰减等启发式策略，与规划目标解耦，容易丢失对决策至关重要的历史信息（如四向停车让行中的到达顺序）。本文针对这一关键空白，提出了一种与规划对齐的压缩框架，使记忆保留由下游驾驶任务驱动。

本文提出COMPACT-VA，一种基于条件VQ-VAE的规划对齐工作记忆框架。该方法通过Q-former对多视角观测进行分层压缩，将历史上下文压缩为有限表示。压缩过程以历史轨迹和从未来轨迹蒸馏出的驾驶意图为条件：后验编码器在训练时从未来轨迹提取意图，先验编码器仅从压缩观测中预测该意图。压缩记忆与预测的离散技能嵌入拼接后输入策略网络，实现端到端优化。若压缩丢弃了决策关键信息，先验将无法准确预测意图，从而通过KL散度与轨迹损失联合驱动模型保留关键历史线索。

实验聚焦于高信号动态场景（四向停车、动态遮挡、无保护转弯），设计了行为正确性指标（停/走成功率、滑行通过率、停车位置/时长误差）。在同等token预算下（1424 tokens），COMPACT-VA的Go成功率达68.3%，较基线提升超过6%，较无规划对齐的压缩提升2.7%；停车成功率89.2%，滑行率降低22%。消融实验验证了分层压缩、历史条件与规划耦合各组件的有效性。闭环评估表明，该方法在保持一般驾驶能力的同时，实现3.3倍推理加速与2.7倍显存降低。

该工作首次将token压缩质量与规划性能通过变分目标显式耦合，为VLA策略提供了可学习的、有界的工作记忆机制。其意义在于：不仅解决了长上下文带来的计算瓶颈，更证明了任务感知的记忆压缩对物理智能体决策的关键作用。方法兼容现有VLA架构无需修改主干，具备良好的部署实用性，并对机器人、自动驾驶等需长时记忆与快速推理的具身智能领域具有重要借鉴价值。

<summary>详细分析</summary>

视觉-语言-动作（VLA）模型虽能直接从观测与语言指令预测机器人动作，但其性能高度依赖大规模高质量标注数据，而真实机器人动作数据稀缺且成本高昂。现有研究利用潜在动作模型（LAM）从无标注视频中学习视觉动态的潜在表示，为VLA提供额外监督。然而，LAM与VLA通常分阶段独立训练：LAM在VLA训练期间保持冻结，导致其缺乏真实动作轨迹的grounding，容易学习到背景、光照等与控制无关的虚假视觉变化；同时VLA也被限制在固定的LAM表示中，无法利用前向动态先验来约束动作生成。

为此，本文提出Latent Action Representation Alignment（LARA），一种轻量且即插即用的联合优化框架。LARA将LAM的连续潜在动作与基于扩散的VLA策略（DiT）中间层隐藏状态通过可学习的投影头进行余弦相似度对齐，联合优化目标为动作流匹配损失、LARA对齐损失与LAM重构损失。该机制产生双向正则化效应：一方面，LAM在动作轨迹监督下抑制非因果视觉干扰，学习更专注于末端执行器与交互目标的逆动态表示；另一方面，VLA通过LAM蕴含的前向动态先验，减少物理上不可行或功能无效的动作轨迹幻觉。LARA兼容预训练从头训练、预训练VLA后训练增强、以及LAM精炼三种应用范式。

实验在LIBERO（4个子集）、SIMPLER-ENV（3类任务）、GR1-Sim-24及Unitree G1真机（双臂抓取-倾倒等复合任务）上展开。在OXE数据受限设置下，完整LARA在LIBERO平均达到88.6%（较DiT-only提升5.0%），在SIMPLER-ENV平均达到65.2%（提升16.8%），并超越Moto-GPT、LAPA等同类方法。作为后训练模块应用于GR00T-N1.6时，在LIBERO平均提升0.6%，在G1真机任务平均提升5.56%；应用于π0.5同样在LIBERO平均提升0.9%。此外，将LARA精炼后的LAM（LARA-LAM）作为伪标签用于Moto-GPT训练，在SIMPLER-ENV上较vanilla LAM平均提升15.7%，注意力可视化也显示其更聚焦于任务相关区域。

LARA的意义在于以极低的架构改动代价，首次实现了世界模型（LAM）与策略（VLA）在表示层面的端到端联合演化。这不仅缓解了机器人数据瓶颈，还通过注入物理动态先验显著提升了策略的泛化性与物理一致性。其即插即用特性使得现有大规模预训练VLA模型（如GR00T-N1.6、π0.5）无需重新预训练即可获得稳定增益，为利用互联网规模无标注视频进行通用机器人学习提供了高效且可扩展的技术路线。

### 第二模块：核心架构解释

**1. LAM（Latent Action Model）架构**

LAM 采用类 Moto-GPT 的 VQ-VAE 结构，负责从视觉动态中提取潜在动作：

- **视觉编码**：使用**冻结的预训练 ViT** 分别编码当前帧 \(I_t\) 与未来帧 \(I_{t+C}\)，将得到的 patch embedding 拼接为统一视觉特征序列。
- **运动提取（M-Former）**：4 层 Transformer Encoder 配备 8 个可学习 query，通过自注意力将视觉变化蒸馏为连续潜在动作表示 \(z_t\)。
- **量化**：采用 VQ 码本（词汇量 128）将 \(z_t\) 离散化为 \(z_t^q\)。
- **重建**：12 层 ViT 解码器（隐藏维度 768）以 \(I_t\) 和 \(z_t^q\) 为条件重建未来帧 \(\hat{I}_{t+C}\)。
- **训练目标**：标准 VQ-VAE 损失 \(\mathcal{L}_{\text{LAM}}\)，包含重建损失、stop-gradient 码本损失与 commitment 损失。

**2. 扩散 VLA 架构**

VLA 采用基于流匹配（Flow Matching）的扩散策略：

- **视觉-语言编码**：冻结的 Eagle-2 VLM 提取任务相关的视觉-语言 token，经可学习的自注意力 Adapter 精炼。
- **状态与动作编码**：针对异构机器人 embodiment，使用独立的 MLP 编码器将本体状态 \(s_t\) 和加噪动作 \(A_t^\tau\) 投影到共享嵌入空间。
- **DiT 去噪网络**：16 层 Diffusion Transformer，交替执行自注意力与交叉注意力（条件为 VLM 输出），预测速度场 \(v_\theta\)。
- **动作生成**：通过流匹配从噪声积分得到动作块 \(A_{t:t+C}\)。

**3. LARA 对齐机制**

LARA 的核心是将 LAM 与 VLA 通过表示对齐进行联合优化：

- **特征提取**：将 DiT 视为编码器-解码器结构 \(E_\theta \circ D_\theta\)。在 DiT 的第 **L-2 层**（倒数第二层）提取中间隐藏状态 \(h_t^\theta\)。论文特别指出，选取对应动作块**最终时间步**（\(t+C\)）的 hidden token 进行对齐，以强制策略对完整动作轨迹的表示与 LAM 预测的视觉效应匹配。
- **对齐损失**：计算 LAM 的**连续潜在动作** \(z_t\)（量化前）与投影后的 DiT 特征之间的余弦相似度：
  \[
  \mathcal{L}_{\text{LARA}} = -\mathbb{E}\left[\texttt{CosSim}\left(z_t,\; f_\psi(h_t^\theta)\right)\right]
  \]
  其中 \(f_\psi\) 为可学习的投影头。
- **联合目标**：
  \[
  \mathcal{L} = \mathcal{L}_{\text{ACT}} + w_1 \mathcal{L}_{\text{LARA}} + w_2 \mathcal{L}_{\text{LAM}}
  \]
  默认 \(w_1=0.01,\; w_2=0.01\)。

**4. 三阶段训练流程**

- **阶段 1（LAM 预训练）**：在 OXE 子集的无标签视频上训练 LAM，时域跨度 \(C=5\)，步数 350k。
- **阶段 2（LARA 联合预训练）**：加载阶段 1 的 LAM，在带动作标签的机器人数据上联合训练 DiT 与 LAM，时域跨度 \(C=16\) 以匹配动作块长度，步数 200k。
- **阶段 3（LARA 联合后训练）**：在目标任务数据上微调全部参数。

**5. 核心伪代码**

import torch
import torch.nn as nn
import torch.nn.functional as F

# -----------------------
# 模块定义
# -----------------------
class LAM(nn.Module):
    def __init__(self):
        super().__init__()
        self.vit_encoder = load_pretrained_vit(frozen=True)
        self.mformer = MFormer(num_layers=4, num_queries=8)
        self.vq = VectorQuantize(codebook_size=128)
        self.vit_decoder = ViTDecoder(num_layers=12, hidden_size=768)
    
    def forward(self, I_t, I_tC):
        # I_t, I_tC: [B, 3, H, W]
        feat_t = self.vit_encoder(I_t)
        feat_tC = self.vit_encoder(I_tC)
        visual_feat = torch.cat([feat_t, feat_tC], dim=1)  # 拼接 patch tokens
        
        z_t = self.mformer(visual_feat)          # [B, D] 连续潜在动作
        z_t_q, indices = self.vq(z_t)            # 量化
        I_hat_tC = self.vit_decoder(I_t, z_t_q)  # 重建未来帧
        return z_t, z_t_q, I_hat_tC

class DiT_VLA(nn.Module):
    def __init__(self, num_layers=16, align_layer=14):  # L=16, L-2=14
        super().__init__()
        self.vlm = load_eagle2_vlm(frozen=True)
        self.adapter = SelfAttentionAdapter()
        self.state_encoder = MLPEncoder()
        self.action_encoder = MLPEncoder()
        self.dit_blocks = nn.ModuleList([DiTBlock() for _ in range(num_layers)])
        self.action_head = nn.Linear(hidden_dim, action_dim)
        self.align_layer = align_layer
    
    def forward(self, A_tau, condition):
        # A_tau: [B, C, action_dim] 加噪动作块
        # condition 包含 VLM 特征与本体状态
        h = self.embed(A_tau, condition)
        h_align = None
        for i, block in enumerate(self.dit_blocks):
            h = block(h, condition)
            if i == self.align_layer:
                h_align = h  # 提取 L-2 层特征
        v_pred = self.action_head(h)
        return v_pred, h_align

# -----------------------
# LARA 联合训练步骤
# -----------------------
def lara_train_step(batch, lam, vla, proj_head, optim, w1=0.01, w2=0.01):
    I_t, I_tC, A_chunk, instruction, proprio = batch
    B, C, _ = A_chunk.shape
    
    # --- LAM 前向 ---
    z_t, z_t_q, I_hat_tC = lam(I_t, I_tC)  # z_t: [B, D_z]
    
    # --- VLA 条件构造 ---
    vl_feat = vla.vlm(I_t, instruction)
    vl_feat = vla.adapter(vl_feat)
    condition = {
        'vl': vl_feat,
        'state': vla.state_encoder(proprio)
    }
    
    # --- 流匹配前向 ---
    tau = torch.rand(B, 1, 1)
    epsilon = torch.randn_like(A_chunk)
    A_tau = tau * A_chunk + (1 - tau) * epsilon
    
    v_pred, h_align = vla(A_tau, condition)
    # h_align: [B, C, D_h] ; 取最终时间步 token 对应动作块末端
    h_target = h_align[:, -1, :]             # [B, D_h]
    z_proj = proj_head(h_target)             # [B, D_z]
    
    # --- 损失计算 ---
    loss_act = F.mse_loss(v_pred, A_chunk - epsilon)
    loss_lam = F.mse_loss(I_hat_tC, I_tC) + vq_commitment_loss(z_t, z_t_q)
    loss_lara = -F.cosine_similarity(z_t, z_proj, dim=-1).mean()
    
    loss = loss_act + w1 * loss_lara + w2 * loss_lam
    
    # --- 反向传播与更新 ---
    optim.zero_grad()
    loss.backward()
    optim.step()
    
    return {
        'loss': loss.item(),
        'loss_act': loss_act.item(),
        'loss_lara': loss_lara.item(),
        'loss_lam': loss_lam.item()
    }
```

Q1: 这篇论文试图解决什么核心问题？

A1: 论文试图解决 LAM（Latent Action Model）与 VLA（Vision-Language-Action）模型训练脱节的核心问题。现有范式通常将 LAM 作为静态的伪标签提供者或预训练权重，导致两个直接后果：第一，LAM 仅通过视觉重建学习，缺乏真实动作轨迹的 grounding，容易编码光照、阴影、背景等与控制无关的虚假视觉变化；第二，VLA 策略受限于冻结的 LAM 表示，且行为克隆本身缺乏对动作物理后果的显式建模，容易产生运动学合理但功能无效的动作轨迹幻觉。

当前视觉-语言-动作（VLA）模型在骨干网络、训练数据与策略上快速迭代，但其动作解码器——负责将隐藏状态映射为连续控制信号——却长期停滞，普遍采用单点预测范式（如L1回归、自回归分桶或流匹配去噪）。这类解码器将动作空间视为无结构向量，忽略了相邻动作在几何与物理上的邻近性，导致训练信号稀疏、数据效率低下，且难以捕捉多模态示教中的分布信息，从而限制了末端执行器的定位精度与策略收敛速度。

本文提出ActionMap，一种即插即用的体素热力图动作头，可直接替换现有VLA的原生解码器而无需改动骨干网络。该方法将7维动作分解为平移、旋转与夹爪三个分支，在离散化的三维体素网格上显式预测动作概率分布；训练时以ground-truth为中心生成高斯blob软标签，通过交叉熵进行监督；推理时采用top-k soft-argmax从热力图中恢复连续动作值。这种“空间结构化分类”替代了传统的单点回归，使得模型在训练阶段即可利用动作空间的局部几何结构，并兼容不同架构的VLA骨干。

实验在LIBERO仿真四套件与真实Franka机器人三项操作任务上开展。在相同训练步数下，ActionMap将OpenVLA-OFT的四套件平均成功率提升8.2%（其中Long套件提升26.6%），将π0.5提升1.6%；在仅使用10%训练数据的低数据场景下，相比OpenVLA-OFT提升26.0%，且收敛速度显著加快。在真实世界实验中，ActionMap在完整数据下以20/30对7/30全胜OpenVLA-OFT，抓取定位误差缩小2–3倍，展现出更强的空间精度与数据效率。

## 第二模块：核心架构解释

### 模型架构与流程

ActionMap 是一个**即插即用（drop-in）的 action head**，直接替换现有 VLA 的原始动作解码器，而保留 backbone、视觉-语言编码器、注意力机制及训练配方不变。

**1. 输入与主干**
- VLA backbone（如 OpenVLA-OFT 或 π0.5）处理视觉观测与语言指令，输出对应于动作 token 位置的最后一层隐状态 **h**。
- 现代 VLA 通常一次前向传播输出 **T** 个动作（chunked prediction），head 需并行读取这 **T** 个 action-token 隐状态。

**2. ActionMap Head 结构**
- 共享的 MLP trunk（含残差连接）接收隐状态 **h**。
- 三分支并行输出：
  - **Translation head**：输出 logits，reshape 为 **N_x × N_y × N_z** 的 3D grid。
  - **Rotation head**：输出 logits，reshape 为 **N_φ × N_θ × N_ψ** 的 3D grid。
  - **Gripper head**：输出 2 个 logits（binary open/close）。
- 每个体素直接存储对应动作取值的概率质量，即 **Pr(x,y,z)** 与 **Pr(φ,θ,ψ)**。

**3. 训练：软标签监督**
- 对每一维动作分量，将 ground-truth 动作坐标映射到对应体素网格位置。
- 构建以该坐标为中心的 **Gaussian blob** 目标分布（softmax 归一化），标准差为 σ：
  - 邻近体素获得非零软标签，显式编码动作空间几何邻近性。
- 损失函数为预测 softmax 分布与 Gaussian blob 目标之间的**交叉熵**，三分支求和，并对 **T** 个 chunk slot 求和。

**4. 推理：Top-k Soft-Argmax 解码**
- Translation 与 Rotation：对 grid logits 取 top-k（默认 k=10），经 temperature softmax 后做概率加权平均，恢复连续动作值。
- Gripper：直接对 2 个 bin 取 argmax。
- 该解码方式可微且比硬 argmax 更稳定。

### 实验流程

- **LIBERO 模拟**：在四个套件（Spatial, Object, Goal, Long）上评估。OpenVLA-OFT 使用 LoRA（rank 32）微调 10K 步；π0.5 遵循原 recipe 训练 30K 步。数据效率实验在 LIBERO-Spatial 上取 10%、25%、50% 分层子集。
- **真实世界 Franka**：三项任务（Pick, Sweep, Insert），对比 full data 与 50-episode 低数据场景。除 action head 外，所有超参、优化器、相机输入、训练步数均与基线严格一致。额外测量 Pick 任务 grasp 时刻的末端执行器定位误差（mm）。

import torch
import torch.nn as nn
import torch.nn.functional as F

class ActionMapHead(nn.Module):
    def __init__(self, hidden_dim, trans_grid=(48,48,24), rot_grid=(24,24,24), grip_bins=2):
        super().__init__()
        self.trans_grid = trans_grid
        self.rot_grid = rot_grid
        
        # Shared trunk
        self.trunk = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
        )
        
        # Three parallel branches
        self.trans_head = nn.Linear(hidden_dim, trans_grid[0]*trans_grid[1]*trans_grid[2])
        self.rot_head   = nn.Linear(hidden_dim, rot_grid[0]*rot_grid[1]*rot_grid[2])
        self.grip_head  = nn.Linear(hidden_dim, grip_bins)
        
    def forward(self, h):
        # h: (B, T, hidden_dim)
        x = self.trunk(h)
        trans_logits = self.trans_head(x).view(-1, *self.trans_grid)   # (B*T, Nx, Ny, Nz)
        rot_logits   = self.rot_head(x).view(-1, *self.rot_grid)       # (B*T, Nphi, Ntheta, Npsi)
        grip_logits  = self.grip_head(x)                               # (B*T, 2)
        return trans_logits, rot_logits, grip_logits

def gaussian_blob_target(gt_action, bin_centers, sigma):
    """
    gt_action: (..., D)  ground-truth continuous action
    bin_centers: (G, D)  grid bin centers
    sigma: scalar
    Returns: (G,) softmax-normalized target distribution
    """
    dist_sq = torch.sum((bin_centers - gt_action.unsqueeze(-2)) ** 2, dim=-1)
    logits = -dist_sq / (2 * sigma ** 2)
    target = F.softmax(logits, dim=-1)
    return target

def actionmap_loss(trans_logits, rot_logits, grip_logits, 
                   gt_trans, gt_rot, gt_grip, 
                   trans_bins, rot_bins, sigma):
    # Flatten grids for cross-entropy
    B = trans_logits.size(0)
    trans_pred = F.log_softmax(trans_logits.view(B, -1), dim=-1)  # (B, Nx*Ny*Nz)
    rot_pred   = F.log_softmax(rot_logits.view(B, -1), dim=-1)      # (B, Nphi*Ntheta*Npsi)
    grip_pred  = F.log_softmax(grip_logits, dim=-1)               # (B, 2)
    
    # Build soft targets
    trans_target = gaussian_blob_target(gt_trans, trans_bins, sigma)  # (B, Nx*Ny*Nz)
    rot_target   = gaussian_blob_target(gt_rot, rot_bins, sigma)      # (B, Nphi*Ntheta*Npsi)
    grip_target  = F.one_hot(gt_grip.long(), num_classes=2).float()   # (B, 2)
    
    # Cross-entropy (soft labels)
    loss_trans = -(trans_target * trans_pred).sum(dim=-1).mean()
    loss_rot   = -(rot_target * rot_pred).sum(dim=-1).mean()
    loss_grip  = -(grip_target * grip_pred).sum(dim=-1).mean()
    
    return loss_trans + loss_rot + loss_grip

def topk_soft_argmax(logits, bin_centers, k=10, temperature=1.0):
    """
    logits: (B, G)  or  (B, Nx, Ny, Nz)
    bin_centers: (G, D)
    """
    B = logits.size(0)
    logits_flat = logits.view(B, -1)
    probs = F.softmax(logits_flat / temperature, dim=-1)
    
    # Select top-k
    topk_probs, topk_idx = torch.topk(probs, k, dim=-1)  # (B, k)
    topk_probs = topk_probs / topk_probs.sum(dim=-1, keepdim=True)
    topk_bins = bin_centers[topk_idx]                      # (B, k, D)
    
    action = (topk_probs.unsqueeze(-1) * topk_bins).sum(dim=1)  # (B, D)
    return action
```

### 第二模块：核心架构解释

**整体流程**  
Coarse-to-Control 是一个两阶段自回归 VLA：先预测粗粒度规划 token，再在其条件下预测可执行动作 token。整个系统由三部分组成：**粗粒度动作压缩**、**联合双粒度残差 VQ Tokenizer**、**Plan-Execute 自回归策略**。

**1. 粗粒度动作压缩**  
对于时刻 t，从未来长程动作序列 \(A_{t:t+H_p-1}\) 中抽取粗粒度规划轨迹 \(\bar{A}_t\)，共 \(K\) 步，块大小 \(c=H_p/K\)。  
- **motion 维度**：对块内相对位移求和，保留净运动方向。  
- **gripper 维度**：取块内最后一个状态，保留阶段末的夹爪开合意图。  
这样得到的 \(\bar{A}_t\) 丢弃高频细节，保留阶段级运动意图（如接近、抓取、运输、放置）。

**2. 联合双粒度残差 VQ Tokenizer**  
Tokenizer 有两个模式，通过 mode embedding 区分，但共享同一组残差 VQ codebook（3 层，每层 4096 个条目）：  
- **执行模式（m=0）**：编码短程可执行动作块 \(A_{t:t+H_e-1}\)。  
- **规划模式（m=1）**：编码粗粒度长程轨迹 \(\bar{A}_t\)。  

两者输出同一离散词汇表中的 token ID，因此规划 token 与执行 token 处于同一动作语义流形。训练目标为重构损失（\(\ell_1\)）+ 残差 VQ 正则化（codebook loss + commitment loss，\(\beta=0.25\)）。

**3. Plan-Execute 自回归 VLA**  
策略主干为基于 PaliGemma-3B 的 VLA。输入多模态上下文 \(x_t=(o_t,l,s_t)\) 后，模型自回归地生成拼接后缀：  
\[
z_t = [z_t^{\mathrm{plan}}, z_t^{\mathrm{exec}}]
\]  
训练时使用 teacher forcing，对所有 token 做 next-token prediction；推理时仅将 \(z_t^{\mathrm{exec}}\) 解码为连续机器人动作，\(z_t^{\mathrm{plan}}\) 仅作为内部上下文，不引入额外规划器-控制器接口。

**实验流程**  
- **Tokenizer 预训练**：仿真设置使用 LIBERO + Bridge；真实世界设置使用 Fractal、Kuka、Bridge、Droid(EEF) + LIBERO 的混合数据。Tokenizer 在 8×H200 上预训练后固定。  
- **策略训练**：使用 AdamW，lr=2.5×10⁻⁵，1k warmup，cosine decay，weight decay 10⁻¹⁰。LIBERO 训练 60k 步（batch 4）；SimplerEnv-WidowX 训练 4 epoch（batch 16）；真实世界训练 30k 步（batch 8）。  
- **评估**：LIBERO 每任务 50 trials；SimplerEnv-WidowX 每任务 24 trials；真实世界 4 个物理任务，每任务 50 演示、20 trials。

# 1. 粗粒度动作压缩
def coarse_subsample(A_future, H_p, K):
    c = H_p // K
    A_coarse = []
    for i in range(K):
        chunk = A_future[i*c : (i+1)*c]
        motion = sum(chunk.motion)          # 块内相对运动求和
        gripper = chunk.gripper[-1]           # 取块末夹爪状态
        A_coarse.append(concat(motion, gripper))
    return A_coarse  # K 步粗粒度轨迹

# 2. 联合残差 VQ Tokenizer（共享词汇表，模式条件）
class JointActionTokenizer(nn.Module):
    def __init__(self):
        self.encoder = SharedEncoder()
        self.decoder = SharedDecoder()
        self.codebooks = [ResidualVQ(size=4096) for _ in range(3)]
        self.mode_embed = nn.Embedding(2, dim=64)  # 0=exec, 1=plan

    def encode(self, A, mode):
        x = self.preprocess(A) + self.mode_embed(mode)
        z = self.encoder(x)
        tokens = []
        for rq in self.codebooks:
            z_q, ids = rq.quantize(z)   # 离散化并返回 token ID
            tokens.append(ids)
            z = z - z_q                 # 残差
        return tokens

    def decode(self, tokens, mode):
        z = sum(self.codebooks[i].lookup(tokens[i]) for i in range(3))
        z = z + self.mode_embed(mode)
        return self.decoder(z)

# 3. VLA 训练（teacher forcing）
def vla_forward(obs, lang, state, A_exec, A_plan):
    context = vlm_encoder(obs, lang, state)
    z_plan = tokenizer.encode(A_plan, mode=1)
    z_exec = tokenizer.encode(A_exec, mode=0)
    z_all = concat(z_plan, z_exec)
    
    loss = 0
    for i in range(len(z_all)):
        logits = transformer(context, z_all[:i])  # 因果掩码
        loss += cross_entropy(logits, z_all[i])
    return loss

# 4. 推理：先规划，后执行，仅解码执行分支
def inference(obs, lang, state):
    context = vlm_encoder(obs, lang, state)
    
    # 阶段 1：生成规划 token（内部使用）
    z_plan = []
    for _ in range(num_plan_tokens):
        logits = transformer(context, z_plan)
        z_plan.append(sample(logits))
    
    # 阶段 2：条件生成执行 token
    z_exec = []
    for _ in range(num_exec_tokens):
        logits = transformer(context, z_plan + z_exec)
        z_exec.append(sample(logits))
    
    A_out = tokenizer.decode(z_exec, mode=0)
    return A_out

现有交互式世界模型在实用场景的多样化可控性方面探索不足，尤其是在第一人称（egocentric）视角下，如何自然地进行身体动作交互并精确控制局部场景状态仍是一个开放问题。现有方法多依赖键盘、相机轨迹或文本等简化控制信号，无法反映真实的人类第一人称交互方式；同时，环境通常由初始帧或全局提示隐式定义，难以在特定三维位置指定物体存在性或控制局部场景的时序演化。本文针对这一空白，提出了“世界可定制的具身第一人称模拟”任务。

**TL;DR:** 作者提出了一种基于**混合视角投影**与**位姿关联锚点视图**的 **AnchorWorld** 框架，以解决现有交互式世界模型缺乏**精细具身动作控制**与**局部世界状态显式定制**能力的问题，在静态/动态第一人称场景及合成 UE 场景的场景一致性、相机控制精度和动态演化对齐上实现了显著超越基线的表现。

**研究动机：** 现存方案存在两大痛点。第一，控制信号过度简化（键盘、文本或仅手部），无法反映自然人机交互；且第一人称视频中全身大部分区域不可见，导致**动作监督稀疏且弱对齐**。第二，世界状态由初始帧或全局文本隐式定义，用户无法在特定 3D 位置指定局部场景内容，更无法驱动其随时间演化。本文的切入点极为巧妙：它利用**第三人称视频**补充被遮挡的全身监督，并通过“投影”将外部视角与第一视角统一为同一条件空间；同时把世界状态显式编码为带有 **6DoF 位姿的锚点视图**加演化文本，实现了“指哪打哪”的时空一致世界定制。

**核心机制：** 剥离复杂的流匹配公式，其架构本质可概括为两点：一是将 **3D 人体动作序列与相机外参在投影空间统一为条件 token**，通过空间自注意力注入 DiT，让模型在第三人称视频上学会“动作-视觉后果”的映射，再迁移到第一人称；二是将局部世界状态编码为**带位姿的图像 token**作为上下文拼入视频序列，并用**掩码交叉注意力**将每条局部演化文本严格绑定到对应的锚点视图，从而在统一坐标系下实现多视角一致且可演化的场景生成。

**关键数据：**

- **最能证明有效性的核心数据：** 在 **Ego Static Scene** 上，AnchorWorld 的 Matched Pixels 达到 **4493.4K**（CaM-Ego 为 4379.4K，PlayerOne-Scene 为 4334.8K），CLIP-V 达到 **0.885**（CaM-Ego 为 0.872），绝对平移误差 ATE 降至 **0.112**（CaM-Ego 为 0.125）。这组数据同时覆盖了场景几何一致性、语义一致性和相机轨迹精度，证明混合视角动作控制与锚点视图机制带来了全面的性能提升。

## 第二模块：核心架构解释

AnchorWorld 以 **Wan2.2 TI2V 5B**（基于 Flow Matching 的 DiT 视频生成模型）为基座，通过四阶段渐进训练，逐步获得混合视角动作控制与可演化锚点视图定制能力。

### 1. 混合视角人体动作控制（Hybrid-View Human Action Control）

人体动作采用 SMPL-X 参数化模型表示，包含 22 个主要关节，每关节由 3D 位置与 3D 轴角旋转向量组成，即 **M ∈ R^{f×k×6}**。相机轨迹（第三人称观察视角或第一人称头部视角）表示为外参序列 **C ∈ R^{f×3×4}**。

- **投影式条件编码**：Motion Encoder 将 M 映射为 **z_m ∈ R^{f'×k×d}**，Camera Encoder 将 C 映射为 **z_c ∈ R^{f'×1×d}**，其中 f' 为 VAE 编码后的时间分辨率。
- **Spatial Pose Attention**：在 DiT 的每一层，将视频 latent token **z_v^{(t)}** 与 **z_m**、**z_c** 沿**空间维度**拼接为统一序列 **T = [z_v^{(t)}; z_m; z_c]**，经过 Spatial Self-Attention 后，通过 **Truncate** 操作丢弃 pose token，仅保留更新后的视频特征。这使得模型显式感知帧级动作-视频对应关系，并弥合 pose 特征与 VAE latent 的分布差异。

### 2. 可演化锚点视图定制（Evolvable Anchor-View Customization）

世界状态由初始第一帧 I_0 和一组锚点视图 **S = {(I_i, c_i, t_i)}** 定义，其中 c_i 为 6DoF 位姿，t_i 为描述局部场景动态演化的文本。

- **In-Context 图像先验**：锚点视图图像经 VAE 编码为 **z_s**，与视频 token **z_v^{(t)}** 沿**帧维度**拼接（**T_total = [z_v^{(t)}; z_s]**）。为区分多个锚点，引入 **3D RoPE**，给锚点视图分配独立的帧轴位置编码。
- **View Pose 注入**：将视频帧与锚点视图的相机位姿统一编码为 **z_pose**，广播到空间分辨率后**残差相加**到视觉 token 上，使模型建立锚点视图在统一世界坐标系中的空间 grounding。
- **文本驱动的掩码交叉注意力**：每个锚点的演化文本 t_i 通过 Cross-Attention 注入。关键设计在于**注意力掩码**：文本 i 的 Key 仅对**视频 token** 和**第 i 个锚点视图的 token** 可见，对其他锚点掩码为 -∞。这严格保证了局部演化指令的局部性，避免不同锚点间的语义干扰。

### 3. 渐进式多阶段训练策略

训练分为四个阶段，逐步叠加能力：

- **Stage I（第三人称动作预训练）**：使用 200K 内部单人称视频 + 101K UE 合成 MultiCamVideo 数据。相机参数为外部观察视角，让模型学习完整的全身动作投影与交互先验。
- **Stage II（第一人称动作适配）**：使用 100K Ego-Exo4D / LEMMA 同步数据，将相机轨迹对齐到穿戴者头部姿态，适配 egocentric 分布。
- **Stage III（静态锚点视图定制）**：使用 25K 大视角变化样本，学习在静态场景下利用锚点视图保持多视角几何一致。
- **Stage IV（动态锚点视图演化）**：混合 25K 静态样本与 10K 动态样本（含人工标注的演化文本），学习文本驱动的局部状态演化。

class AnchorWorld(nn.Module):
    def __init__(self, dit, motion_enc, camera_enc, pose_enc, text_enc):
        self.dit = dit
        self.motion_enc = motion_enc
        self.camera_enc = camera_enc
        self.pose_enc = pose_enc
        self.text_enc = text_enc

    def spatial_pose_attention(self, video_tokens, motion, camera):
        # video_tokens: (B, f', h*w, d)
        # motion: (B, f, k, 6), camera: (B, f, 3, 4)
        z_m = self.motion_enc(motion)      # (B, f', k, d)
        z_c = self.camera_enc(camera)      # (B, f', 1, d)
        T = torch.cat([video_tokens, z_m, z_c], dim=2)  # spatial concat
        T = self.dit.spatial_self_attn(T)
        out = T[:, :video_tokens.size(2), :]  # Truncate pose tokens
        return out

    def anchor_condition(self, video_tokens, anchor_imgs, anchor_poses, video_poses):
        # Encode anchor images and concat along frame axis
        z_s = torch.cat([vae_encode(img) for img in anchor_imgs], dim=0)
        T_total = torch.cat([video_tokens, z_s], dim=0)  # (f'+n, h*w, d)
        
        # 3D RoPE with distinct frame ids for anchors
        frame_ids = list(range(video_tokens.size(0))) + \
                    [video_tokens.size(0) + i for i in range(len(anchor_imgs))]
        rope = compute_3d_rope(T_total, frame_ids)
        
        # Pose injection: add pose embeddings to all visual tokens
        all_poses = torch.cat([video_poses, anchor_poses], dim=0)
        z_pose = self.pose_enc(all_poses).broadcast_to(T_total.shape)
        T_total = T_total + z_pose
        return T_total, rope

    def masked_evolution_cross_attn(self, visual_tokens, text_embs, video_len, anchor_indices):
        # text_embs: list of (L_i, d) per anchor
        # anchor_indices: global frame index of each anchor in visual_tokens
        out = visual_tokens
        for i, txt in enumerate(text_embs):
            mask = torch.full((visual_tokens.size(0),), float('-inf'))
            mask[:video_len] = 0               # attend to video tokens
            mask[anchor_indices[i]] = 0        # attend to own anchor token
            out = cross_attn_with_mask(out, txt, frame_mask=mask)
        return out

    def forward(self, I0, motion, camera, anchors, evolution_texts, t):
        z_v = vae_encode(I0)  # video latent
        z_v = self.spatial_pose_attention(z_v, motion, camera)
        
        z_v, rope = self.anchor_condition(
            z_v, anchors['images'], anchors['poses'], camera
        )
        text_embs = [self.text_enc(txt) for txt in evolution_texts]
        z_v = self.masked_evolution_cross_attn(
            z_v, text_embs, video_len=z_v.size(0) - len(anchors['images']),
            anchor_indices=anchors['indices']
        )
        v_pred = self.dit(z_v, rope=rope, timestep=t)
        return v_pred

# Progressive Training Pipeline
def train_progressive(model, loaders):
    # Stage I: Exocentric motion (TPV)
    train(model, loaders.tpv, iters=30000, lr=1e-4, batch=16)
    # Stage II: Egocentric motion (FPV)
    train(model, loaders.fpv, iters=15000, lr=1e-4, batch=16)
    # Stage III: Static anchor-view consistency
    train(model, loaders.static, iters=10000, lr=1e-4, batch=16)
    # Stage IV: Dynamic anchor-view evolution
    train(model, loaders.dynamic, iters=10000, lr=1e-4, batch=16)

## 第三模块：核心学术问答

Q1: 这篇论文试图解决什么核心问题？

A1: 论文试图解决交互式世界模型在具身第一人称模拟中的两大核心缺陷。第一，**控制信号不够具身**：现有工作多依赖键盘、文本或手部动作，缺乏以全身 3D 人体动作为驱动的自然交互控制；且第一人称视频中大部分身体区域不可见，导致从 egocentric 视频学习动作-视觉映射时监督稀疏、空间 grounding 弱。第二，**世界状态定义过于隐式**：环境内容通常由初始帧或全局文本决定，用户无法在特定 3D 位置显式指定局部场景外观，更无法精确控制该区域随时间动态演化。论文将这两个需求形式化为“世界可定制的具身第一人称模拟”任务。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 核心解决方案是 **AnchorWorld** 框架，包含三项关键创新：
- **混合视角投影式动作控制**：引入第三人称视频作为辅助训练数据，将 3D 人体动作与相机外参统一为投影式条件，通过 Spatial Pose Attention 注入 DiT。这使得模型先在第三人称视角下学习完整的动作-场景交互先验，再迁移到第一人称，显著缓解了 egocentric 监督缺失问题。
- **位姿关联的可演化锚点视图**：提出用锚点视图（RGB 图像 + 6DoF 位姿 + 演化文本）显式定义局部世界状态。通过 In-Context 帧拼接、3D RoPE 区分、位姿残差注入和掩码交叉注意力，实现了多锚点空间 grounding 与局部动态演化的解耦控制。
- **渐进式四阶段训练策略**：从第三人称动作 → 第一人称动作 → 静态锚点一致性 → 动态锚点演化，逐步叠加能力，保证每阶段在稳定基础上构建新技能。

Q5: 这项工作在哪些相关研究的基础上做了推进？（列举1-2个最核心的前置工作即可）

A5:
- **前置工作1：PlayerOne (Tu et al., 2025)。** 该工作首次尝试用全身人体动作驱动第一人称世界模型，并引入部位解耦的动作注入。AnchorWorld 在此基础上推进：指出其仅依赖第一人称视频导致的监督稀疏问题，并通过混合视角投影机制显著提升了动作控制精度与空间一致性。
- **前置工作2：Context-as-Memory / CineScene (Yu et al., 2025; Huang et al., 2026)。** 这类工作通过历史帧检索或密集视角表示来维持场景一致性。AnchorWorld 推进了该范式：不再被动依赖历史上下文，而是允许用户通过带位姿的锚点视图**主动显式定义**局部世界状态，并进一步支持文本驱动的动态演化，从“记忆一致”走向“定制演化”。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

A6: 论文在附录中坦诚了若干局限，但仍存在值得深挖的“未讲明的故事”：
- **长期探索与实时交互的缺失：** 当前框架仅支持短片段（77 帧）生成，缺乏长时记忆与自回归实时交互能力。第一人称智能体在持续探索中需要实时更新自身动作引起的环境状态变化，这要求模型具备**长时记忆机制**与流式推理能力，这是后续关键方向。
- **动态控制的粒度不足：** 尽管框架支持每个锚点配一个演化文本，但受限于当前 egocentric 数据，实现中所有锚点共享**同一全局演化描述**（t_1 = ... = t_n），且动态场景主要局限于人类相关活动。真正的开放世界需要**锚点独立、细粒度、甚至物理一致的动态演化**（如一个锚点描述“树叶飘落”，另一个描述“水面结冰”）。
- **数据层面的隐含妥协：** 训练时锚点视图图像常包含第一人称玩家自身（Ego-Exo4D 的固有缺陷），作者未做修复，仅依赖模型“学会忽略”。虽然推理时可用干净锚点，但这本质上是一种数据噪声下的侥幸，未从根因上解决。
- **基础模型能力的天花板：** 失败案例显示，复杂纹理细节不一致与运动模糊问题部分源于 Wan VAE 16 倍下采样导致的信息损失。这提示后续工作：**世界模拟的上限不仅取决于条件控制架构，更取决于基础生成模型的保真度与时空分辨率**。未来应联合探索更高质量的视频 VAE 与更高效的细粒度控制接口。

### 第二模块：核心架构解释

RhinoVLA 的整体 pipeline 可分为 **输入对齐**、**视觉-语言编码**、**动作生成** 与 **部署优化** 四层。

**1. 输入对齐层：View Registry 与 72D Slot 空间**
异构机器人数据首先被标准化。多视角图像通过 **View Registry** 打上显式的角色-模态标签（如 `[head|rgb]`、`[left_wrist|rgb]`），再与语言指令拼接；机器人状态与动作则通过语义映射写入统一的 **72D 物理 slot 空间**（如 D0–D6 固定为 Arm0 关节弧度，D14–D15 为夹爪闭合比），而非按数据集顺序偏移。每个样本同时生成二进制 **state_mask** 与 **action_mask**，标记当前机器人实际拥有的自由度，防止缺失关节污染监督信号。

**2. 视觉-语言编码层：Qwen3-VL 并行编码**
三路相机图像（head + 左右腕部）以 **256×256** 输入 Qwen3-VL ViT。通过空间合并，每图仅产生 **64 个视觉 token**（对比 PaliGemma 的 256 个）。在部署时，三视图被 batch 为单次并行编码，视觉编码延迟从 34.52 ms 降至 **24.31 ms**。随后，Qwen3-VL（2.13B，冻结主干+可训 LoRA）处理多模态前缀，提取 **最后 18 层 KV cache** 作为 Action Expert 的视觉-语言条件。

**3. 动作生成层：Action Expert + Instance LoRA + Masked Flow Matching**
Action Expert（0.40B，18 层，hidden size 1024，Qwen 兼容结构）接收以下输入：
- 噪声动作 chunk `x_t`、流匹配时间步 `t`
- 72D 当前状态 `s`、state_mask、action_mask
- VLM 前缀 KV cache `c_vlm`
- `robot_id` 选通的 **robot-instance LoRA**

在每个 Transformer 层的 FFN 中，实例 LoRA 注入机器人特定的残差修正，而 attention 模块与最终投影层保持共享。模型预测 72D 流速度 `v_θ`，训练目标为 masked flow-matching loss：

\[
\mathcal{L}_{\mathrm{FM}} = \frac{\sum_{h,d} m_a(d) w(h,d) \|\hat{v}_{\theta}(h,d) - (z(h,d)-a(h,d))\|_2^2}{\sum_{h,d} m_a(d) w(h,d) + \epsilon}
\]

仅 `action_mask` 为真的 slot 参与监督，并辅以 per-slot 权重平衡不同动作组。此外，base Action Expert 的输出也直接受监督，防止 instance LoRA 接管全部预测，确保共享部分学到跨机器人通用结构。

**4. 部署优化层：软硬协同**
- **编译优化**：针对 R1 的 SPM（scratchpad memory）定制 FlashAttention 风格分块，实现 >80% 理论峰值；图级算子融合将 Attention/MLP 中的 norm、投影、激活、残差合并，减少 DDR 访问；运行时细粒度调度避免计算单元空转。
- **混合精度**：采用 **W8A16**（INT8 权重、FP16 激活），并定制 fused GEMM kernel 将反量化与乘加流水化，up_proj 延迟从 191 μs 降至 **113 μs**（1.69× 加速）。
- **并行视觉编码**：三视图 batch 处理，提升 kernel 占用率。

**5. 实验流程**
- **预训练**：在 AgiBotWorld Beta/2026（约 3000 小时 G1/G2 数据）与 Open X-Embodiment 子集上，以幂律采样（指数 0.43）混合训练，联合优化 VLM LoRA、共享 Action Expert 与 instance LoRA。
- **诊断**：分析预训练损失曲线与 LoRA 余弦相似度矩阵，验证 instance LoRA 确实编码 embodiment 残差（与 action-mask 的 Hamming 距离负相关）。
- **仿真**：在 LIBERO 四套件（Spatial/Object/Goal/Long）上测试单检查点性能。
- **真机**：在 Galbot G1（单臂短程）、AgiBot G2（长程单臂）、AgiBot G1（双臂毛巾折叠）上进行 seen/unseen 设置评估，仅微调目标机器人的 instance LoRA。
- **效率**：在 Huixi R1 上测量端到端延迟与频率。

def preprocess(sample, robot_meta):
    # 1. View Registry: 显式标注相机角色与模态
    views = []
    for cam_field, img in sample["images"].items():
        role = robot_meta[cam_field]["role"]      # e.g., "head", "left_wrist"
        mod = robot_meta[cam_field]["modality"]   # e.g., "rgb"
        views.append((f"[{role}|{mod}]", img))
    
    # 2. 统一 72D 物理 slot 空间与 mask（语义映射，非位置偏移）
    state = torch.zeros(72)
    action = torch.zeros(72)
    state_mask = torch.zeros(72, dtype=torch.bool)
    action_mask = torch.zeros(72, dtype=torch.bool)
    
    for joint, val in sample["state"].items():
        idx = SLOT_SEMANTIC_MAP[joint]
        state[idx] = to_physical_unit(val, joint)
        state_mask[idx] = True
    
    for joint, val in sample["action"].items():
        idx = SLOT_SEMANTIC_MAP[joint]
        action[idx] = to_physical_unit(val, joint)
        action_mask[idx] = True
    
    return views, state, action, state_mask, action_mask

class RhinoVLA(nn.Module):
    def __init__(self):
        # VLM: Qwen3-VL-2B, 冻结权重，仅训练 LoRA
        self.vlm_backbone = Qwen3VL2B(frozen=True)
        self.vlm_lora = LoRA(self.vlm_backbone, r=64)
        
        # Action Expert: 18层, 1024 hidden, Qwen兼容结构
        self.action_expert = ActionExpert(
            n_layers=18, hidden_size=1024, mlp_size=3072,
            n_heads=16, kv_heads=8, head_dim=128
        )
        
        # Robot-instance LoRA: 每个机器人一个轻量适配器，插入 FFN
        self.robot_loras = nn.ModuleDict({
            rid: LoRA(self.action_expert.ffn_layers, r=16) 
            for rid in ROBOT_REGISTRY
        })
        
        self.action_proj = nn.Linear(1024, 72)
    
    def forward(self, views, task_text, state, state_mask, 
                noisy_action, t, robot_id):
        # --- VLM 前缀编码（并行视觉编码）---
        visual_tokens = self.vlm_backbone.encode_images_parallel(
            images=views, target_size=(256, 256)
        )
        prefix_tokens = self.vlm_backbone.build_prompt(
            task=task_text, tagged_views=visual_tokens
        )
        # 取最后 18 层 KV cache
        prefix_kv = self.vlm_backbone.forward_prefix(
            prefix_tokens, use_last_n_layers=18
        )
        
        # --- Action Expert 去噪 ---
        suffix = pack_suffix(state, state_mask, noisy_action, t)
        lora_adapter = self.robot_loras[robot_id]
        
        hidden = self.action_expert(
            suffix_tokens=suffix,
            vlm_prefix_kv=prefix_kv,
            lora=lora_adapter,
            use_qwen_compatible_attention=True,
            ada_rms_conditioning=True
        )
        v_pred = self.action_proj(hidden)
        
        # 无效维度置零
        v_pred = v_pred * action_mask.unsqueeze(1).float()
        return v_pred

def compute_loss(model, batch):
    views, task, state, s_mask, action_gt, a_mask, robot_ids = batch
    B, H, D = action_gt.shape
    
    # Flow Matching
    noise = torch.randn_like(action_gt)
    t = torch.rand(B, device=action_gt.device)
    x_t = (1 - t.view(B, 1, 1)) * noise + t.view(B, 1, 1) * action_gt
    
    v_pred = model(views, task, state, s_mask, x_t, t, robot_ids)
    target = action_gt - noise
    
    # Masked + 加权 MSE
    weights = compute_slot_weights(a_mask)
    loss_fm = weighted_masked_mse(v_pred, target, a_mask, weights)
    
    # 残差正则化: base model 直接受监督
    v_base = model.forward_without_robot_lora(
        views, task, state, s_mask, x_t, t, robot_ids
    )
    loss_reg = F.mse_loss(v_base, target.detach())
    
    return loss_fm + 0.1 * loss_reg

def deploy_infer(model, obs, task, robot_id):
    # 端到端部署: 编译静态图 + W8A16 + 并行编码
    with hw_aware_compile(), mixed_precision(W8A16):
        views = preprocess_images(obs["images"], size=256)
        state, s_mask = encode_72d_state(obs["robot_state"])
        
        prefix_kv = model.vlm_backbone.encode_parallel(views, task)
        
        # 流匹配去噪
        action = torch.randn(1, HORIZON, 72)
        for t in diffusion_timesteps:
            v = model(views, task, state, s_mask, action, t, robot_id)
            action = action + v * dt
        
        return action * s_mask.unsqueeze(1).float()

- **72D slot 的信息损失**：当前预留 11 个辅助 slot（D61–D71）未定义语义，且对无法可靠映射到 slot 的数据直接丢弃而非保留原始表示，可能损失部分机器人特有的控制信息。

对后续科研的启发：
- **Token 效率应成为 VLA 的首要优化目标之一**：在边缘算力约束下，视觉 token 的压缩与 MLP 计算削减比单纯缩小模型尺寸更具杠杆效应，未来可探索动态分辨率、视觉 token 稀疏化等更激进的压缩策略。

<summary>详细分析</summary>

现有Vision-Language-Action (VLA)模型虽具备强大的预训练泛化能力，但在面对新任务或分布偏移时，通常需要收集带有动作标注的任务专属演示并进行额外的梯度微调，导致部署成本高且难以扩展。本文提出WIZARD，一种基于权重空间元学习的框架，旨在绕过上述瓶颈：仅依据语言指令和一段简短的演示视频，即可在单次前向传播中生成任务专属的LoRA适配器权重，无需目标动作标签，也无需测试时优化。

方法上，WIZARD首先在元训练阶段构建一个由任务嵌入与专家LoRA参数对组成的数据集，其中任务嵌入来自冻结VLA编码器对语言与视觉证据的编码。随后，一个元网络学习将任务嵌入直接映射到权重空间的LoRA更新。为了应对机器人VLA架构的多模态异构性和参数尺度敏感性，作者提出三项关键设计：按感知-推理-控制模块进行多模态权重结构化表示、联合预测归一化权重与逐层统计量的尺度感知生成机制、以及通过余弦相似度约束方向一致性的对齐导向监督损失（MSE+尺度+余弦）。

实验在LIBERO基准的四个数据集（Spatial、Object、Goal、10）以及真实Franka Emika Panda机械臂上展开。在严格的数据集外零样本设定下，WIZARD在未见数据集上的平均成功率较MT-VLA基线提升约2倍，在未见任务上最高提升约14倍；在真实机器人上，其平均成功率从0.22提升至0.41。此外，生成的适配器可作为微调的暖启动，使策略在70步内达到专家水平（对比MT-VLA的90步），并能在零样本下达到需要25条演示才能匹配的MT-VLA性能。

### 第二模块：核心架构解释

**整体流程**：WIZARD 分为两阶段。第一阶段构建元数据集：在 LIBERO 的三个数据集上，为每个任务冻结 $\pi_{0.5}$ 骨干并训练独立的 LoRA 专家，同时用冻结的 VLA 编码器提取语言-视频任务嵌入。第二阶段训练元网络：学习将任务嵌入直接映射为结构化的 LoRA 权重张量。测试时，对新任务的语言指令和短视频进行一次编码，元网络单步前向生成 LoRA 参数并注入冻结 VLA，无需动作标签与梯度更新。

**关键实现细节**：
- **任务嵌入构建**：从任务的若干演示片段中，使用冻结的 VLA 多模态编码器 $G^{\mathrm{enc}}$ 分别对语言指令 $p$ 和视觉观测 $v$ 编码，再对多个片段的 embedding 做平均池化，得到固定维度的任务表征 $z^{(k)}$。
- **多模态权重张量化**：VLA 的 LoRA 参数横跨视觉、语言、动作三类异构模块。为避免结构混乱，参数被按拓扑排序（Action Projector → Gemma Expert → PaliGemma LM → Multi-Modal Projector → Vision Tower → Temporal MLPs）后，填充并堆叠为统一张量 $\Delta W \in \mathbb{R}^{L \times 3 \times r \times H}$，其中第二维显式区分三种模态。
- **尺度感知生成**：由于机器人策略对参数尺度极度敏感，元网络除预测归一化权重外，还并行预测每层的统计量 $\tilde{S}^{(k)} = \{(\mu_l, \sigma_l)\}$。重建时按 $\Delta \tilde{W} \leftarrow \tilde{S} \cdot (\Delta \tilde{W} / \|\Delta \tilde{W}\|)$ 重新缩放，防止因跨层幅度异质性导致训练发散。
- **对齐导向监督**：损失函数由三项组成：掩码 MSE 重建损失 $\mathcal{L}_{\text{MSE}}$、尺度回归损失 $\mathcal{L}_{\text{scale}}$、以及余弦方向损失 $\mathcal{L}_{\text{cos}}$。其中余弦损失强制生成权重与专家权重在参数空间中的方向一致，确保功能相似性而非逐元素逼近。

**实验流程**：采用留一数据集协议评估跨分布泛化（如以 Goal/Object/10 训练，在 Spatial 上测试）。对比基线包括任务特定专家（上限）、最近邻检索、以及两个多任务微调 MT-VLA 基线（OpenVLA-OFT 与 $\pi_{0.5}$）。真实世界实验在 Franka Emika Panda 上进行，基线与 WIZARD 共享相同的真实域初始化（30 段真实数据微调），以隔离权重空间特化本身带来的增益。

import torch.nn as nn
import torch.nn.functional as F

# 加载冻结的 pi_0.5 VLA 骨干与编码器
frozen_vla = load_pretrained_vla("pi_0.5")
frozen_encoder = frozen_vla.encoder  # G^enc，全程冻结

# ==================== 1. 构建 Meta-Dataset ====================
meta_dataset = []
for task in meta_train_tasks:
    # Phase 1: 用动作标签训练任务专属 LoRA 专家（仅元训练需要动作标注）
    expert_lora = train_lora_expert(
        base_model=frozen_vla,
        episodes=task.episodes,  # (p, v, s, a)
        rank=16, alpha=16, dropout=0.0
    )
    # 将专家 LoRA 权重拓扑排序、填充、分块为统一 token 网格
    delta_W_gt = tokenize_lora(expert_lora.state_dict())  # (L, 3, r, H)
    S_gt = compute_layerwise_stats(expert_lora)  # 每层 (mu, sigma)
    
    # Phase 2: 构建任务嵌入（无需动作标签）
    support_eps = sample(task.episodes, k=5)
    z_list = [frozen_encoder(ep.lang_prompt, ep.video) for ep in support_eps]
    z = torch.stack(z_list).mean(dim=0)  # 平均池化
    
    meta_dataset.append((z, delta_W_gt, S_gt))

# ==================== 2. 元网络架构 ====================
class DecomposedConv3D(nn.Module):
    """分解式 3D 卷积：并行 1x7 和 7x1 空间卷积后平均"""
    def __init__(self, in_ch, out_ch, spatial):
        super().__init__()
        self.path1 = nn.Sequential(
            nn.Conv2d(in_ch, in_ch, kernel_size=(1, 7), padding=(0, 3)),
            nn.Conv2d(in_ch, out_ch, kernel_size=(7, 1), padding=(3, 0))
        )
        self.path2 = nn.Sequential(
            nn.Conv2d(in_ch, in_ch, kernel_size=(7, 1), padding=(3, 0)),
            nn.Conv2d(in_ch, out_ch, kernel_size=(1, 7), padding=(0, 3))
        )
        self.bias = nn.Parameter(torch.zeros(out_ch))
        self.dropout = nn.Dropout(0.15)
    
    def forward(self, x):
        x1 = self.path1(x)
        x2 = self.path2(x)
        out = (x1 + x2) / 2 + self.bias.view(1, -1, 1, 1)
        return self.dropout(F.silu(out))

class MetaNetwork(nn.Module):
    def __init__(self):
        super().__init__()
        self.proj = nn.Linear(2048, 512)  # VLA embedding 投影
        
        # 3D 全卷积解码器：时序维度逐步展开，最终生成 5929 个 token
        self.decoder = nn.Sequential(
            DecomposedConv3D(168, 128, 32),   # (B,128,32,512)
            DecomposedConv3D(128, 128, 32),   # (B,128,32,512)
            DecomposedConv3D(128, 1024, 16),  # (B,1024,16,512)
            DecomposedConv3D(1024, 5929, 16), # (B,5929,16,512)
        )
        
        # 尺度预测器：输出 per-token 的 mu/sigma（up/down 共 4 维）
        self.scale_pred = nn.Sequential(
            nn.Linear(16 * 512, 1024),
            nn.SiLU(),
            nn.Dropout(0.15),
            nn.Linear(1024, 5929 * 4)
        )
    
    def forward(self, z):
        # z: (B, T, 2048) -> 插值到 168 帧 -> 投影到 512
        z = temporal_interpolate(z, target_len=168)
        x = self.proj(z)  # (B, 168, 512)
        x = x.unsqueeze(1)  # 适配 2D 卷积的通道维度
        
        tokens = self.decoder(x)  # (B, 5929, 16, 512)
        flat = tokens.view(tokens.size(0), 5929, -1).mean(dim=-1)
        S = self.scale_pred(flat).view(tokens.size(0), 5929, 4)
        return tokens, S

# ==================== 3. 元网络训练 ====================
meta_net = MetaNetwork().cuda()
optimizer = AdamW8bit(meta_net.parameters(), lr=1e-4)

for z, delta_W_gt, S_gt in meta_loader:
    z, delta_W_gt, S_gt = z.cuda(), delta_W_gt.cuda(), S_gt.cuda()
    
    delta_W_pred, S_pred = meta_net(z)
    
    # 尺度感知重缩放
    delta_W_pred = rescale_by_layer(delta_W_pred, S_pred)
    
    # 多目标损失
    loss_mse = masked_mse(delta_W_pred, delta_W_gt)      # 仅计算非填充区域
    loss_scale = F.mse_loss(S_pred, S_gt)
    loss_cos = 1 - F.cosine_similarity(
        flatten(delta_W_gt / delta_W_gt.norm()),
        flatten(delta_W_pred / delta_W_pred.norm()),
        dim=-1
    ).mean()
    
    loss = loss_mse + lambda_scale * loss_scale + lambda_cos * loss_cos
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

# ==================== 4. 零样本推理 ====================
def zero_shot_adapt(lang_prompt, demo_video):
    with torch.no_grad():
        z_new = frozen_encoder(lang_prompt, demo_video).mean(dim=0, keepdim=True)
        delta_W_new, S_new = meta_net(z_new)
        delta_W_new = rescale_by_layer(delta_W_new, S_new)
        
        # 将生成的 LoRA 注入冻结 VLA：W + Delta_W
        adapted_policy = inject_lora(frozen_vla, detokenize(delta_W_new))
    return adapted_policy

Q1: 这篇论文试图解决什么核心问题？

A1: 这篇论文试图解决大规模预训练 VLA 策略在部署到新任务时的**高效适配**问题。具体来说，现有方法通常要求为每个新任务收集带有动作标签的演示数据，并通过梯度微调训练专用适配器，导致部署成本高、扩展性差。作者希望实现一种**无需目标动作标注、无需测试时梯度优化**的零样本适配机制，仅通过语言指令和短视频演示即可在单步前向传播中完成任务级特化。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 作者提出的核心解决方案是 **WIZARD**（Weight-space Inference for Zero-shot Adaptation from Robotic Demonstration），其创新点包括三个层面：
- **问题重构**：将机器人策略适配从传统的“动作空间监督/微调”转变为**权重空间中的参数生成问题**，即直接预测 LoRA 适配器权重而非优化动作输出。
- **单步任务级权重生成**：利用冻结 VLA 自身的多模态编码器提取任务嵌入，通过元网络在单次前向传播中直接生成任务特定的 LoRA 参数，彻底摆脱测试时梯度计算。

## 第二模块：核心架构解释

### 1. 整体架构设计

FLIGHT VLA 的核心是**异步双速率系统**，将长程认知推理与实时运动控制彻底解耦：

- **低频慢系统：Streaming Pilot VLM**
  - 基于 **Qwen2.5-VL-3B-Instruct** 加 **LoRA** 微调，并继承 **StreamingVLM** 的在线视频流处理能力。
  - 输入：自然语言指令 $I$、最近 $W_i$ 长度的视频与状态窗口、以及历史 Pilot Reasoning 记忆 $M$。
  - 输出：Pilot Reasoning 文本 $M_\tau$（总结当前飞行状态并预测下一步子目标）和语义隐特征 $z_\tau$（取自输入与最新生成 token 的最终层隐藏状态）。
  - 记忆机制：通过文本形式的推理历史压缩长程多模态上下文，避免保留全部视觉 token。

- **高频快系统：Diffusion Action Model**
  - 独立 **ViT** 编码当前 FPV 帧 $V_t$，获得实时视觉特征 $\mathbf{f}_t$。
  - **相对位姿编码**：将当前 UAV 位姿转换到最近一次 VLM 推理时刻 $\tau$ 的坐标系下，得到 $q_t$，消除全局坐标漂移并适配异步延迟。
  - 条件融合：$c_t = [\mathbf{f}_t;\, q_t;\, z_{\tau(t)}]$。
  - 动作生成：采用 **DiT-B**（Diffusion Transformer）结合 **Flow Matching** 目标，从噪声轨迹迭代去噪，预测未来 $H=7$ 步的连续相对动作序列 $A_t$。

- **异步对齐机制**
  - 推理时，VLM 以较低频率（如每 2 秒）更新，Action Model 以控制频率（如 10Hz）持续运行，直接从缓存的 $z_{\tau(t)}$ 获取最新可用语义条件。
  - 训练时，显式模拟 VLM 延迟：对动作模型的训练片段随机采样 **0s / 1s / 2s / 3s** 的历史 VLM 特征，并计算对应参考系下的相对位姿，使动作模型学会补偿时延。

现有端到端自动驾驶规划器普遍采用“生成-评分-选择”范式：先产生有限候选轨迹，再由评分器挑选最优者。然而，评分器仅在候选集生成后被动使用，无法改善候选质量；若候选集本身较弱，即使评分器再强，规划性能也会受限于“矮子里拔将军”。更深层的问题是，作者发现大多数在固定词汇表上训练的评分器在分布外轨迹上表现极差，无法直接作为奖励函数进行优化，而传统排序评估无法暴露这一缺陷。

为此，本文提出TOAD（Test-time Optimization for Autonomous Driving），一种无需重训练、即插即用的测试时优化方法。TOAD将冻结的评分器视为轨迹级别的奖励函数，在控制空间（加速度与偏航率）中运行交叉熵方法（CEM）进行采样优化。搜索以基础规划器选中的轨迹为锚点进行热启动，并通过锚点正则项与运动学舒适正则项将搜索限制在可信区域内；同时利用可逆自行车模型保证轨迹动态可行性。该方法可包裹任意现有规划器，仅需前向推理，不修改模型权重。

在NAVSIM-v1、NAVSIM-v2和闭环HUGSIM基准上，TOAD对六种基础规划器（iPad、Hydra-MDP、GTRS、ZTRS、RAP、DrivoR）均带来一致提升。在NAVSIM-v2上，弱规划器增益最大（如iPad提升43.6%），强规划器DrivoR提升3.1%至56.3 EPDMS，逼近特权方法PDM-Closed（56.6），达到新的最先进水平；NAVSIM-v1上DrivoR+TOAD取得94.7 PDMS。HUGSIM零样本测试也显示安全性与舒适性提升。消融实验表明，收益来源于搜索发现新轨迹，而非简单重排序或平滑；且只有与生成器解耦、能泛化到分布外轨迹的评分器（如DrivoR）才能成功，固定词汇评分器会导致性能下降。

这项工作揭示了标准“打分-排序”范式中隐藏的评分器泛化缺陷，指出未来应构建 inherently generalizable 的评分器以释放测试时搜索的潜力。TOAD以极低的推理开销（1.9–20 ms）显著放大现有规划器性能，为自动驾驶规划提供了一种轻量且实用的推理时增强方案。尽管其应用场景为自动驾驶，但将冻结判别模型作为奖励函数进行测试时优化的思路，对基于学习的规划与决策具有方法论参考价值。

**核心机制：** TOAD的本质是在**控制空间**（加速度与偏航率序列）中以基础规划器输出为锚点，迭代执行"采样→rollout轨迹→scorer打分→elite筛选→重拟合高斯"的CEM循环；通过可逆自行车模型保证动态可行性，通过anchor正则与comfort正则将搜索约束在信任区域内，从而在不离开scorer可靠域的前提下发现训练词汇表之外更优轨迹。

**关键数据：**

- **最能证明有效性的数据：** DrivoR + TOAD 在 NAVSIM-v2 达到 **56.3 EPDMS**，超越此前最强学习方法 DriveFuture（55.5），且仅比使用真值感知的 PDM-Closed（56.6）低 0.3。这一结果证明了测试时搜索可以将现有最强规划器推向理论上限。

## 第二模块：核心架构解释

### 方法流程

TOAD 的核心是一个围绕**冻结scorer**构建的测试时优化循环，整体分为三个阶段：

1. **基础规划器输出与Warm-start初始化**
   任意基础规划器接收观测 $o$ 与导航目标 $g$，输出候选轨迹集 $\mathcal{T}$ 及其选中的锚点轨迹 $\tau_{\text{base}}$。通过**逆自行车模型** $\operatorname{BM}^{-1}$ 将轨迹转换为控制序列 $u_{\text{base}}$ 与候选控制集 $\mathcal{U}$。CEM的初始均值设为 $\mu_0 = u_{\text{base}}$；初始标准差由候选集 spread 决定：$\sigma_0 = \max(\beta \cdot \mathrm{std}(\mathcal{U}), \epsilon)$，确保探索范围与规划器自身不确定性挂钩。

2. **控制空间中的CEM搜索**
   每一迭代 $k=1,\dots,K$：
   - **采样**：从高斯分布 $\mathcal{N}(\mu_k, \mathrm{diag}(\sigma_k^2))$ 中抽取 $M$ 条控制序列 $u$。
   - **Rollout**：通过前向自行车模型 $\tau = \operatorname{BM}(u, v_0)$ 得到动态可行轨迹。
   - **评分**：计算组合目标
     $$J(u) = S(\tau; o, g) - \lambda_a \|u - u_{\text{base}}\|^2 - \lambda_c C_{\text{comf}}(u)$$
     其中 $C_{\text{comf}}$ 为纵向/横向加速度、jerk、偏航率及偏航加速度的平方违反累加，提供闭式舒适信号。
   - **精英筛选**：保留得分最高的 $E$ 个序列构成精英集 $\mathcal{E}_k$。
   - **分布重拟合**：$\mu_{k+1} = \mathrm{mean}(\mathcal{E}_k)$，$\sigma_{k+1} = \mathrm{std}(\mathcal{E}_k)$。

3. **最终选择与输出**
   循环结束后，rollout均值控制序列得到 $\tau_{\text{mean}}$。最终返回 $\tau_{\text{mean}}$ 与 $\tau_{\text{base}}$ 中在**不含anchor惩罚**的 scorer + comfort 目标下得分更高者，保证输出不会比基础规划器更差。

### 实验流程

- **基准测试**：在 NAVSIM-v1 (`navtest`)、NAVSIM-v2 (`navhard-two-stage`) 两个伪闭环基准，以及闭环真实感仿真器 HUGSIM 上评估。
- **基础规划器**：覆盖固定词汇表（Hydra-MDP, GTRS, ZTRS）与自由生成（iPad, RAP, DrivoR）两类共六种，全部使用公开checkpoint，**不做任何重训练**。
- **统一scorer**：除DrivoR自带解耦scorer外，其余五种规划器均外接DrivoR的冻结scorer作为奖励函数。
- **超参数**：固定 $M=64$, $E=8$, $\beta=0.5$, $\lambda_a=0.5$, $\lambda_c=0.05$；on-the-fly生成器使用 $K=5$，固定词汇表规划器使用 $K=100$（因其词汇表>8K，需要更多迭代跳出局部）。

### 核心伪代码

```python
def toad(base_planner, scorer, obs, goal, v0):
    # 1. 基础规划器输出候选与锚点轨迹
    candidates, tau_base = base_planner(obs, goal)
    u_base = inverse_bicycle_model(tau_base, v0)
    U_cand = [inverse_bicycle_model(tau, v0) for tau in candidates]
    
    # 2. CEM初始化：锚点为均值，候选spread为初始方差
    mu = u_base
    sigma = max(0.5 * torch.std(torch.stack(U_cand)), eps)
    
    # 3. CEM主循环
    for _ in range(K):
        # 采样控制序列并前向rollout为轨迹
        u_samples = sample_gaussian(mu, sigma, M)   # [M, T, 2]
        trajectories = [bicycle_model(u, v0) for u in u_samples]
        
        # 计算组合奖励：scorer + anchor正则 + comfort正则
        scores = []
        for tau, u in zip(trajectories, u_samples):
            J = scorer(tau, obs, goal) \
                - lambda_a * l2_loss(u, u_base) \
                - lambda_c * comfort_violation(u)
            scores.append(J)
        
        # 选取elite并重拟合高斯分布
        elite_u = topk(u_samples, scores, E)
        mu = mean(elite_u)
        sigma = std(elite_u)
    
    # 4. 最终决策：CEM收敛轨迹 vs 基础轨迹（不含anchor惩罚）
    tau_mean = bicycle_model(mu, v0)
    tau_star = argmax(
        [tau_mean, tau_base],
        key=lambda t: scorer(t, obs, goal) 
                      - lambda_c * comfort(inverse_bicycle_model(t, v0))
    )
    return tau_star
```

## 第三模块：核心学术问答

Q1: 这篇论文试图解决什么核心问题？

A1: 现有端到端自动驾驶规划器采用"生成候选轨迹 → scorer排序 → 选择最优"的流水线，其中scorer仅在候选生成后被调用，无法反过来改善候选集本身。这导致当候选集整体质量较差时，即使scorer能力再强，规划性能也会被候选集的上限锁死。论文旨在突破这一瓶颈，让scorer从"事后裁判"转变为"可优化的奖励函数"，通过测试时搜索主动发现更高质量的轨迹。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 
- **范式重构**：将冻结的轨迹scorer重新定义为轨迹级奖励函数，在测试时通过CEM直接搜索奖励最大化的轨迹，而非仅对固定集合做一次性排序。
- **信任区域CEM**：以基础规划器输出为warm-start和anchor，将搜索约束在邻域内，既保证动态可行性（通过控制空间自行车模型），又防止搜索漂移出scorer的可靠分布。
- **诊断性洞察**：发现只有与生成器解耦、能评估自由解码轨迹的通用scorer（如DrivoR）才能支撑测试时优化；固定词汇表scorer在分布外会灾难性失效，暴露了传统排序评估无法检测的隐藏缺陷。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

A3: 
- **跨架构验证**：在六种架构迥异的基础规划器（固定词汇表与自由生成兼有）上验证，证明框架的即插即用性；且统一使用外接的DrivoR scorer，排除了scorer差异的混淆因素。
- **严格对照实验**：设计了"仅平滑（BM）"、"仅重打分（re-scoring）"、"换用不同scorer"等对照，严格隔离了"搜索发现新轨迹"与"重新排序旧轨迹"的贡献，证明增益确实来自CEM搜索本身。
- **困难场景与闭环验证**：NAVSIM-v2的`navhard-two-stage`包含更具挑战性的分布外场景，能有效区分方法的真实鲁棒性；HUGSIM提供基于3D Gaussian Splatting的闭环真实感仿真，验证零样本迁移能力。

Q4: 这篇论文最显著的贡献点（Top 3）是什么？

A4:
- **测试时搜索的范式验证**：首次系统性地将端到端规划中的scorer从"排序器"转变为"可优化的奖励函数"，通过轻量级CEM循环在六种基础规划器上实现一致提升，无需任何重训练。
- **scorer泛化性的关键诊断**：揭示了当前主流固定词汇表scorer在分布外的致命弱点，以及解耦通用scorer的必要性，为后续端到端规划器的scorer设计提供了明确准则。
- **SOTA性能与极低开销**：在NAVSIM-v2上达到56.3 EPDMS的新SOTA，且搜索本身在DrivoR上仅增加1.9ms，证明了推理时计算在自动驾驶中的实用价值。

Q5: 这项工作在哪些相关研究的基础上做了推进？（列举1-2个最核心的前置工作即可）

A5:
- **DrivoR** (Kirby et al., 2026): 提供了与轨迹生成器解耦的通用scorer，是TOAD能够成功的前提。TOAD直接将其冻结scorer作为跨规划器的统一奖励函数使用，并在此基础上通过CEM进一步挖掘其潜力。
- **Hydra-MDP / GTRS / ZTRS** (Li et al., 2024/2025): 代表了当前主流的"固定大规模词汇表 + scorer排序"范式。TOAD在这些方法之上进行测试时优化，并通过实验揭示了其scorer在分布外失效的问题，直接推进了对该范式瓶颈的理解。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

A6: 
- **强依赖特定scorer的隐性成本**：TOAD的成功几乎完全依赖DrivoR的disentangled scorer，而实验中5/6的基础规划器自带的scorer均无法在搜索中正常工作。这意味着"即插即用"实际上需要额外部署一个DrivoR级别的通用scorer及其感知骨干（约100ms前向开销），对于没有该scorer的用户门槛较高。
- **信任区域过于保守**：论文明确将搜索限制在基础规划器输出的邻域内，这虽然防止了分布外崩溃，但也意味着TOAD无法修正基础规划器的重大结构性错误（如完全错误的车道选择），只能做局部精修。作者也在Limitations中承认，理想情况下应能从零搜索。
- **未讲明的故事**：论文将DrivoR scorer的泛化性简单归因于"训练时接触了自由解码轨迹"，但未深入剖析其网络结构、损失设计或数据分布的具体作用机制。此外，CEM作为无梯度优化器，在更长时域或更高维动作空间中的扩展性（如多模态交互场景）未被讨论；且图4c显示增加CEM迭代次数反而导致性能下降，暗示scorer与真实EPDMS指标存在不完全对齐，但论文未量化分析这种misalignment的来源。
- **后续启发**：未来工作应聚焦于设计"为搜索而生"的通用scorer（例如通过世界模型或自监督预训练降低对昂贵轨迹级标注的依赖），并探索更高效的测试时优化算法（如基于梯度的优化或学习式优化器），以进一步释放推理时计算的潜力，同时解决scorer与真实驾驶指标的对齐问题。
